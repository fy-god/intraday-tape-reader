# 盘中短线精灵 · Intraday Tape Reader

**A股盘中实盘急拉急跌预警 + 短线精灵滚动播报**（纯 Python 标准库实现）

`intraday-tape-reader` — 复刻同花顺/大智慧「短线精灵」的**效果**：用公开行情数据
实时播报火箭发射、大笔买入、封涨停板等 33 类盘中信号，并带 Web 看板。

> 为什么叫 "Tape Reader"：短线精灵本质是**读盘口**（reading the tape）——
> 把逐笔的价量变化翻译成人能一眼看懂的一句话。本项目用免费公开行情近似做到
> 这件事，并**明确标注哪些信号拿不到**（见下）。

---

## 它做什么

一个持续运行的进程：每 3–5 秒抓一次全市场行情 → 跑规则 → 去重 → 推送告警 +
刷新 Web 看板的滚动列表。盘中盯着它，异动会自己跳出来。

**33 个短线精灵信号**，按组分类：

| 组 | 数量 | 例子 |
|---|---|---|
| 价格异动 | 6 | 火箭发射、高台跳水、快速反弹、加速下跌 |
| 盘口委托 | 8 | 大笔买入、有大买盘、机构买单、机构吃货 |
| 涨跌停 | 11 | 封涨停板、打开涨停、封跌停板、打开跌停 |
| 指数 | 2 | 拉升指数、打压指数 |
| 形态 | 6 | 平台突破、均线多头 |

外加 4 个通用规则：急拉、急跌、涨停/跌停打开、放量、异动。

## 三个必须说清楚的事

**1. 有 6 个信号拿不到，而且不会假装拿得到。**

短线精灵里这些依赖 **Level-2 逐笔委托**（交易所付费数据）：

> 买单分单、卖单分单、买入撤单、卖出撤单、买入新单、卖出新单

免费公开行情只有快照（每 3 秒一次的五档 + 内外盘），**看不到单笔委托和撤单**。
本项目不伪造它们。要这 6 个信号只有两条路：付费 Level-2 数据源
（同花顺 iFinD / 东财 Choice / Wind 的官方 Python API），或自己去券商开户拿行情授权。

**2. `spirit_order` 的成交类信号是"近似"的。**

「大笔买入」在真实短线精灵里是**逐笔**判定（单笔外盘成交 > 阈值）。本项目只有
3 秒快照，所以用**相邻两轮外盘增量**近似：两轮之间累计的外盘增加量超过阈值就报。
后果：3 秒内的多笔小单可能被合并成"一笔大单"而误报，一笔大单也可能被拆到两轮里
而漏报。这是免费数据源的固有误差，已在代码和文档里标注，**不是 bug**。

**3. 不抓同花顺客户端。**

有人会想"装个同花顺让你读它的界面"。这条路走不通也不该走：同花顺没有公开 API，
抓客户端违反其服务条款。本项目**只用公开行情接口**（腾讯 / 新浪 / 东财），
这也是它能在任何机器上直接跑起来的原因。

## 快速开始

```bash
pip install -e .            # 装本项目（唯一的第三方依赖 PyYAML 会一起装上）
python -m arad.cli selftest # 离线全链路自检，不需要开盘
python -m arad.cli serve    # 起 Web 看板 -> http://127.0.0.1:8899/
```

> 不想装也可以：把 `src/` 加进 `PYTHONPATH` 即可
> （`$env:PYTHONPATH='src'`，Linux/macOS 用 `PYTHONPATH=src`）。
> 但**必须**是二者之一——`src/` 布局意味着直接 `python -m arad.cli` 找不到包。
>
> 装完还可以直接用 `arad` 这个命令（等价于 `python -m arad.cli`）：
> `arad selftest` / `arad serve` / `arad check`。

看板长这样：左边是**短线精灵**滚动列表（新行从顶部插入，红涨绿跌），下面是告警流，
右边是行情表。带分组筛选按钮：全部 / 价格异动 / 盘口委托 / 涨跌停 / 指数 / 形态。

每条精灵一行显示 6 列：`时间 代码 名称 信号 现价 涨跌幅`，行高 **23px**，
一屏约 10 条——这个密度是刻意的。短线精灵的价值全在**信息密度**：一眼扫过去能看多少条
异动，决定了它有没有用。所以布局是横向铺开而不是上下堆叠。

> 这里踩过坑：CSS 只声明了 5 列却有 6 个格子（漏了涨跌幅），CSS Grid 把第 6 个自动换到
> 第二行，行高从 23px 变成 **46.5px**，一屏从 10 条掉到 5 条。不报错、测试不红、截图乍看
> 也正常，只是密度腰斩。现在有 `tests/test_dashboard_frontend.py` 盯着列数与格子数必须相等。

盘中用之前：

```bash
python -m arad.cli check    # 配置/时段/数据源体检
python -m arad.cli once     # 真抓一次行情，确认网络通
```

### 开盘前必做

`config/settings.yaml` 里三个 `spirit_*` 模块**默认关闭**。想开短线精灵就打开：

```yaml
rules:
  spirit_price: { enabled: true }   # 火箭发射/高台跳水/快速反弹/加速下跌
  spirit_order: { enabled: true }   # 大笔买入/有大买盘/机构买单...
  spirit_index: { enabled: true }   # 拉升指数/打压指数
```

> 为什么默认关：`spirit_price` 和 `tick_surge` 都在抓"快速上涨"，两个一起开会对
> **同一波行情重复播报**。开 `spirit_price` 时建议把 `tick_surge` 关掉。

`app.dry_run` 默认 `true`（通知只打印不真发）。要收钉钉/飞书/弹窗就改成 `false`。

## 盘中可用吗

**可以。** 以下是真实网络实测（复现：`python tools\bench_round.py --live`）：

| 指标 | 实测值 |
|---|---|
| 全市场股票池 | **5563 只** / 18.7s |
| 单轮扫描（5563 只，7 规则全开） | **949 ms** (p50) / 1082 ms (max) |
| 其中纯 CPU | **24 ms**（其余是网络） |
| 5 秒轮询预算余量 | **5.3×** |
| 五档深度 / 内外盘 / 流通股本可用率 | 800/800 · 799/800 · 800/800 |

规模扫描 500 → 5563 只确认成本**线性**增长（每只成本 0.004 ms 基本不变）。

**但必须知道**：性能数字强依赖机器负载。CPU 被占满时曾测到 p95 = 5991 ms
（超预算），机器空闲后重测是 949 ms。**别在跑着编译/渲染的时候判断它撑不撑得住。**

### 真实盘中实测（不是模拟）

`python tools\live_session.py --minutes 12` 在**真实交易时段**跑过一次
（2026-09-17 周四 10:03–10:15，早盘连续竞价中，4800 只股票池）。

**144 轮全部通过，8 项检查 0 失败**（报告落 `data/live_session_*.json`）：

| 检查 | 结果 |
|---|---|
| 轮次 | 144 轮 / 720.55s（间隔 5.0s） |
| 单轮耗时 | min/median/p95/max = **825 / 1233 / 1513 / 1657 ms** |
| 抓取失败 / 空数据 | **0 轮 / 0 轮**（容差 14 轮） |
| 看板接口 | 576 次请求：非 200 **0**、JSON 坏 **0**、连不上 **0** |
| SSE | 已连接，740 个事件（tick 359 / phase 144 / alert 118 / spirit 118），**未断流** |
| 内存 | 历史点 4800 → 466050，单只有界（上限 360），股票池无爆炸 |
| 日志 | WARNING 1、**ERROR 0**、CRITICAL 0 |
| 告警 | 118 条：涨停 46 / 异动 28 / 放量 23 / 急拉 18 / 急跌 3 |

抓到的都是**当天真实的票和价格**，不是合成数据：

| 时间 | 代码 | 名称 | 现价 | 涨跌 | 信号 |
|---|---|---|---|---|---|
| 10:03:38 | 300434 | 金石亚药 | 12.49 | **+19.98%** | 封涨停 封单2.23亿 |
| 10:03:38 | 002080 | 中材科技 | 61.47 | +10.00% | 封涨停 封单16.72亿 |
| 10:03:38 | 601091 | N沈鼓 | 12.21 | **+178.13%** | 高开低走 -6.1% |
| 10:04:33 | 600448 | 华纺股份 | 3.04 | +3.75% | **急拉 +4.47% / 1分钟** |
| 10:06:38 | 920016 | 中草香料 | 14.95 | +4.55% | 急拉 +3.03% / 3分钟（**北交所**） |

**最能说明它在正确工作的一条链**：`600448 华纺股份` 在 4 分钟里走完了一个完整周期，
每一步都被认成**不同的事件**、而不是同一个信号反复刷：

```text
10:04:33  急拉 +4.47% / 1分钟
10:04:48  放量异动 量比4.6 速度16.0倍
10:06:38  封涨停 封单8118万
10:06:58  炸板 -0.31%
10:07:28  快速回封          ← reseal 形态：炸板回落后重新封上
10:07:38  炸板 -1.55%（第2次）
```

同一只票的**触板 → 炸板**跃迁被分开记录，而不是每轮重报：

```text
605058 澳弘电子（12 分钟里在涨停价附近反复拉锯）
  10:06:18  触及涨停 +9.86%     ← 第 1 次触板
  10:06:33  炸板 -0.37%          ← 跌离
  10:07:43  炸板 -0.68%          ← 第 2 次跌离
  10:10:03  触及涨停 +9.97%     ← 第 4 次触板（touch_count 累计 3）
  10:12:48  炸板 -0.53%          ← 第 10 次跌离
  10:15:18  触及涨停 +9.95%     ← 第 16 次触板（touch_count 累计 15）
```

12 分钟里价格**16 次触及涨停价**，但只产出 **6 条**告警——因为报的是**状态跃迁**
而不是"现在在涨停价上"。这正是状态型信号的正确行为：`touch_count` 是**触板次数
计数**（用于展示"这板争得多激烈"），不是告警条数。

其它只在真盘中才能验证的边界：

| 情形 | 实例 | 验证点 |
|---|---|---|
| **北交所 ±30%** | `920016 中草香料`、`920895 花溪科技` | `920xxx → bj` 前缀映射生效（此逻辑曾在 `tools/probe_sources.py` 里被抄错成 `sh`，见 `docs/TOOLS_AUDIT.md`） |
| **创业板 ST 仍 ±20%** | `300419 ST浩丰` -11.34% 报「巨震」 | 没被误判成跌停（主板 ST 才是 ±5%） |
| **次日新股** | `601091 N沈鼓` +178%、`688801 C燧原-U` 508 元 | 无涨跌幅限制的票不会被涨停逻辑误伤 |
| **科创板 ±20%** | `688137 近岸蛋白` 10:14:48 触板 → 10:14:58 炸板 | 10 秒内完成一次跃迁并被正确识别 |

东财股票池被限流（1 条 WARNING）后**自动降级到新浪**，照常拿到 4800 只——
这就是正常降级路径，不是故障。

### 时段语义比"上午+下午"复杂

| 时段 | 范围 | 行为 |
|---|---|---|
| 休市 | 非交易日 / 09:15 前 | 休眠 |
| 集合竞价 | 09:15–09:25 | **照抓**（撮合中价格在动） |
| 开盘静默 | 09:25–09:30 | **不抓**——可撤单不可成交，价格不动 |
| 早盘 | 09:30–11:30 | 正常告警 |
| 午休 | 11:30–13:00 | 休眠，不计入交易时长 |
| 午盘 | 13:00–15:00 | 正常告警 |
| 已收盘 | 15:00 之后 | 休眠 |

09:25–09:30 那 5 分钟价格不动但时间在走，继续抓会把重复价格灌进「急拉」窗口，
**把速度稀释掉**（同样涨幅摊到更长窗口），反而导致开盘后该报的急拉报不出来。
边界全部左闭右开，有测试守着（`tests/test_session_boundaries.py`）。

## 数据源

| 源 | 用途 | 备注 |
|---|---|---|
| 腾讯 `qt.gtimg.cn` | 主行情 | 800 码/请求，字段最全（含五档、内外盘、流通股本） |
| 新浪 | 兜底 + 股票池 | 行情 800 码/请求；股票池走行情中心列表接口，可列全 5563 只 |
| 东财 | 股票池首选 | 字段最全，但**会对部分网络限流** |

**东财限流是常态，不是故障。** `push2.eastmoney.com` 会对高频来源直接
`RemoteDisconnected`。所以股票池配成**列表**、自动按序兜底：

```yaml
sources:
  universe: ["eastmoney", "sina"]   # 东财失败自动退到新浪行情中心
```

早期只配 `"eastmoney"` 单个来源，东财一被限流整轮刷新就报废，系统**静默**退化成
只盯自选股那 10 只——日志之外看不出异常，盘中基本没用。现在不会了：实测东财失败
时 18.7 秒内用新浪拿到全 5563 只。

## 架构

```
src/arad/
├── models.py          Quote / Alert / Board（含涨跌停价推算）
├── session.py         交易时段与交易日（7 个时段，边界左闭右开）
├── engine.py          主循环：抓取 -> 状态 -> 规则 -> 去重 -> 通知
├── store.py           告警环形缓冲 + SSE 推送
├── spirit.py          展示层：33 个信号的名称/方向/分组
├── config.py          配置加载（含缓存陷阱的处理）
├── sources/           tencent / sina / eastmoney + 故障切换
├── rules/             tick_surge limit_board volume_burst unusual
│                      spirit_price spirit_order spirit_index
├── notifiers/         console / file / 钉钉 / 飞书 / 弹窗
└── server/            web.py + dashboard.html（单文件，无构建步骤）
```

**两层去重**：告警 key 带时间桶（同桶同信号只报一次），外加 `cooldown_seconds`
真实时间间隔判定。第二层是必要的——时间桶落在固定时钟网格上，`cooldown=300`
配 5 分钟桶会在桶边界漏掉。

**事件型 vs 状态型信号**：事件型（火箭发射、大笔买入）每次发生都报；状态型
（封涨停板、有大买盘）**只在状态跃迁时报**，否则一只封死的票每轮都刷屏。
