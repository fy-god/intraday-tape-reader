## 一、修掉的缺陷

审计第一次跑出来 **10 项未通过**，其中 4 个是真缺陷，其余是审计脚本自己的判据写错了。

### D1（严重）每行被排成两行，一屏条数腰斩

**现象**：`.sp` 的 CSS 只声明了 5 列，而 `spiritRow()` 实际产出 **6 个** `<span>`
（时间/代码/名称/信号/现价/涨跌幅）。CSS Grid 容不下第 6 个，就把它自动换到第二行：

| | 修复前 | 修复后 |
|---|---|---|
| 行高 | 46.5px（两行文字） | **23.2px** |
| 一屏可见 | 5 条 | **10 条** |
| 格子 y 偏移 | `[4,4,2,2,3,26]` ← 涨跌幅在 y=26 | `[4,4,2,2,3,3]` |

**为什么这条最严重**：短线精灵的全部价值就是**信息密度**——一眼扫过去能看多少条异动。
行高一翻倍，观感立刻就不像那个东西了。而这个 bug 不报错、测试全绿、截图乍看也正常。

**修复**：`grid-template-columns` 补齐为 6 列
（`46px 52px minmax(0,1fr) 60px 50px 50px`）。信号名给**固定 60px** 而非 `auto`——
遇到超长信号名要截断，不能让 `auto` 撑开把名称列挤没。

**防回归**：`tests/test_dashboard_frontend.py::test_spirit_row_grid_columns_match_rendered_cells`
比对 CSS 列数与 JS 里的 `span` 数量。已实测：把 CSS 改回 5 列，该测试立刻失败并
打印"声明了 5 列，但 spiritRow 产出 6 个格子"。

### D2（中）分组按钮折行，白吃掉一条精灵的高度

**现象**：6 个分组按钮在 1280×800 / 1440×900 / 1024×768 下都折成 **2 行**，
表头从 31px 涨到 **53px**。这块面板是定高的，等于少显示一整条。

**根因**：`.spfilters` 只有 `flex-wrap:wrap`，而 flex 项的 `min-width` 默认是 `auto`
（= 内容宽度），**根本不允许收缩**，于是必然折行。

**修复**：容器加 `flex:1 1 auto; min-width:0` + `flex-wrap:nowrap; overflow:hidden`，
按钮收紧到 `font-size:10.5px; padding:1px 5px`（6 个合计约 230px，420px 左栏下富余）。

### D3（中）1024×768 横向溢出 186px

**现象**：三栏的 `min-width` 合计 1208px，1024 宽下 `scrollWidth=1210 > clientWidth=1024`，
最右侧「自选股」列被切掉一截。横向滚动条会连带把左侧短线精灵一起推出视野。

**修复**：加 `@media (max-width:1140px)`，降级为两栏——自选股列换到第二行整行铺开。
宁可上下排也不要横向滚动。

### D4（轻）时间戳对比度不足

**现象**：`--fg3: #5d6a80` 在面板底色上是 **3.34:1**（最差底色 3.15:1），
低于 WCAG AA 正文要求的 4.5:1。时间戳是小字号，在暗色面板上偏糊。

**修复**：`--fg3: #75849e` → 三个底色上分别为 5.11 / 4.83 / 4.56，全部达标；
仍明显暗于 `--fg2`（6.27），层级关系没乱。

**防回归**：`test_theme_foreground_colors_meet_contrast` 用真实 WCAG 公式算，
并断言 `--fg3` 必须比 `--fg2` 暗（否则"次要信息"看起来比主要信息还重）。

## 二、审计脚本自身修掉的误判

这四条是**审计判据写错了**，不是看板的错。记在这里是因为"测试写错"和"代码出错"
必须分清楚，否则会去改本来正确的代码。

### A1 `up` 行的涨跌幅必须以 `+` 开头 —— 前提就错了

审计原本断言 `up` 行涨跌幅以 `+` 开头、`down` 行以 `-` 开头，实测得到 `up=-1.50%`
就报失败。**但这是正确的语义**：

`up`/`down` 是**信号方向**，不是当日涨跌方向。`快速反弹`、`打开跌停` 这类信号，
本身就是"**一只当日下跌的票出现了看多事件**"——红色行配当日 -1.50% 完全正确。
（`打开跌停` 在展示层映射为 `UP`，理由见 `src/arad/spirit.py`：跌停被打开是买盘力量的体现。）

真正该守的是**涨跌幅带正负号**——符号才是颜色之外的第二载体，不依赖红绿也能读。
已改为断言这一点。

### A2 要求 6 个格子的 `y` 完全相等 —— `baseline` 对齐下不可能

网格是 `align-items:baseline`，时间/代码是 10.5px 而名称/信号是 11.5px，
基线对齐时大字号的顶边天然比小字号高 2-4px。那是**正确排版**，不是折行。

判据已改为用**行高**（`<= 26px`）判断有没有折行——这才是真正的信号。

### A3/A4 两个硬编码 5 列的断言

`6 个格子全部落在同一行（5 列网格容不下 6 个格子是缺陷）` 这条断言名里写死了 5 列，
修复后实际是 6 列，断言名就自相矛盾了（虽然逻辑上通过了）。已改写为与 D1 对应的
两条：格子在同一视觉行 + 行高够紧凑。

## 三、验证过没问题的部分

以下均通过，无需改动：

* **红涨绿跌全部正确**：12 个信号逐个核对，含最易搞反的
  `打开涨停`=绿 `rgb(18,196,106)`、`打开跌停`=红 `rgb(255,77,79)`。
  CSS 变量 `--up:#ff4d4f` / `--down:#12c46a` 语义正确（**注意这是中国市场惯例，与欧美相反**）。
* **信号方向色与涨跌幅列颜色同源**：0 行出现同格双色。
* **筛选**：5 个分组逐个点击，列表真的只剩该组；激活态视觉可区分
  （`rgb(255,255,255)`/底 `rgb(34,43,59)` vs 未激活 `rgb(139,152,174)`/透明）。
  来回切换**不产生重复行**，各分组并集 == 全部（0 行丢失）。
* **超长名称**：极端中文名（如"某某某超长股票名称压力测试用例啊啊啊"）被省略号截断，
  **行高不变**（23.3 vs 23.25），不撑破行。
* **未注册信号名**：原样降级显示，**不显示 `undefined`/`null`**，且被截断不撑破行。
* **DOM 上限**：推 260 条后仍为 200 行（`MAX_SPIRIT=200`），且截的是**最旧的**、
  最新行仍在顶部。
* **SSE**：页面刷新后自动重连并补齐历史行，刷新后新行仍能推到顶部。
* **零 JS 错误**：整个会话 0 条 `pageerror` / `console.error`。
* **色盲可用性**（三条独立线索，不只靠颜色）：
  1. 涨跌幅带正负号；
  2. 中文信号名本身可读（`大笔买入` / `大笔卖出`）；
  3. 左侧色条 `border-left`（`rgba(255,77,79,.5)` vs `rgba(18,196,106,.5)`）。
* **方向色亮度**：信号色对比度 5.9–8.4，可作大字/图形使用（≥3:1）。
* **1920×1080 下面板无需滚动即可见**（top=38 bottom=344，视口高 1080）。

## 四、已知的观感取舍

* **一屏 10 条**是目前 253px 面板高度下的结果。真实同花顺短线精灵通常能显示
  15–20 条，因为它整块区域更高。想要更多条数就调大 `#spiritPanel` 的
  `flex:0 0 306px`——但会挤压下面的告警流，属于取舍而非缺陷。
* **现价/涨跌幅数字本身靠红绿区分**，但上面三条独立线索都在，判读不受影响。
  这是国内交易软件的通行做法（颜色即信息），刻意不做成纯灰度。
