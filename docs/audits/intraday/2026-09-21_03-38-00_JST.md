## 3. `IT-P2-DAEMON-HEALTH-001` —— 已确认错误 / 已修复（我自己上一提交的缺陷）

### 指控成立

云端指出的是 `9c4e08d`（我上一轮加的 `--detach`）自身的缺陷：

```text
_detach_and_return() 先 Popen 新 daemon，再轮询 if _healthy(port): 成功
但单实例/端口占用检查在新 child 的 run() 里
→ 8899 已有健康服务时，新 child 因"已有实例"退出，
  父进程却看到端口 200，打印"健康检查通过 —— 现在可以关闭这个窗口了"
```

用户因此拿到**假的成功承诺**，而他要的新进程根本没起来。

### 端到端对照（决定性证据）

端口 8906 先起一个服务，再跑 `--detach`：

```text
旧实现：打印"健康检查通过 … 可以关闭这个窗口了"，退出码 0   <- 谎报
新实现：[!] 8906 端口已有服务在响应（不是本守护启动的）—— 不重复启动
        退出码 2
```

### 修复

1. 新增 `_preflight(args)`，**Popen 之前**先查占用（守护存活 / 端口已服务）；
2. 新增 `_child_owns_service(port, child_pid)`，成功判据**绑身份**：
   状态文件 `pid` == 新 child pid、且该 pid 活着、且端口健康，三者同时成立；
   child 已退出则**立刻**返回 False（不傻等满超时）；
3. 平台契约：`_detach_flags()` 非 Windows 返回 0，此时**不再**打印
   Windows 等价的"可以关闭窗口"承诺，改为明确告知仍会随终端停止。

### 证据强度（诚实标注，不冒充强证据）

新增 8 条测试。回退 `tools/run_daemon.py` 后复跑：


## 4. 用户可见推进：`serve --replay`（`a415965`）

### 为什么做

用户原话：「你能不能把同花顺 短线精灵的线路导通 我就想要那个效果」
「你的项目做的不就是盘中盯盘 你想办法让项目能跑就行了」。

看板的实时数据只在连续竞价时段产生，而用户想"先看看长什么样"时往往
正是休市。原来只打印一句「想先看效果：python -m arad.cli replay」——
但 `replay` 是**纯命令行**的，告警打到 stdout，**根本不经过看板**。
那句话等于没解决问题。

### 实现

`serve --replay`（`--stocks/--seed/--minutes/--speed`）用合成行情驱动
**同一个看板**。关键点：**共用同一个 store** —— `Replay.build_engine(store=)`
把回放告警写进看板正在读的 store，前端 SSE 与 `/api/spirit` 照常工作。

同时修掉一个自相矛盾：`store.status()` 原用**墙钟**重算 `calendar.phase()`，
回放时墙钟是凌晨 → 显示"休市"，而左栏同时滚动 63 条 09:40 的告警。
改为优先用**引擎实际评估过的** `state.session`（`poll_once` 用引擎自己的
时钟在同一轮写入，`engine.py:1049`），墙钟仅作启动瞬间回退；
并新增 `_describe_phase()`（`calendar.describe()` 会自己重算墙钟，
不能用来描述引擎算出的 phase）。

### 真实浏览器验证（Playwright + Chromium，非仅看 API）

- 页面标题「A股盘中雷达 · 急拉急跌预警」，**控制台零错误零警告**

## 11. `IT-P2-DAEMON-STATE-001` —— 已确认错误 / 已修复（本轮自己实测暴露）

### 怎么发现的

写本报告时需要"正式守护在 8899 盯盘、另开 8905 看回放预览"，
于是按最自然的用法起了第二个守护。结果：

```text
8899 守护（PID 12180）仍在运行，
但 `--status` 显示的是 8905 的 PID 31516 —— 记录被顶掉了。
```

### 机制

状态文件固定叫 `data/run/arad-daemon.json`，是**单槽**的：
后启动的守护 `_write_state()` 直接盖掉先启动的记录。
连带 `_preflight` / 单实例检查会拿**错端口**的记录去判"是否重复启动"。

### 修复与验证

状态改为 `arad-daemon-<port>.json`；旧单槽文件继续刷新作兜底，
且仅在 `port` **恰好匹配**时参与兼容读取。实测两守护并行：

```text
[端口 8899] 守护 PID 14420（运行中）
[端口 8905] 守护 PID 29412（运行中）
data/run/ 下 arad-daemon-8899.json 与 arad-daemon-8905.json 并存
```

顺手修掉一个**我自己在本修复里引入的真实崩溃**：
`_write_state(args.port, port=args.port, ...)` 会在进入函数体**之前**抛
`TypeError: got multiple values for argument 'port'` → 守护启动即退出
（日志可查）。函数内 `pop` 拦不住，只能把第一形参改名 `_port`。

回退验证：**7 RED + 1 AssertionError + 2 结构性**。
诚实说明：7 条 RED 中 6 条是 `TypeError`（旧签名不接受 `_read_state(port)`），
属"签名变化"而非纯行为差异；**唯一干净的纯行为牙**是
`test_read_state_uses_legacy_only_when_port_matches`（AssertionError）。
本缺陷的决定性证据是上面两端口并行的真实 `--status` 输出。

### 同批：`--replay` 可常驻

`run_daemon.py` 新增 `--replay/--stocks/--seed/--minutes/--speed` 透传，
所以"休市想看短线精灵"不必开着终端：

```text
python tools/run_daemon.py --detach --replay --port 8905
```
