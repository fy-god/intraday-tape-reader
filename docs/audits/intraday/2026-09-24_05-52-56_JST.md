### 2.1 【已确认错误】route 静默分叉（WP03 新 P2）

caller `route="stocks"` + 源自报 `result.route="index"` 时，修前 Manager 的
`_serving`/`_fails` 记 **stocks**，而返回对象的 `route` 写 **index** ——
**同一批数据的归属有两个答案**。下游按 `result.route` 分账会算到另一条链上。

避免"三次 `_replace` 三次判断"。

## 5. WP02 设计：caller-owned role（三次返工的收敛）

生产合同（任务书 §WP02）：

```text
stocks route -> bare 6-digit code
index  route  -> prefixed exchange symbol
```

三次返工的共同根因是**让某一侧去"猜"身份**：

| 版本 | 做法 | 后果 |
|---|---|---|
| 第 1 版 | request 判 `prefix and sym in idx_set`，而类级出口把"显式写了前缀"当成"它是指数" | `sh600000`（浦发银行）被判指数；`IT-P2-...-KEY-AXIS-001` |
| 第 2 版（我上轮） | request 改名称盲，raw 仍用 provider 真名 | 7 个名称唯一指数两轴分离（§1） |
| **第 3 版（本轮）** | **角色由调用方 route 拥有；三处消费同一份 role；`name` 不参与身份** | 15/15 三轴一致 |

实现：

```python
def is_index_role(symbol, *, index_role, idx_set=None) -> bool:
    if index_role:                       # 调用方声明 -> 权威，不再二次否决
        return True
    if idx_set and symbol in idx_set:    # per-symbol 角色元数据
        return looks_like_index(symbol, "", symbol[2:])
    return False
```

`parse_response` 增加 `route="stocks"` 参数，与 `_key`/`_req_key` 同调此函数。
`tests/test_sources_tencent.py::test_public_api_surface` 已同步钉住新签名。
