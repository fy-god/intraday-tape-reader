# 2. 本轮新确认 P1：`IT-P1-UNIVERSE-WATCHLIST-PIN-001`

## 2.1 触发链

当前 `_codes` setter 的合同是：

```python
@_codes.setter
def _codes(self, codes):
    self._codes_raw = list(codes)
    self._codes_pinned = bool(codes)
```

也就是说：**只要通过 `_codes = ...` 赋一个非空列表，就意味着“显式固定股票池，后续不要自动联网刷新”。**

这个语义对：

```text
replay / test injected codes
--watch-only
```

是正确的；`tests/test_cli_watch_only.py` 甚至明确断言 watch-only 必须 pin。

但是 normal 模式的“全市场失败 -> 自选股降级”也使用同一个 setter：

```python
if not self._codes and self.watchlist:
    self._codes = list(self.watchlist)
    self._universe_refreshed_at = time.time()
```

而下一轮 `_maybe_refresh_universe()` 一上来就是：

```python
if self._codes_pinned and not force:
    return
```

于是出现：

```text
启动
↓
Eastmoney / Sina universe 都失败
↓
降级为 watchlist 10 只
↓
_codes setter 把 watchlist 标成 pinned
↓
以后每轮 _maybe_refresh_universe() 直接 return
↓
数据源后来恢复，也不会再自动尝试全市场
```

日志却写的是：

> “全市场扫描**暂不可用**”

实际状态则是：

> **不重启、不显式 force，就可能永久停在自选股。**

这不是 `--watch-only` 的预期 pin；是 normal 模式的 degraded fallback 被错误复用了“显式 pin”状态。

## 2.2 本轮沙箱机制复现

固定：

```text
watchlist = 10
t=0   所有 universe source 失败
t=60  universe source 恢复，可给完整 5913
```

按当前控制流：

```text
refresh attempts = 1
active codes     = 10
pinned           = True
t=60             = skip_pinned
recovered_to_full= False
```

候选合同把“显式 pin”与“watchlist fallback”分开后：

```text
refresh attempts = 2
active codes     = 5913
mode             = full
recovered_to_full= True
```

这只是固定机制 fixture，不是实盘覆盖率测试。结果见本轮本地 `universe_recovery_probe.json`。

### 根因

`_codes_pinned` 现在同时承担了两种不同状态：

```text
explicit_pinned:
  用户/回放/测试明确要求不要联网覆盖

watchlist_fallback:
  全市场暂时不可用，应该持续尝试恢复
```

这两个状态在恢复策略上完全相反，不能再共用一个 bool。

# 3. 本轮新确认 P1：`IT-P1-UNIVERSE-REFRESH-STORM-001`

## 3.1 当前 partial-reject 分支不推进任何重试时钟

当前完整池刷新成功后：

```python
self._universe_refreshed_at = time.time()
```

TTL 默认：

```yaml
poll:
  universe_refresh_seconds: 1800
  universe_seconds: 5
```

TTL 到期后，如果所有来源都只能给一个**比现有池更小**的 partial candidate，当前代码会正确保护现有池：

```python
if prev and n < prev:
    log.warning("...保留现有股票池...")
    return 0
```

这个“不要被更小 partial 覆盖”原则本身是正确的。

问题是这个分支：

```text
不更新 _universe_refreshed_at
也没有 last_attempt_at / retry_at
```

而 `poll_once()` 每轮都会调用 `_maybe_refresh_universe()`。

因此只要旧 full pool 已经超过 1800 秒：

```text
第1轮：
TTL 过期 → refresh → partial smaller → reject → timestamp 仍过期

第2轮（5s 后）：
仍然过期 → 再 refresh

第3轮：
再 refresh
...
```

在数据源持续 partial 的阶段，股票池刷新从“每30分钟一次”退化成“**每轮一次**”。

这会把一个保护扫描范围的正确逻辑变成对 Eastmoney/Sina 的高频重试器，并可能把昂贵的 universe 分页请求塞进每个 5 秒行情轮。

## 3.2 本轮固定 10 分钟机制实验

固定：

```text
已有 full active pool = 5913
full pool 已过 TTL
之后 10 分钟每次 universe refresh 只得到 partial 4100
轮询 = 每5秒
```

当前控制流：

```text
rounds           = 120
refresh attempts = 120
active codes     = 5913（保护本身有效）
```

候选合同增加独立 `last_attempt_at`，degraded/retained 状态暂以 60 秒为**起始候选值**重试：

```text
refresh attempts = 10
active codes     = 5913
reduction        = 12×
```

60 秒不是已验证最优参数，只是下一轮红/绿测试的起点；它必须配置化，真实环境再标定。

### 根因

当前一个 `_universe_refreshed_at` 被同时用作：

```text
last successful/applied universe
+
下一次是否允许尝试 refresh 的调度时钟
```

但“最后完整成功时间”与“最后尝试时间”不是同一件事。

requested = len(active _codes)

```text

保留旧 full？

还是用户显式 pin？
```

所以：

> Universe Truth 不能只是一张 coverage 表，还必须包含 **Recovery State**。

# 5. 主改造：`Universe Truth & Recovery Contract v2`

建议冻结六个状态：

```text
unknown
full
partial_degraded
retained_previous
watchlist_fallback
explicit_pinned
```

并把三个时钟彻底拆开：

```text
last_attempt_at
    最近一次真的尝试 universe refresh 的时间
    —— 控制 degraded retry/backoff

last_applied_at
    active codes 真正被替换的时间

last_complete_at
    最近一次 transport-complete universe 的时间
    —— 控制正常 30min TTL 与 active pool age
```

### 5.1 核心不变量

```text
1. 只有 explicit_pinned 可以禁止自动 universe refresh。

2. watchlist_fallback 必须是 recoverable degraded 状态，
   不能设置 explicit pin。

3. 较小 partial candidate 被拒绝时：
   - last_attempt_at 必须推进
   - last_applied_at 不变
   - last_complete_at 不变
   - active codes 不变
   - mode = retained_previous

4. expected_total 不可得：
   active_coverage = null/not_measured
   不能填 0%，更不能填 100%。

5. candidate universe 与 active universe 必须同时可见。

6. round returned/requested 只是 active-pool conditional coverage，
   绝不能认证 full-market coverage。
```

### 5.2 起始配置

```yaml
poll:
  universe_refresh_seconds: 1800
  universe_retry_seconds: 60   # 候选起点，不是已认证最优
```

正常 `full`：

```text
last_complete + 1800s
```

才重新刷新。

`unknown / partial_degraded / retained_previous / watchlist_fallback`：

```text
last_attempt + retry_seconds
```

才允许下一次尝试。

这样既不会永久卡 watchlist，也不会 5 秒打一遍 universe。

# 6. `IT-P2-UNIVERSE-STATUS-CACHE-001` 本轮重新按当前固定 SHA 确认

`AlertStore.status()` 当前返回：

```python
"universe": len(quotes)
```

而这里的 `quotes` 是：

```text
state.quotes
```

—— latest quote cache。

它不等于：

```text
len(engine._codes)
```

而且指数 current 也会写入 `EngineState.quotes`；历史上 active pool 变化后，latest cache 也可能保留更多代码。

因此 `status.universe` 这个名字会把：

```text
latest_quote_cache_size
```

误读成：

```text
active_scan_universe
```

下一版应至少显式分开：

```text
latest_quote_cache_size
active_scan_universe
universe_truth
```

旧 `universe` 若为了 API 兼容暂时保留，应标 deprecated，并明确它不能作为 coverage gate 分母。

本轮机制表只是说明这种口径差异，不代表实盘当前 cache 真有这些具体数量。

# 15. 本轮最终判断

前一轮已经把 Universe denominator 识别成当前研究主瓶颈。本轮继续往“恢复行为”推进后发现：

> 当前系统不只是**不知道 active pool 覆盖了多少市场**，它在两个 degraded path 上连“如何恢复”也没有正确状态机。

一个方向会：

```text
全市场暂时失败
→ watchlist fallback
→ 被错误 pin
→ 以后永不自动恢复
```

另一个方向会：

```text
已有 full pool
→ TTL 到期
→ 每次只拿到更小 partial
→ 正确拒绝覆盖
→ 但每5秒又重试一次 universe
```

所以接下来不应该只做 `active_coverage` 一个字段。

真正需要闭合的是：

```text
expected market
→ candidate universe
→ active universe
→ recovery mode
→ retry clock
→ round current coverage
→ signal evaluability
→ committed event
→ delivery
→ future label
```

本轮主结论因此是：

**先把已证明的 Delivery health gate 小补丁落地，然后立即完成 Universe Truth & Recovery Contract v2。真实覆盖率重新测量与 per-code mixed-source 都建立在这条状态链之上；在它闭合前继续扩大模型搜索没有研究价值。**
