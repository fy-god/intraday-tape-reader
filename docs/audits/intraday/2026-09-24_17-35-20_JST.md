## 1. 【已确认错误 → 已修复】`IT-P2-TIME-REJECT-ROUTE-ATTRIBUTION-011`

### 位置
`src/arad/engine.py`
- `EngineState.update()`（旧 `:282`，本轮重构）
- `Engine.poll_once()` 旧 `:1782-1783`（基线取数）、`:1854-1855`（差值消费）

### 触发条件
同一个 poll 轮里，**两条 route 各发生一种不同的时间拒绝**。

### 机制（原文代码）

```python
# 旧 :1782-1783 —— 更新**之前**取一次全局基线
_t0_future = int(self.state.stats.get("t_reject:future", 0))
_t0_ooo    = int(self.state.stats.get("t_reject:out_of_order", 0))
# 旧 :1786-1788 —— 两条 route 的更新都夹在这一个基线区间里
idx_admitted = self.state.update(idx_quotes, now, route=ROUTE_INDEX)
admitted     = self.state.update(quotes,     now, route=ROUTE_STOCKS)
# 旧 :1854-1855 —— 算一个 aggregate delta
future_rej = int(self.state.stats.get("t_reject:future", 0)) - _t0_future
ooo_rej    = int(self.state.stats.get("t_reject:out_of_order", 0)) - _t0_ooo
```

`update()` 只返回 admitted，future/ooo 只写**全局** counters。两条 route 共用
一个基线区间，差值必然把归属丢光：

| Case | index | stocks | 合计（唯一可见信息） |
|---|---|---|---|
| A | future=1 | ooo=1 | future=1 / ooo=1 |
| B | ooo=1 | future=1 | future=1 / ooo=1 |

### 影响
- **诊断方向完全相反**却无法区分：`index future`（指数时间轴超前 → 源时钟错）
  与 `stock ooo`（个股乱序 → 传输乱序）需要**不同**的处置。
- 下游 `live_session.py` soak 报告只留合计，事后复盘无从下手。
- 属本仓库反复出现的同一类错：**拿合并后的结论当每个子集的结论**
  （规则 D15 /「逐批次结论当成全局结论」）。

### 修复
1. 新增 `StateUpdateResult`（frozen dataclass）：`route` / `admitted` /
   `rejected_future` / `rejected_out_of_order` / `stale_diagnosed`。
2. 新增 `EngineState.update_detailed()`；**`update()` 变成它的薄包装**
   （逻辑只有一份，避免"同一语义实现两次"）。
3. `poll_once` 改调 `update_detailed`，**直接消费** route-local 计数，
   删除全局差分。
4. `RoundObservationSet` 增加 `reject_by_route` / `admitted_by_route` /
   `returned_by_route`，并在 `as_dict()` 导出 + 加 `_schema_note`。
5. 正常路径与空轮分支**共用** `Engine._route_ledger()`（单一事实来源）。

### 现存 `PollOnce` 前置修复（WP02）

### 位置
`src/arad/engine.py` `EngineState` 的四个诊断映射（旧 `:138/:147/:149/:152`）

### 触发条件
`index route` 与 `stock route` **出现同一个裸 code**（`000001` 既是指数
（上证指数）又是平安银行），且两者 age 不同。

### 机制
`accepted_watermark_by_route` / `seen_in_epoch` 早已按 `(route, code)` 分账
（IT-P1-TIME-ROLE-004），但这四个**诊断**映射仍只按**裸 code**：

```python
self.provider_ts_raw[q.code] = _raw
self.time_age_seconds[q.code] = _age
```

### 影响

### 修复

## 8. 研究想法（1–3 条，可证伪）

### R1【程序修复】`_admit_time` 的 `why` 字符串是**唯一**的 reason 来源

`_admit_time()` 返回 `"future"` / `"stale"` / `"out_of_order"`，而
`update_detailed` 用 `if why == "future"` 分派。字符串字面量做协议 =
**改错的静默失败**（新增一个 reason 会让计数悄悄漏掉）。
**可证伪预测**：加一个 `assert why in {"future","stale","out_of_order"}` 并
用 `Literal` 标注返回类型，然后注入一个拼错的新 reason ——
现有代码会把该拒绝**计到 global counter 但不计入 route-local**，
测试不报错。⇒ 应当枚举化。

### R2【任务定义调整】WP03 的"terminal buckets 不相交并集"应当**先立不变式再改代码**

任务书 WP03 要求 `Requested = disjoint union(admitted, missing, quality,
future, ooo, stale, unattributed)`。我现在只做了 reject 分账。
**可证伪预测**：在**当前**代码上，按现有桶定义算
`len(requested_codes)` vs `sum(len(bucket))`，会有**非零差**（因为
`unattributed` 尚不存在，且 `time_rejected_codes` 与 `future/ooo` 计数
口径不同 —— 前者是按**代码**、后者是按**条数**）。
⇒ 先把"桶是代码集合还是条数"钉死，否则不变式写出来也对不上。

### R3【模型真正增量提升】= **0**

本轮所有改动都是**程序修复**与**任务定义澄清**。没有任何涉及
数据集/标签/训练的部分 —— 真实多日 manifest 仍 blocked。
