> **provider 已经明确告诉我们结果不完整，但 health 把它归入“未测量”。**

# 7. P1：`IT-P1-SOURCE-EMPTY-001` 继续存在，且现在更适合修了

当前 `SourceManager.call()`：

```python
try:
    out = getattr(src, method)(*args)
except Exception:
    continue
return out
```

所以：

```text
主源抛异常
→ 会尝试 backup

主源返回 []
→ 被视为成功
→ backup 不调用
→ serving 仍记主源
→ fail counter 归零
```

10:05 独立审计已经实际复现；本轮同构机制再次得到：

```text
primary returns []：
returned=0
backup_calls=0
serving=primary
fails=0

primary raises：
backup_calls=1
serving=backup
fails=1
```

前几轮我们暂缓直接改，是因为 observation/accounting 与 per-code provenance 当时还很不稳。

现在 silent-empty health 与 request reconciliation 已基本修好，SourceManager 可以正式增加一个**soft-empty snapshots policy**：

```text
非空 requested code list
+ snapshots 返回 []
=> 视为 soft failure candidate，尝试备用源
```

但不能把所有 `[]` 一刀切为 provider failure。

要严格区分：
- caller 根本没有 dispatch（休市/规则不需要指数）；
- 非空请求真的发出且源返回 `[]`；
- universe enumeration 空结果；
- source 明确 unavailable / suspension 等 code-level 语义。

下一轮建议只对 `method=="snapshots"` 且 requested codes 非空启用 soft-empty fallback，Universe 保留自己的 source-chain 完整性合同。

# 9. P1：`IT-P1-WINDOW-001`——ObservationInterval 现在应该进入真实实现，而不再停留在散文

固定源码仍然只在：

```python
prev is None
or prev != q.price
or volume changed
```

时 append history。

因此：

```text
t=0   price=10.0
t=5..60 每5秒都有新鲜 observation，但价量完全相同
t=65  price=10.3
```

history 只保留：

```text
(0, 10.0)
(65,10.3)
```

`tick_surge._covered()` 却看：

```text
hist[0].ts <= now - 0.9 * window
```

所以 `_covered(60s)=True`。

但 `price_change(60s)` 从 `window(60s)` 取 `[5,65]`，t=0 被裁掉，只剩 t=65，一个点，返回 `None`。

于是：

> 规则判“覆盖够”，却又拿不到涨幅，信号静默不评估。

本轮机制候选 `ObservationInterval`：

```text
[first_observed_at=0,
 last_observed_at=60,
 price=10.0,
 cum_volume=100]

[next at 65, price=10.3]
```

60s 窗口截止点 5 秒落在第一个 interval 内，所以 anchor=10.0 合法；同时如果 5..60 没有真实 observation，`last_observed_at` 不会延长，就不会伪造覆盖。

这比“每5秒硬 append 一个重复点”更节省内存，也更符合事实。

## 最终判断

项目已经从最早的“旧缓存冒充 current round”推进到了相当深的位置：

```text
current round
→ universe denominator
→ coverage
```

现在真正的最大瓶颈变成了：

> **系统能描述“当前正在用哪份股票池”，但还不能描述“最近一次刷新发生了什么、这份池已经多旧、刷新失败是否应该改变健康结论”。**

如果继续只维护一份 `_universe_meta`，两种错误修法都会出问题：

```text
失败时清空 meta
→ 丢掉 retained active pool 的真实事实

失败时保留 meta
→ 又会把旧的 100% coverage 当成刚刚验证过
```

正确答案是**双账**：

```text
Active Universe Snapshot
+
Latest Refresh Attempt
+
Freshness
```

并让 live-session 在整个 soak 内持续聚合，而不是只在启动前拍一次照片。

与此同时，三个真正仍存活的老问题——宿主时区、soft-empty failover、fresh-flat window——都已经被最新独立回归收窄到清晰、可测试的小问题，应该在下一轮直接实施，而不是继续写泛化设计。

在这四条 measurement/reliability contract 闭合之前，模型训练仍然不该成为主任务。真实模型研究的正确入口仍然是：

```text
Refresh Truth
→ Session/Timezone Truth
→ Source Recovery Truth
→ ObservationInterval
→ Universe / per-code provenance
→ real labels
→ factors
→ tabular
→ TCN
```
