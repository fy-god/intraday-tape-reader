## WP01 — Alert stage ledger【P1 / P0-0 前置，第一优先】

### 当前缺陷
`SignalEvalStats.published` 在 rule 返回前就记；Engine 后面还有 ignore + AlertBus key/cooldown。现字段其实是 `rule_selected`。

### 实施
1. deprecated 旧 `published` 语义，新增/迁移：
   - `rule_selected`
   - `bus_accepted`
   - `committed`
2. `Alert` 或 sidecar 加稳定：
   - `signal_id`
   - `event_id`（bus accepted 后、Store commit 前生成）
3. Store commit 后再记 `committed`；失败不得伪记。
4. 账本 API 仍要防御式，不得因 observability 异常影响行情主链。

### 红测/真牙
- 同 code 每 5 秒命中，cooldown=600，至少 24 轮；断言 `rule_selected=24 / bus_accepted=1 / committed=1`。
- max_per_round 截断与 cooldown 要分别对账。
- 回退产品实现后真断言必须重新红。

### 产物
`alert_delivery_reconcile.json` + red/green/rollback logs + diff hash。

## WP02 — Typed NotificationResult【依赖 WP01】

### 当前缺陷
Notifier 协议返回 bool，但 Engine `_dispatch_many()` 完全忽略。内置 notifier 失败通常**不抛异常**、只返回 False，所以 Engine 无法统一记录失败；同时 disabled/severity skip 返回 True，True 也不等于“物理发送”。

### 终态
引入等价结构：
```text
status = sent | skipped_disabled | skipped_severity | skipped_dry_run | failed
channel
mode = single | digest
event_ids
attempts
reason
started_at / ended_at
```

### 兼容
- built-in notifier 全量迁移 typed result；
- legacy bool 走 adapter：False=failed，True=legacy_true_unknown，不允许直接认证为 sent；
- 不要在 digest False 时无条件逐条重发，先解决 idempotency/event_id。

### 真牙
1. Webhook fake poster 连续 500 → notifier 返回 failed，**Engine 必须落 delivery_failed**；
2. disabled → skipped_disabled，不是 sent；
3. severity filter → skipped_severity；
4. 成功 2xx → sent；
5. notifier exception → failed 且主行情循环不炸。

产物：`notification_delivery_reconcile.json` + red/green/rollback。

## WP03 — committed-event T+5/T+30 标签【依赖 WP01】

只消费 `committed event_id`：
```text
signed_return_h = direction * (P[t+h]/P[t]-1)
known_at = t+h
h = 5min, 30min
```
匹配 control：同 symbol、同交易日/日内时段、同方向分布，排除 alert 邻域；选 control 时禁止读未来收益。主报告保留连续 signed return，二值 continuation 只做辅助。绝不能称真实 Precision/交易收益。
