## §2 已确认错误 #1：`IT-P1-SOURCE-MANAGER-GLOBAL-IDX-BREAKS-ROUTE-ISOLATION-008`

**文件/函数/行**：`src/arad/engine.py` — `class SourceManager` `:497`；全局首选源 `self.idx` `:514`；
逐路由 `_fails` `:515` / `_serving` `:516`；`_switch()` `:537-541`；`_bump()` `:543-545`；
`call()` `:547-589`（提升 `:578-581`）；`call_detailed()` `:591-669`（提升 `:658-661`）。

**触发条件/反例**（**真类实跑**，非阅读）：`threshold=2`，primary **仅对个股代码失败**，指数完全健康：

```
stock#1 -> backup 服务, idx 仍 0, _fails={stock:1}
stock#2 -> backup 服务, idx 变 1, _fails={}      <- 全表清空
index   -> 由 BACKUP 服务, 且 primary 从未被调用
```

**镜像臂**：仅指数失败 → **个股**供数源改变。**4 个对照臂全部成立**：①什么都不失败 → 指数走 primary；
②`threshold=3` 未达（2<3）→ 指数走 primary、`_fails={stock:2,index:0}`；③达阈值后 `_fails` **全表清空**；
④健康路由只清零自己（`:573`）。

**机制**：失败计数**按路由分账**，但「当前首选源」只有**一个全局 `self.idx`**；`_fails.clear()` 在
`:540`/`:580`/`:660` 三处**全部清整张表**，只有 `:573`/`:653` 真正路由作用域。失败顺序
`[self.idx] + 其余`（`:561`、`:622-623`）⇒ **路由只影响记账，永不影响首选源**。

**影响（可达性，我自己数的数）**：两条路由**共用同一实例**（`engine.py:807` + `_wrap_sources:862-871`），
调用方**确实**传不同 route（`:1528` 个股、`:921` 指数、`:1325` universe）⇒ **出厂接线真会走到该机制**：
个股劣化会**静默改变指数 provider**，`serving_of("index")` 随之变化，Engine 会为指数开新 source epoch
——**即使指数自身从未失败**。生产 `.call(...)` 调用点 **4 个**：`cli.py:130`（无 route）、
`engine.py:921`/`:1528`/`:1325`；默认 `threshold=3`（`:863`）。

**⚠ 最重要——现有测试把当前行为钉成了期望值**（我逐行读过）：`tests/test_engine.py:256-259`


**这条断言字面要求「指数被跨路由连带切换」**，注释还把它解释成「切换真的生效了」。

## §3 已确认错误 #2：文档给出的验证命令被 `addopts` 静默削弱

**文件/行**：`README.md:265`、`docs/ARCHITECTURE.md:866`、`pyproject.toml:59`（`addopts = "-q"`）。

**触发条件/反例**：照抄 README 的 `python -m pytest -q`。

| 臂 | argv | exit | stdout 汇总行 |
|---|---|---|---|
| **A = README 原命令** | `-m pytest -q` | **0** | **（ABSENT）** 末行是 `........... [100%]` |
| B 对照：清空 addopts | `-m pytest -q -o addopts=` | 0 | `1891 passed in 98.17s` |
| C 对照：裸 `pytest` | `-m pytest` | 0 | `1891 passed in 91.43s` |
| D 对照：显式单一 `-q` | `-m pytest -o addopts=-q` | 0 | `1891 passed in 99.38s` |

**机制**：pytest 的 `-q` 可叠加；`addopts` 已含一个，文档再给一个 ⇒ `-qq`，该级别**不输出统计汇总行**，
只剩进度点。**exit code 仍 0**。

**影响**：① 照文档执行的人**看不到任何测试数量**，只剩「没崩」；② 同一行的 `1035 项` **已过期**
（实测 **1891**，少报 **856**），`ARCHITECTURE.md:866` 写 `1064 项` 同样陈旧；③ 全仓库测试数声明
**互不一致**（1026/1028/1029/1032/1035/1047/1048/1064/1068/**1891**）；
④ `docs/audits/intraday/2026-09-20_04-05-31_JST.md:233` **4 天前就记录过**该漂移
（「本轮审计没有权限改 README，只记录」）⇒ **已记录但一直没修**。
注：历史文档里的旧数**不算错误**（自带日期、属归档）；**可执行命令后面挂的未标日期数字**才算。

**修复建议**：文档命令改为 `python -m pytest -o addopts=-q`（或 `python -m pytest`），或去掉
`addopts="-q"`；并把测试数量从文档里**删掉**，避免每加测试多一处漂移。

**验收测试**：脚本**必须**解析 `N passed` 行并断言 `N > 0`（当前**无 CI**：`.github` 在尖端**不存在**，
tracked `.github` 文件 **0** 个）。**阳性对照**：故意让一个测试失败，断言解析到的不是 `0 passed`。
