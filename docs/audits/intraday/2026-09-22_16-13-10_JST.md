## 1.2 更正附刊把 `engine.py:1180` 的异常出口列成 P0，证据不足，降为 P2 robustness

更正附刊指出：

```python
for src in self._universe_sources():
```

位于 provider-call 的 `try` 外，若 `_universe_sources()` 本身抛异常，`refresh_id` 已自增但 `_universe_attempt` 不会 finalize。**这个机制问题成立。**

但本轮继续做 production reachability 审计后，不支持 P0：

1. 正常 provider 网络/解析异常发生在 `src.universe()`，它已经位于 per-source `try/except` 内，会继续到下一源，最终能走 `all_failed` 台账。
2. `_universe_sources()` 内的 `build_source(settings, name)` 自己也有 `try/except`，坏源构造失败只会被跳过。
3. `Settings.get()` 对普通 YAML dict 是纯字典安全遍历，缺键返回 default。
4. 能让 `_universe_sources()` 在 `for` 求 iterable 阶段直接抛出的当前已知方式，是 monkeypatch、自定义异常对象或内部状态破坏；**仓库内没有给出一个正常产品输入/网络条件能触发它。**

因此本轮把该项重命名为：

# 4. 新 P1：`IT-P1-UNIVERSE-TRANSPORT-TRISTATE-R1`

这是本轮从 fixed SHA 源码直接确认的新问题。

当前 `Engine.universe_truth()` 有两处：

```python
"transport_complete": bool(transport_complete)
```

分别在顶层和 `active_snapshot`。

当 `_universe_meta` 为空，真实语义是：

```text
transport_complete = None
```

但导出会变成：

```text
False
```

因此 cold-start / pinned / replay / 尚未刷新过的场景会被描述成：

> provider 明确声明股票池被截断。

13:55 更正附刊已经复现了这一错误。

本轮新增的是：**同一缺陷在 live-session 又复制了一次。**

`make_round_sample()` 继续执行：

```python
bool(universe_truth.get("transport_complete"))
```

所以只改 Engine 不够。

### tri-state 必须端到端保留

```text
True  = provider / transport 明确完整
False = provider / transport 明确不完整
None  = 没测到 / 没声明
```

健康语义：

```text
False -> universe_transport FAIL
True  -> transport OK
None  -> NOT_MEASURED
```

不得在 Engine、Store、round sample、session aggregate 的任一层使用 `bool(x)` 抹掉 None。

本轮 `universe_missingness_propagation.json` 还记录了同族问题：

```python
universe_age_s = _safe_float(None)
```

会得到：

```text
0.0
```

即“年龄未知”变成了数值意义上**最年轻**。

这是为什么 missingness contract 不能继续靠“安全转 0”统一处理。

# 9. 本轮主改造：Health Consumer Contract v1

过去多轮反复出现同一类缺陷：

```text
数据已经算出来
→ 字段已经进 report
→ 测试只断言字段名字存在
→ 最终 verdict 没有消费者
```

目前已经出现：
- Delivery accounting；
- no-data / cumulative cache；
- Universe absolute size；
- Universe transport session；
- session watchlist scope；
- `evaluability_fail_coverage` 读出但无实际判决效果；
- session delivery totals 只展示、未必参与 verdict。

所以继续“发现一个接一个”不够，下一版应该给健康系统加一个**消费合同**。

## 9.1 Consumer Registry

至少列明：

| Produced fact | Expected consumer |
|---|---|
| `watchlist_only_rounds / ever_watchlist_only` | `universe_scope` |
| `rounds_transport_incomplete` | `universe_transport` |
| `worst_state` | `universe_freshness` |
| `delivery_accounting_session` | `delivery_accounting` |
| `evaluability_fail_coverage` | **要么实现消费者，要么删除配置键** |

## 9.2 Consumer-effect test

所有 intended health fact 必须有同一种测试：

```text
先造 fully-green baseline
只修改一个事实
断言完整 verdict signature 按设计变化
```

不能只做：

```text
assert "field_name" in source
```

或：

```text
assert field exists in report
```

## 9.3 Missingness contract

```text
Optional[bool]
Optional[float]
```

在 producer → Store → round sample → session summary → verdict 全链保持。

禁止：

```text
None -> False
None -> 0.0
```

除非该字段的业务合同明确规定默认就是 False/0。

## 9.4 Session 优先级

最终 verdict 必须按：

```text
session measured facts
> t0 setup snapshot
```

但不是简单覆盖，而是按轴合并：
- scope：任一 measured fallback 都必须留下；
- transport：任一 explicit incomplete 都必须留下；
- freshness：取最坏；
- unknown：保持 not_measured。

完整候选合同已落本轮 `health_consumer_contract_v1.json`。

## 本轮最终判断

最近几轮已经证明，一个非常稳定的根因反复出现：

```text
事实层算出来
→ 报告里有字段
→ 测试看到字段名字
→ 最终判决却没有消费
```

因此下一轮不能继续靠“发现第 7 个、第 8 个零读者”推进。

需要把它升级成系统级门禁：

> **任何被宣称为 health fact 的字段，都必须有 consumer-effect test；只存在于报告而不能改变结论的字段，不算完成。**

同时，“缺数据”的语义必须端到端保留：

```text
unknown != false
unknown != 0
unknown != fresh
```

本轮还纠正了两个重要的审计偏差：
- 13:55 附刊把 outer `_universe_sources()` 异常出口升成 P0，当前仓库证据不足，按生产可达性应降为 P2 robustness；
- 13:32 建议的 `setup OR 顶层 fell_back` 只能抓 30/30 轮 fallback，**29/30 轮仍会漏**，必须保留 round count/ratio/ever 事实。

当前最优推进顺序因此是：

**Health Consumer Contract + tri-state → freshness clocks → source/time/window truth → membership/provenance → real dataset/labels → tabular → TCN。**
