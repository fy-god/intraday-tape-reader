## §0 本轮一句话

* **机制**：`_universe_meta` 里 provider 已算好的分母**没有任何出口**，
  于是 `evaluate_health` 只能看 `setup['universe_size']`（绝对只数），
  **回答不了 `4500 / ? = ?`**。

  这是唯一会让用户**系统性**误读结果的因素。

  1. **新 `Engine.universe_truth()`**：把分母与**四个分开的** coverage 一起导出

     **分母未知时返回 `None`，绝不返回 0 或 1 冒充已知。**
  2. **`store.status()['universe_truth']`**：`_universe_meta` 的**第一个生产出口**。

  3. **`evaluate_health` 新增 `universe_coverage` 判决项**：
     `< 90%` → **fail**；`90–95%` → **warn**；`>= 95%` → **ok**；
     分母未知 → **ok（未测量）**。
* **设计纪律（都有实测依据）**
  * 判据用 **`coverage_active`**（= `active_scan_codes / expected_total`），
    **不是** `coverage`（那是 `C_round` = 本轮返回/本轮请求）。
    云端 §8.3 明确 **`C_round` 永远不能替代 `C_active`** ——
    实测 `C_round=100%` 而 `C_active=76.10%` 时，判决**仍然转红**（有专门测试）。
  * **成员集 ≠ 可用 Quote 数**（云端 §8.2）：transport 拿到 100 个代码、
    其中 94 个能构造 Quote 时，`active_scan_codes` 必须仍是 **100**、不是 94。

  * 阈值 `UNIVERSE_COV_FAIL=0.90` / `UNIVERSE_COV_WARN=0.95` 是云端 §8.5 的
