  * `src/arad/engine.py:1334-1368`（修复前）`Engine._mark_stage()`

  即 `limit_board` / `tick_surge` / `unusual` / `spirit_index` / `spirit_price`
  这 5 条（7 条能发 Alert 的规则里占 5 条）。
* **机制**：`_mark_stage` 的门禁是
  ```python
  evals = getattr(observation, "signal_evals", None)
  if not isinstance(evals, dict) or sig not in evals:
      return
  ```
  于是 `signal_id` 只是**必要**条件，**不是充分条件** —— 该 signal 还必须
  已由规则自己创建了 eval 行。这 5 条规则恰好没有。
  根因**不是漏填字段**，而是：**可评估性与交付被错误地放在同一个 registry 上**。
* **影响**：真实回放 **66 条 committed 告警只有 6 条可对账**。
  60 条无法回答"它到底有没有交付" → 无法被 T+5/T+30 标签引用 →
  **无法定量回答"报得准不准"**。这是用户核心诉求的直接阻塞项。
* **为什么两个"显然的"修法都不对（都已用真实代码证伪，不是论证）**
  1. **只给另外 5 条规则补 `signal_id`** —— 不够。那条 `sig not in signal_evals`
     门禁照样拦下；实测填了也照样 `return`。
     （注：该建议出自 **13:37 轮**报告 `:183-187`，**不是**我 13:00 轮

     `considered=0/evaluable=0/hit_candidates=0/rule_selected=0` 却
     `bus_accepted=1/committed=1` 的幽灵行，违反可评估性不变量，

## §6 1–3 条有证据、可证伪的研究想法

### 想法 1〔**程序修复**〕：`signal_id` 与 `metrics["pattern"]` 的一致性门禁

* **证据**：本轮我为 8 个 pattern 手工写了 `signal_id`（§1.1）。这是
  **纯人工映射**，而 `metrics["pattern"]` 本来就在同一处赋值 —— 二者是
  同一事实的**两份拷贝**，必然有漂移风险（对照：`limit_board` 的
  `_make_seal/_make_touch/_make_break` 各写一次 pattern 与一次 signal_id）。
* **可证伪预测**：若加一条门禁"每条 Alert 的 `signal_id` 必须等于
  `<模块>.<metrics['pattern']>`（或显式豁免）"，则**任何** pattern 改名而
  忘记同步 signal_id 的提交都会立刻红灯。
  反证条件：若真实运行中两者恒相等，该门禁永不触发 —— 说明我过虑了。
* **类别**：**程序修复**（且成本极低，防止账本"能工作但名字说谎"）。

### 想法 2〔**任务定义调整**〕：交付率应当**按 signal 分别看**，不许汇总成一个数

* **证据**：本轮实测 8 个 signal 的交付分布差异极大 ——
  `tick_surge.surge 19` 条 vs `limit_board.limit_down_seal 3` 条；
  `volume_burst` 的 60 条候选被 cooldown 压成 6 条（交付率 10%），
  而 `limit_board` 几乎 1:1 交付。**把这两类混在一起算"系统交付率"
  会得到一个既不反映 cooldown 也不反映规则质量的平均值**。
* **可证伪预测**：若验收改为"逐 signal 的 `committed/rule_selected`"，
  则调 cooldown 应**只**显著改变 `volume_burst` 的交付率，而
  `limit_board` 基本不动。反证：若两者一起变，说明瓶颈在别处，我归因错了。
* **类别**：**任务定义调整**（不改产品语义，改"什么算交付成功"）。

### 想法 3〔**模型真正增量提升：无**〕：本轮**没有**任何模型层面改进

* 诚实声明：`程序修复` = §1.1 + §1.3（文档更正）；
  `任务定义调整` = 想法 2（尚未实施）；**`模型真正增量提升` = 0**。
* 核心问题仍未回答：**真实 Precision / Recall / 漏报率 / 收益 = `unavailable`**。
  本报告不编造任何数字。
* 但本轮确实**移除了**回答该问题的最后一道结构障碍：66/66 告警现在
  全部可被 T+5/T+30 标签引用（此前只有 6/66）。**这是"能开始测量"，
  不是"已经测出结果"** —— 两者不可混为一谈。
