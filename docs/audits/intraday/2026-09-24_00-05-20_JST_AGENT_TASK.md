## WP03 — SourceManager.call_detailed contract validation【P1/P2】

### 现有 P1

```text

backup -> 健康 SnapshotFetchResult
```

当前行为会在 `out._replace(...)` 处 AttributeError，备源不调用。

### GREEN

把以下全部放进每个 source 的 `try`：
```text
1. 获取结果
2. isinstance(SnapshotFetchResult) / 合同验证
3. actual source 绑定
4. caller route 绑定/验证
```

类型错误必须按 source failure 处理并尝试后备源。

### 新 P2 route guard

构造一个类型正确的 outcome：
```text
caller route = stocks
result.route = index
```

修后不得静默让：
```text
Manager _serving/_fails 记 stocks
而 result.route 仍写 index
```

可选策略：
- Manager 直接规范化 `result.route = caller route`；或
- 把 route mismatch 当 contract error，继续 failover。

必须固定一个策略并写测试。

### source 对照

结果自填错误 source 时，仍应绑定到**实际被调用对象**的 `name`。

### rollback tooth

回退 type validation 到 try 外后，wrong-type primary 测试必须重新红。
