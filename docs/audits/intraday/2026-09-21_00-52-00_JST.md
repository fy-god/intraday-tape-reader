## 2. 已确认错误（本轮实测）

### 2.1 `IT-P1-CAPABILITY-003` —— capability health 的分母与语义都是错的 · **已修复**

**文件 / 函数 / 行（修复前）**
- `src/arad/capabilities.py:227-229`：`unavailable_capability = len(self.unavailable_codes)`
  —— 所有 rule 写入的 **code 集合并集**，且**不区分**"硬阻断"与"可跳过"。
- `tools/live_session.py:419-423`：`if n > 0: unavailable_rounds += 1`
  —— 把"这一轮里**出现过任意一个**缺失"当成整轮不可评估。
- `tools/live_session.py:502-503`：`ratio = unavailable_rounds / obs_rounds`
  —— **分母是"轮"**。
- `tools/live_session.py:104`：`unavailable_fail_ratio = 1.0`。
- `tools/live_session.py:657-660` docstring 把这个推论**明文写成契约**：
  「每一轮都不可评估说明整类规则在这整场 soak 里一次都没被验证过，判红。」

**触发 / 机制**
`ratio` 的分子是"出现过缺失的轮数"。**5000 只票里每轮只坏 1 只**，该轮就进分子；
连续 20 轮 → `ratio = 1.0` → 撞上 fail 阈值 → 判红，并配上
「整类规则在这整场 soak 里一次都没被评估过」。而真实可评估率是
**4999/5000 = 99.98%**。这不是阈值高低，是**分母不是同一件事**。

**影响**：soak 健康结论被**系统性误红**污染，而它正是后续 capability mask /
provider specialist / targeted fallback 的**分母来源** —— 分母错了，
下游所有基于它的判断都跟着错。

**修复（真实改了什么）**

1. `src/arad/capabilities.py` 新增 **`SignalEvalStats`**（`:172`），字段：
   `considered / evaluable / blocked_capability / advisory_missing /
   evaluated_no_hit / hit_candidates / published / blocked_reasons /
   blocked_sample`；派生量 `evaluable_coverage`（`:221`）
   **在 `considered <= 0` 时返回 `None`（not_measured），不是 `0.0`** ——
   填 0 会把"这一项没测"误报成"整类失效"，与旧缺陷同源。
2. 三个**互斥**语义常量：`BLOCKING` / `ADVISORY` / `NOT_REQUIRED`。
3. `RoundObservationSet` 新增有界记账 API：`mark_considered` / `mark_blocked` /
   `mark_advisory_missing` / `mark_evaluated` / `mark_published`，
   以及机械不变量自检 `check_signal_invariants()`（`:459`）。
4. `src/arad/rules/volume_burst.py` 按语义**分账**：
   - 缺 `turnover` 且 `min_turnover>0` → **blocking**（该票真的不能判）；
   - 缺 `volume_ratio` → **advisory**（`vr > 0.0` 为假即跳过门槛，
     规则靠速度/金额**仍能命中**）。为此新增 `_mark_advisory`（`:119`），
     **不写进 `unavailable_codes`**。
5. `max_per_round` 截断后单独 `mark_published` → **被截断的命中留在
   `hit_candidates`，绝不变成 `evaluated_no_hit`**（"被限流吞掉"与"没到门槛"
   是两件事，旧账本分不开）。
6. `tools/live_session.py` 健康判据改为**逐 signal 可评估率**（`:962-1020`）：
   只认一种 fail 形状 —— **某 signal 的 `considered` 全部被 blocked**。
   旧轮级比例保留为**诊断量**，且降级为**最高只到 warn**。

**真实数字（审计原文反例，本机复跑，脚本 `%TEMP%\repro_cap003.py`）**

| | 修复前 | 修复后 |
|---|---|---|
| 输入 | 20 轮 × 5000 code × 1 blocked | 同 |
| `capability_unavailable_ratio` | **1.0** | 1.0（仅诊断） |
| 真实按 code 可评估率 | 99.98% | 99.98% |
| 新口径整体可评估率 | ——（不存在） | **0.9998**（99980/100000） |
| `capability` level | **fail** | **ok** |
| `healthy` / `exit_code` | **False / 1** | **True / 0** |
| 文案 | 「整类规则…一次都没被评估过」 | 「逐 signal 可评估率 99.98%…（诊断：旧口径轮比例 100%，仅供参考）」 |

**验收测试（审计给的两条，均通过）**
- 「5000 code 中 1 code blocked、连续 20 轮 → **不得**被判 `evaluable_coverage = 0`」
  → `tests/test_live_session_observation.py::test_one_blocked_in_five_thousand_is_not_fail`
- 「单条 enabled signal 的**全部** code 都 blocked 时，**才**允许 whole-class FAIL」
  → `tests/test_live_session_observation.py::test_all_blocked_signal_is_the_only_fail`

**新增容错闸门**：样本不足（`considered < evaluability_min_samples = 200`）时
**最多只到 warn，不判 fail** —— coverage 是小样本比率，一只票坏掉就能让 3 只票的
signal 从 1.0 掉到 0.67，没有足够样本时判红等于**用噪声定罪**。

**语义修正声明（不是放宽断言）**：两条既有测试编码了旧语义，我**改了它们的断言**：
- `test_two_missing_fields_recorded_when_both_reachable`（`tests/test_capabilities.py`）
  原断言 `unavailable_capability == 1`（把"缺量比"也算能力缺失）。
  修正为 `== 0` + 断言该票**仍产出一条 alert** —— 因为量比缺失的真实语义是
  **可跳过**。理由写在该测试 docstring 里，**不是为了让测试变绿**。
- `test_capability_whole_class_unavailable_is_not_green` 与
  `test_unavailable_thresholds_configurable`（`tests/test_live_session_observation.py`）
  原断言 `level == "fail"`，修正为 `"warn"`。理由同样是**分母**：这两条只有轮级
  数据，用"这轮出现过缺失"推"整类一次都没评估过"不成立。真正的 fail 形状由新的
  逐 signal 测试钉住。

### 2.2 `IT-P2-OBS-STATUS-001` —— `/api/status` 不暴露 observation 身份 · **已修复**

**文件 / 函数 / 行（修复前）**：`src/arad/store.py` `AlertStore.status()` 只暴露
`observation` 与顶层 `"ts": datetime.now()`。**`ts` 是请求时刻，不是账本时刻。**

**触发 / 机制**：失败轮**故意**保留最后一次成功账本（那比清空有用）。但消费者
拿请求时刻去解释它，就会把几分钟前的旧账当成"刚刚的"。

**修复**：`set_poll_stats()` 在**同一临界区**记录身份三元组并与账本内容同轮写入
（`store.py:158-161`）：
- `observation_seq`（每写入一次 +1；未变 = 本轮没产生新账本）
- `observation_observed_at`（账本写入时刻 `YYYY-MM-DD HH:MM:SS`；无账本 `None`）
- `observation_poll_count`（账本写入时的 poll 计数；无账本 `0`）

三者与 `status()`（`store.py:258-260`）**同一临界区读出**，避免"新 seq 配旧账本"。
刻意**不复用** `_last_poll_ts` —— 后者每次 poll 都刷新（**包括**没账本的失败轮），
用它就是"账本没更新但时刻变新了"，比原缺陷更坏。

**验收**：`tests/test_status_observation_identity.py`（12 passed）。
**齿的真实分类（实测，不夸大）**：回退 `store.py` 后逐条分类 ——
**真行为级验牙 1 条**（`test_observed_at_is_not_the_request_time`，红在
`AssertionError`，只用修复前已存在的 API）；**新增契约断言 1 条**
（`test_status_payload_still_has_original_keys`，形式上 AssertionError 但断言的是
新键存在，**不算验牙**）；**结构性 7 条**（`AttributeError` ×5 / `KeyError` ×2，
只证明"新东西还没写"）；**不受影响 3 条**（回归保护）。
→ **本项的行为证据只有 1 条**，如实记录。

| `test_truncated_hit...` / `test_published_never_exceeds...` | 我用了 `VolumeBurstRule({"max_per_round": 1})`，但该类第一个位置参数是 `name` 不是 `cfg`；且 `ctx.cfg` **优先于** `rule.cfg`，配置必须从 ctx 下发 | **我的测试错** |

不把测试写错包装成"发现了 4 个 bug"。

### (4) 一个既有测试编码了缺陷语义

`tests/test_capabilities.py::test_two_missing_fields_recorded_when_both_reachable`

**不是**为了让测试变绿而放宽 —— blocking 侧的可见性仍由
`test_sina_marks_unavailable_instead_of_silent_zero` 钉住。
