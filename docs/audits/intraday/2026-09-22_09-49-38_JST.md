## §4 【P1 · 已确认错误】断供后 `_universe_meta` **不清空**，把陈旧分母当现状报"覆盖 100.00%"

**文件/函数/行**
- `src/arad/engine.py:1138-1140` —— `refresh_universe()` 全源失败路径：`return 0`，**不重置 `self._universe_meta`**
- `src/arad/engine.py:1114 / :1133` —— 仅**成功**路径写 `_universe_meta`
- `src/arad/engine.py:914-979` —— `universe_truth()` 直接读 `_universe_meta`，**无任何新鲜度/时效字段**
- `src/arad/store.py:310-316, :346` —— `status()['universe_truth']` 是**每次调用实时**取值

**触发条件**：一轮成功刷新之后，provider 完全不可达（东财限流 / 断网）。

**机制**：`_codes` 保留旧池（这是**设计**，`engine.py:1076` 注释："绝不清空 —— 清空会让引擎彻底停摆"），
但 `_universe_meta` **同样**被保留且**不标记为陈旧**。`universe_truth()` 读它得出的四个 coverage
与断供前**逐字段相同**。这与 h=20 轮修掉的"判决层读旧账本"**同一 bug 类**，只是换了对象。

**影响（实跑，真实 `Engine` + 注入假源，`fake source calls` 计数证明没走网络）**
```
STEP 1 healthy refresh:  refresh_universe() -> 5913  (fake calls=1)
   universe_truth(): provider_declared_total expected=5913 active=5913 cov_active=1.0
STEP 2 provider now TOTALLY fails: refresh_universe() -> 0  (fake calls=2)
   len(engine._codes) = 5913   (stale pool, by design)
   universe_truth() AFTER the outage:
      denominator_kind  = 'provider_declared_total'   <-- 与 STEP 1 相同
      expected_total    = 5913                        <-- 与 STEP 1 相同
      active_scan_codes = 5913                        <-- 与 STEP 1 相同
      coverage_active   = 1.0                         <-- 与 STEP 1 相同
      last_attempt_at = None   last_applied_at = None   last_complete_at = None
STEP 3 evaluate_health:
   healthy=True  exit=0  fail=[]
   universe_coverage level=ok: 全市场覆盖 active 5913/5913 = 100.00%（transport 100.00%、usable 100.00%）
```

**影响面（精确，不含糊）**：`store.status()` 是**每次调用实时**读 `engine.universe_truth()` 的
（`store.py:310-316`），看板/API **持续**消费它。所以断供期间**实时状态出口会显示"覆盖 100.00%"**。
**边界**：会话**末尾**的 `evaluate_health` 用的是 `live_session.py:2284-2289` 的**循环前快照**，
所以本条**不**直接污染最终 health 判决 —— 它污染的是**实时状态出口**。这个区分必须说清，不能夸大。

**修复建议**：`refresh_universe()` 的全失败分支（`:1138-1140`）清空或**标注** `_universe_meta`
（例如置 `_universe_meta_stale_at = time.time()`），并让 `universe_truth()` 输出
`stale: true` / `age_s`，由 `universe_coverage` 判决项据此判 `warn`。
这也顺带让 `engine.py:976` 那三个**死键**（见 §5）有意义。

**验收测试**：成功刷新 → 令 provider 抛异常 → 再调 `refresh_universe()` →
断言 `universe_truth()["coverage_active"] is None`（或 `stale is True`）。**当前实测仍为 `1.0`，测试会红。**
