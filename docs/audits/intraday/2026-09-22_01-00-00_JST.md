### 1.2 `IT-P1-UNIVERSE-WATCHLIST-PIN-001`：一次**临时**降级变**永久** 〔**已确认 · 已修复**〕
*(云端 00:08 轮 §2 发现；我独立复现确认)*

* **文件/函数/行号**：`src/arad/engine.py:1043`（修复前），
  位于 `_maybe_refresh_universe()`
* **触发条件**：normal 模式下一次全市场股票池抓取失败（限流/断网）。
* **机制**：`_codes` setter 的合同是
  ```python
  self._codes_raw = list(codes)
  self._codes_pinned = bool(codes)      # 赋非空列表 = 显式 pin
  ```
  而**降级分支复用了同一个 setter**：
  ```python
  if not self._codes and self.watchlist:
      self._codes = list(self.watchlist)   # <- 顺手 pin 了
  ```
  下一次 `_maybe_refresh_universe()` 一进门就
  `if self._codes_pinned and not force: return`
  → **源端恢复后也再不会尝试全市场**。
* **实测（我构造，不走网络）**

  | 步骤 | `_codes` | `_codes_pinned` | `refresh_universe` 调用次数 |
  |---|---|---:|---:|
  | 初始 | `[]` | `False` | — |
  | 源端失败 → 降级 | `['000001','000002']` | **`True`** | — |
  | 源端恢复 + TTL 过期 | 仍 2 只 | `True` | **0** |

  修复后第三行为 **1 次**，`_codes` 回到 3000 只。
* **影响**：**用户会在毫无后续提示的情况下，永久只盯自选股那几只票。**
  降级警告只出现过一次，之后系统一直"正常运行"（`healthy` 不看 universe）。
  这是**静默降级成静默残废** —— 与"没报警可能是没扫到"同类的用户可感知危害。
* **修复**：降级走 `_codes_raw` 直赋（**不 pin**），并显式
  `self._codes_pinned = False`，保留"下轮还会重试全市场"。
* **对照（必须不能改坏）**：`--watch-only`（`engine.py:1536`）与 replay
  用 setter 是**对的** —— 它们确实要 pin，
  `tests/test_cli_watch_only.py` 明确断言这一点。已加回归测试钉住。
* **验收测试**：`test_degraded_fallback_must_not_pin`、
  `test_source_recovery_returns_to_full_market`、`test_watch_only_still_pins`

## §6 1–3 条有证据、可证伪的研究想法

### 想法 1〔**程序修复**〕：判决项必须"带证据来源"，否则不许注册

* **证据**：本轮 §1.1 的根因是判决项名单里**没有** `delivery_accounting`
  —— 而这不是"写错了条件"，是**根本没人接**。
  更直接的证据：`R-22` 的 `_scope_note` 是死键、
  上一轮 `check_delivery_invariants()` 生产零调用、
  `R-12` 的 `_universe_meta` 零出口 ——
  **同一个失败模式在我这条线上已经出现至少 4 次**：
  *"我把数据算出来了 / 把字段放上去了"被当成"问题解决了"*。
* **可证伪预测**：若规定"每个判决项必须声明它消费的 metrics 键，
  且加一条门禁：**任何被写入 metrics 的 `*_status` / `*_accounting` /
  `*_coverage` 类字段，必须至少被一个判决项引用，否则测试失败**"，
  则本轮这类"修在数据层"的缺陷**在提交时就会被抓住**，
  不必等云端下一轮来发现。
  反证条件：若真实运行中不存在"算了没人读"的字段，这条门禁永不触发。
  —— 但本轮已找到 4 个实例，**该反证条件已被证伪**。
* **类别**：**程序修复**（把"是否有人消费"变成可测断言）。成本低、直接命中复发模式。

### 想法 2〔**任务定义调整**〕：健康判决必须**显式声明它的盲区**

* **证据**：`evaluate_health` 报 `healthy=True / exit 0`，但
  §4 的 `R-21` 说明它对**扫描范围从 5913 掉到 4100** 完全不敏感；
  §1.1 之前它对**账本损坏**也完全不敏感。
  也就是说 `exit 0` 目前的真实含义是
  *"我检查了 10~11 件事，它们都过了"*，**不是** *"系统健康"*。
  用户读到的却是后者。
* **可证伪预测**：若判决输出改为
  `{"healthy": ..., "checked": [...], "not_checked": ["universe_coverage", ...]}`
  并对每个 `not_checked` 项给出"为什么现在测不了"，
  则用户能一眼看出"exit 0 并不覆盖扫描范围"。
  反证条件：若 `not_checked` 恒为空，说明系统确实全覆盖，本改动无用。
  —— 本轮已知至少 1 项（universe）为空，**反证不成立**。
