## 1. 已确认错误（真实代码复现）

### 1.1 `IT-P1-RAW-PRESENCE-ROUTE-SCOPE-FALSE-GRADE-044`【确认 · 已修】

**文件/函数/行号（云端 @55dc → 我复核的当前树）**：

* `src/arad/engine.py` · `_fetch_indices_detailed()` — 指数未启用 / 抓取异常
  均返回 `([], None)`
* `src/arad/engine.py:2245`（云端 `@55dc:2226-2229`）· **无条件**导出
  `{stocks: exact_stock, index: exact_index}`
* `src/arad/engine.py:2010`（云端 `@55dc:1922-1994`）· 空轮分支**硬编码**
  `{stocks: True, index: True}`

**机制**：一个 bool 同时承担**四种**本应分开的状态：

```text
True  = 有 outcome 且 raw evidence exact
False = 有 outcome 但 legacy/projected
?     = route 根本没请求                     <- 被压成 False
?     = route 请求了但 fetch 失败/无 outcome  <- 被压成 False
```

两个方向都不诚实：

* **false downgrade**：没 dispatch 的 route 被记成 `False` = "投影反推"，
  于是一个**根本没测过**的 route 反过来给 soak 制造黄色证据等级；
* **false upgrade**（云端 §2.3 认定**最危险**）：空轮分支**完全不看
  `stk_outcome/idx_outcome`**，指数请求**失败**时被粉饰成 `exact=True`。

**我独立复现（真实代码，非转述）**：

```
engine.py:2245  raw_presence_known_by_route={
                    ROUTE_STOCKS: exact_stock, ROUTE_INDEX: exact_index}
engine.py:2010  raw_presence_known_by_route={
                    ROUTE_STOCKS: True, ROUTE_INDEX: True}
```

`stk_outcome` / `idx_outcome` 在空轮分支**确实在作用域内**（定义于
`:1967`/`:1974`/`:1986`）—— 也就是说**不是拿不到，是没看**。
这一点我要特别指出：这让 §2.3 从"设计权衡"变成**纯粹的疏漏**。

**修复**：新增 `Engine._route_raw_presence`（`engine.py:1598`）作为
**唯一事实来源**，正常路径（`:2309`）与空轮分支（`:2065`）**共用**它
（bug 类 b：禁止同一语义两份实现）。冻结合同：

```text
outcome present + raw_presence_known=True  -> True   (exact)
outcome present + raw_presence_known=False -> False  (projected/legacy)
route 未请求                                -> **省略键**
route 请求了但 outcome=None（失败/无证据）  -> **省略键**（下游 not_measured）
```

**省略键**的语义是"本 route **不适用 / 没测到**"，
由下游判成 `not_measured`，**绝不**冒充 projected 或 exact。

**验收测试**：`tests/test_raw_presence_route_scope.py`（**19 条**）
覆盖四态合同、空轮不硬编码（**AST 门禁**，非子串）、helper 唯一性、
放大器、043 分母。

### 1.2 云端 §3 放大器：零值 shape key 被当成 route 活动【确认 · 已修】

**文件/函数/行号**：`tools/live_session.py:1115-1158`（`_seen_here` 构造）

**机制**：`_route_ledger()` 为 **schema 稳定**每轮都保留
`stocks` + `index` 键，**即使 index 根本没请求**，键也存在、只是值为 **0**。
旧写法只 union map 的 **keys**：

```python
_seen_here |= {str(x) for x in _m}
```

于是 `index: 0` 仍被当成"这条 route 本轮出过数"，后果有两个：

1. 计入 `rp_rounds_by_route` —— **伪造 route 活动**；
2. 进入 `_seen_here - set(_rp_here)` 差集 —— **假 partial**，
   而 `partial` 是本项目**唯一判 fail** 的证据等级分支。

**修法（我按云端口径实现）**：**键存在 != 有活动**。
不删零键（那是 schema 稳定性要求），只在**消费端**区分：
只有 `returned/admitted/reject` **任一为正**才算本轮真的出过数。

新增 `_positive_activity()`，接受三种形状并 **fail-closed**：

| 输入 | 判定 |
|---|---|
| `int`/`float` | `> 0` |
| `dict`（`reject_by_route` 新版形状） | **任一子值** `> 0` |
| `tuple`/`list`（旧形状 `(future, ooo)`） | **任一元素** `> 0` |
| `None` / 字符串垃圾 / `bool` | **无活动** |

`bool` 判 False 是刻意的：`True` 是布尔真值不是计数，
若放行会让 `{index: True}` 这类脏值伪造活动。

### 1.3 `IT-P2-SOAK-RAW-PRESENCE-ROUND-DENOMINATOR-043`【确认 · 已修】

**文件/函数/行号**：`tools/live_session.py:2874`（`evaluate_health`）

**机制**：

```python
_g_rounds = _safe_int(_grade.get("rounds_seen_by_route"))
```

但 `raw_presence_grade["rounds_seen_by_route"]` 在 `:1520-1595` 明确是
**`{route: round_count}` 即 dict**。`_safe_int(dict)`：

```
_safe_int({'stocks': 1, 'index': 1})  ->  0
_safe_int({'stocks': 2})              ->  0
_safe_int(1)                          ->  1
```

于是人类可读证据文本出现**荒谬分母**：`投影 1/0 轮` / `精确 0 轮`。

**修后实测**（`round_denominator_043.json`）：

```
证据等级为**投影**（1/1 轮，投影 route: ['stocks']）—— 已知降级，
missing/quality 已降为**上界**；非事故，但结论措辞不得含'精确'
```

`1/0` → `1/1`。**判决级别没变**（所以云端定 P2 是对的），
但**证据文本在说谎** —— 而证据文本是 soak 报告里人唯一会读的东西。

**分母口径**：取**任一 route 的最大轮数**。理由：各 route 轮数可能不同，
取最大 = "至少覆盖了这么多轮"，**不会把分母压低**
（压低分母 = 把覆盖率说得比实际好，是假绿方向）。

**云端对测试的批评，我接受**：`tests/test_soak_grade_gate.py`
明明构造了 `rounds_seen_by_route={"stocks":1}`，却**只断言 warn/healthy，
没有断言 detail 里的 `1/1`** —— 这正是测试盲点。新测试补上了这条断言。
