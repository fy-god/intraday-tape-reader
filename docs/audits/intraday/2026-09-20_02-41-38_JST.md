## 4. `IT-P1-CAPABILITY-001` — Sina 占位零被当真实业务零（上游提出，本轮修复）

### 4.1 文件 / 函数 / 行号

- 缺陷 1：`src/arad/rules/volume_burst.py` L131（`evaluate()` 内）
  ```python
  if min_turnover > 0.0 and float(q.turnover) < min_turnover:
      continue
  ```
- 缺陷 2（对照）：同函数 L138 量比门槛**有**缺失语义
  ```python
  if vr_thr > 0.0 and vr > 0.0 and vr < vr_thr:
      continue
  ```
- 来源：`src/arad/sources/sina.py` L219-220 / L306-307 字面写
  `turnover=0.0, volume_ratio=0.0`

### 4.2 触发条件

主配置 `sources.primary=tencent`、`fallback=[sina]`，且
`volume_burst.enabled=true`（默认 `min_turnover: 0.5`）。Tencent 连续失败
达阈值后热备/切换到 Sina。

### 4.3 机制

`Quote.turnover` 是 `float=0.0`，同一类型承载两种语义：

| 语义 | 含义 |
|---|---|
| 真业务零 | 源**提供了**字段，值就是 0 |
| 能力缺失 | 源**不输出**该字段，解析器填 `0.0` 占位 |

规则无法区分，于是 Sina 服务期间 `q.turnover < 0.5` 恒真，**所有**股票在
换手率门槛被静默拒绝。`SourceManager` 认为调用成功、`health()` 正常，
用户只看到放量告警整类消失。

### 4.4 复现证据（真实代码，非推演）

构造同一 Quote 业务状态，只改供数源：

```text
Tencent（提供 turnover+量比）
  turnover=3.0  volume_ratio=5.2  provides(turnover)=True
  -> 告警 1 条  ✅ 可评估(命中)            ← 修复前

Sina   （不提供，填 0.0 占位）
  turnover=0.0  volume_ratio=0.0  provides(turnover)=False
  -> 告警 0 条  ❌ 被静默过滤              ← 缺陷
```

### 4.5 修法与**阶段一边界**（重要）

本轮审计报告 §3.4 明确写道：

> **第一阶段不要擅自"缺 turnover 就跳过门槛"**，那会改变误报率。先把
> `evaluable / unavailable_capability / evaluated_no_hit / hit` 四态显式化。

**我最初正是踩了这个坑**：第一版改成"能力缺失就 `continue` 跳过门槛"，
复现脚本立刻显示 Sina 也产出 1 条告警 —— 也就是**误报率被悄悄改变了**。
已按报告要求回退为"只记账、不改判定"。

最终实现：

1. 新增 `src/arad/capabilities.py`：
   - `SourceCapabilities`（7 个能力位：turnover / volume_ratio / depth_l1 /
     depth_l5 / outer_inner / float_cap / provider_time）
   - `CAPABILITY_TABLE` 三家真实能力（逐行核对解析器得来）
   - `ObservationDecision`、`RoundObservationSet`（WP08 账本）
2. `RuleContext` 增加 `capabilities` 与 `observation` 两个字段，以及
   `provides(key)`。**未挂 capability 时 `provides()` 返回 True** ——
   保证不涉及多源切换的既有路径行为逐字不变。
3. `VolumeBurstRule` 在换手率/量比门槛处**只增记账**：
   ```python
   if min_turnover > 0.0 and not ctx.provides("turnover"):
       self._mark_unavailable(ctx, code, "turnover")
   if min_turnover > 0.0 and float(q.turnover) < min_turnover:
       continue                      # 判定保持原样
   ```
4. `Engine` 用 `serving_of(ROUTE_STOCKS)` 而非 `current` 取能力 ——
   热备期间 `current` 仍是主源，用错会把 Sina 的数据按 Tencent 的能力判定。

### 4.6 修复后（真实执行）

```text
Tencent  -> 告警 1 条，unavailable_capability=0
Sina     -> 告警 0 条，unavailable_capability=1   ← 行为未变，但不再静默
Eastmoney-> 告警 1 条，unavailable_capability=0
```

端到端确认能力真的走到引擎：

```text

capabilities_for -> turnover=False volume_ratio=False
[OK] 热备期间取到的是 Sina 能力（不是 current=tencent）
```

表格 vs 解析器逐源核对（防漂移）：

```text
sina       源码里 turnover=0.0 字面量: True   表声明提供: False  [OK] 一致
tencent    源码里 turnover=0.0 字面量: False  表声明提供: True   [OK] 一致
eastmoney  源码里 turnover=0.0 字面量: False  表声明提供: True   [OK] 一致
```

## 5. `IT-P0-002` — provider 事件时间无写前准入（上游提出，本轮修复）

### 5.1 文件 / 函数 / 行号

- `src/arad/engine.py` `EngineState.window()`（旧 L70）
  ```python
  cutoff = now_epoch - float(seconds)
  return [p for p in h if p[0] >= cutoff]      # 只有下界，没有上界
  ```
- `src/arad/engine.py` `EngineState.update()`（旧 L129-130）
  ```python
  if q.ts is not None and q.ts > now:
      pass  # 行情时间戳超前（时钟偏差），忽略    ← 空操作，数据已写入
  ```

### 5.2 触发条件

provider 返回的事件时间超前于本机 `now`，或乱序到达（迟到点）。

### 5.3 机制

`window()` 文档承诺闭区间 `[now-seconds, now]`，实现只过滤下界，未来点
可以进入窗口；`update()` 先把 quote 写进 `quotes/history`，之后那句
`pass` 什么也没做。两个缺陷叠加，`price_change()` 会算出**真实世界还没
发生的涨幅**，规则据此产出无中生有的告警。

### 5.4 复现证据（修复前，真实执行）

```text
A) window() 缺上界
   窗口内点数: 2
     ts=...(+600s)  price=10.0   <-- 未来点！
     ts=...(+0s)    price=10.5
   结果: [XX] 未来点进入了窗口

B) price_change 被污染
   price_change = 30.000000000000004
   结果: [XX] 未发生的 +30% 被当成真实涨幅

C) update() 只 pass
   quotes 里有 600002: True
   history 里有 600002: True
   结果: [XX] 超前数据已写入状态（pass 是空操作）

D) 乱序倒挂
   窗口内: ts(+0s) price=10.0 -> ts(-120s) price=8.0
   结果: [XX] 首尾按插入序而非时间序，涨跌幅算反
```

### 5.5 修法

1. `window()` 补上界并排序：
   ```python
   return sorted(
       (p for p in h if cutoff <= p[0] <= now_epoch),
       key=lambda p: p[0],
   )
   ```
2. `update()` 改为**写前准入**，新增 `_admit_time()`：
   - `q.ts > now + FUTURE_TOLERANCE_SECONDS(120s)` → 整只丢弃，计入
     `stats["t_reject:future"]`；
   - 轻微超前（时钟抖动内）→ 时间戳夹到 `now`，保留数据；
   - 迟到且比窗口最后一点更旧 → 不顺延追加，计入
     `stats["t_reject:out_of_order"]`；
   - `q.ts is None` → 按接收时间处理（兼容既有 source 不填 ts 的行为）。

### 5.6 修复后（真实执行）

```text
A) [OK] 已挡住（窗口只剩 1 个点）
B) price_change = None
C) quotes/history/last_price 均无 600002，stats["t_reject:future"]=1
D) [OK] 窗口按时间序：8.0 -> 10.0
```

## 8. 三条可证伪的研究想法

### RF-01【程序修复】capability 缺失应触发**跨源补洞**而非只记账

- **假设**：当 `volume_burst` 依赖的 turnover 在当前源不可用时，引擎对
  **受影响的那批代码**向备用源发一次定向 `snapshots`，可用率显著高于
  现在的"整类静默失效/降级"。
- **证伪条件**：在真实盘中注入 Tencent 故障，若补洞请求的额外延迟使该轮
  `poll_ms` 分位数超过 `poll.universe_seconds` 预算，或补洞后
  `evaluable` 提升 < 10%，则假设不成立。
- **为什么值得做**：现在的修法是"看见缺失"，但用户要的是"别丢告警"。

### RF-02【任务定义调整】"能力缺失"应该进入告警流，而不是只进日志

- **假设**：Sina 服务期间产出一条**聚合型**系统告警（如
  "放量规则当前不可评估：缺 turnover，影响 4821 只"），用户对漏报的
  感知与处置显著改善。
- **证伪条件**：若 soak 中出现频率 > 1 次/小时，或与真实异动告警在同一
  通道造成遮蔽（真实告警被挤掉），则说明该设计反而降低信噪比。
- **性质**：这是**任务定义**问题 —— 系统当前承诺"报异动"，未承诺
  "报自身能力缺陷"。

### RF-03【模型真正增量提升】provider-time 准入应成为因子，而非只做过滤

- **假设**：把 `t_reject:future` / `t_reject:out_of_order` 的比率作为
  H 类质量因子输入模型，能提升真实数据上的 PR AUC。
- **证伪条件**：真实语料上加入该因子后 PR AUC 相对 base 提升 < 0.005，
  或该因子在 family permutation 中重要性排名后 50%，则无增量、应移除。
- **前提**：依赖真实多日语料，当前 `blocked`。
