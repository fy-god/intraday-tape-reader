## 1. `IT-P0-002-R1` — 时间准入没有闭合到规则 Snapshot（P0，已修 + 红绿验牙）

### 1.1 文件 / 函数 / 行号

- `src/arad/engine.py` `EngineState.update()`（旧版，改动前）：
  - 签名 `-> None` —— **不返回准入结果**，调用方只能自己重算
  - `self.quotes[q.code] = q` 在乱序判断**之前**执行
  - `self.last_price[q.code] = q.price` 无条件执行
- `src/arad/engine.py` `Engine.poll_once()`（旧 L850）：
  ```python
  returned = {q.code: q for q in quotes if q.price > 0}   # 消费原始 provider 输出
  ```

### 1.2 触发条件

provider 返回远未来时间戳，或乱序（迟到）观测。

### 1.3 机制

两条独立的泄漏路径：

1. **规则侧**：`update()` 拒绝了 far-future，但 `poll_once()` 随后从**原始
   `quotes`** 重建 `returned/eligible/Snapshot`，被拒的点又回到规则手里，
   并被计入 `RoundObservationSet.admitted`。
2. **缓存侧**：`update()` 的乱序分支虽不追加 `history`，但 `state.quotes`
   与 `last_price` 早已被迟到旧价覆盖 —— "不顺延 history"只保护了 history。

根因是 **`update()` 没有把准入结果交出来**，调用方只能自己重算，
于是两边口径必然分叉。

### 1.4 复现证据（修复前，真实执行）

```text
R1-a) 迟到旧价覆盖 latest cache
  正常推进后: quotes.price=10.5  last_price=10.5
  喂入迟到旧价 8.0 后:
    history      = [10.0, 10.5]        ← 正确（未被污染）
    quotes.price = 8.0                 ← [XX] 被倒退
    last_price   = 8.0                 ← [XX] 被倒退

R1-b) far-future 绕过准入
  update() 是否拒绝: True  (stats={'t_reject:future': 1})
  poll_once 从原始 quotes 重建 returned: ['600001']   ← [XX] 仍在 Snapshot 里
    state 拒绝=True，但 Snapshot 仍含 1 只

R1-c) update() 是否暴露准入结果
  返回类型注解: None
  函数体里有 return: False    ← [XX] 调用方拿不到，只能重算
```

### 1.5 修法

**建立单一 admitted-current 合同**：

1. `EngineState.update()` 签名改为 `-> dict[str, Quote]`，返回本轮真正
   被准入的标的。
2. **乱序判定提到所有写入之前** —— 迟到点直接 `continue`，不碰
   `quotes` / `first_seen` / `day_open` / `history` / `last_price`。
3. `Engine.poll_once()` 改为消费返回值：
   ```python
   _t0_future = ...; _t0_ooo = ...            # 准入计数基线
   idx_admitted = self.state.update(idx_quotes, now) if idx_quotes else {}
   admitted = self.state.update(quotes, now)
   returned = dict(admitted)                  # 不再从原始 quotes 重算
   ```
4. **股票与指数共用同一准入合同**（WP01 第 5 条）：指数也走
   `state.update()` 的返回值。

## 6. 三条可证伪的研究想法

### RF-01【程序修复】准入合同应统一由 `state.update()` 返回值承载，禁止局部重算

- **假设**：把"谁被准入"的唯一来源固定为 `update()` 返回值后，类似 R1 的
  "两套口径分叉"缺陷可被静态检查发现 —— 即**任何** `for q in quotes` 形式
  的规则侧重建都应视为可疑。
- **证伪条件**：在 `src/arad/` 全目录加一条 lint（或 AST 检查）后，
  若它报出的候选点全部是误报，或它漏掉本轮的 R1 形态，则规则无效。
- **可执行动作**：可写成 `tools/check_admission_bypass.py`，与
  `check_bom.py` 同级的独立守卫。

### RF-02【任务定义调整】"能力缺失"应以聚合系统告警进入用户视野

- **假设**：Sina 服务期间产出一条聚合系统告警（"放量规则当前不可评估：
  缺 turnover，影响 N 只"），用户对**漏报**的感知显著优于现在的"只写进
  status 的 observation 字段"。
- **证伪条件**：若 soak 中出现频率 > 1 次/小时，或该告警在通知通道上
  挤掉真实异动告警，则说明它降低信噪比、应退回 status-only。
- **性质**：这是**任务定义**问题 —— 系统当前承诺"报异动"，未承诺
  "报自身能力缺陷"。本轮只把事实做进 status，尚未决定是否进通知流。

### RF-03【模型真正增量提升】准入拒绝率应作为质量因子

- **假设**：把 `future_rejected / out_of_order_rejected / coverage` 作为
  H 类质量因子输入模型，能提升真实数据上的 PR AUC。
- **证伪条件**：真实语料上加入后 PR AUC 相对 base 提升 < 0.005，
  或该因子在 family permutation 中重要性排名后 50%。
- **前提**：依赖真实多日语料，当前 `blocked`。本轮已让这三个量在
  `live_session` 报告中可用，为将来取证打好基础。
