### B1〔**已确认错误**〕冷启动时 `universe_transport` **诬告 provider**
*（我原 §4 表格把该项判为「确认已修复」—— 这是本次更正的核心）*

`src/arad/engine.py:975` 恒写 `"transport_complete": bool(transport_complete)`，
回退链 `:938-940` 落到 `_universe_meta_of()` 的 `info.setdefault("complete", True)`（`:1125`）。
未刷新过（冷启动 / 钉池 / 回放）时 `_universe_meta == {}` → `meta.get("transport_complete")`
与 `meta.get("complete")` **都是 `None`** → `bool(None) = False`。

我的实测（真实 `Engine.universe_truth()` + 真实 `evaluate_health`）：

```text

  transport_complete = False     active_scan_codes = 0   attempt_status = ''
verdict: healthy=False exit=1 fail=['universe_transport']

         —— 这是**不需要分母**就能确定的硬事实；此期间'没有告警'不能解释为'没有异动'
```

**provider 什么都没声明。** 这是把「我没测」渲染成「我测出你坏了」，并且**归罪于数据源** ——
正是本次要修的「把不知道当没问题」的**镜像**：把不知道当成了**有罪**。
退出码 1 + fail 项会把排障指向 provider。

即：**本该接住冷启动的那条分支永远不会触发，而触发的是诬告分支。**

## §E 本轮方法学教训（已并入硬规则）

1. **(ppp) 延伸**：仅验证「机制存在」**不等于**「缺陷已修」。一个修复声明的验收必须覆盖
   **①边界可达性 ②出口完整性（含异常出口）③新引入的镜像错误**。
   我原 §4 三项都只验了①的一半。
2. **(jjj) 延伸**：数 `return` 语句**不能**枚举出口 —— **异常出口不是 `return`**。
3. **(eee) 再次成立**：一条对抗性审计线**可以**推翻已发布的主 agent 结论。
   本次它是**对的**，我更正。
4. **镜像错误是独立缺陷**：修「把不知道当没问题」时，很容易引入
   「把不知道当有罪并归罪于数据源」。两者都源于**三态被压成两态**。
