# 4. `R-12 / IT-P1-UNIVERSE-DENOMINATOR-001`：绝对只数门禁无法证明全市场覆盖

当前 `tools/live_session.py` 的 Universe health gate 只有绝对阈值：

```python
UNIVERSE_MIN_ABS  = 3000
UNIVERSE_WARN_ABS = 4500
```

语义：

```text
watchlist fallback -> FAIL
active < 3000      -> FAIL
active < 4500      -> WARN
active >= 4500     -> OK
```

这比“完全不看股票池”已经好很多，但它依然回答不了：

```text
4500 / ? = ?
```

而 Eastmoney `universe()` 当前其实已经计算并保存：

```text
transport_expected_total
raw_unique_codes
usable_quotes
transport_complete
usable_coverage
shortfall
```

Engine 也把采用结果的 meta 放进 `self._universe_meta`。

真正断点是：

> `_universe_meta` 没有成为 Store / live-session / research manifest 的事实来源；`evaluate_health` 只读 active count。

## 本轮优先实验：`EXP-IT-UNIVERSE-TRUTH-002`

这是 deterministic mechanism，不是实盘覆盖率。

固定同一个 current gate，改变 provider 声明的 denominator：

| 场景 | expected | active | active coverage | 当前绝对 gate |
|---|---:|---:|---:|---|
| 4100 / 4200 | 4200 | 4100 | 97.62% | WARN |
| 4100 / 5913 | 5913 | 4100 | 69.34% | WARN |
| **4500 / 5913** | 5913 | 4500 | **76.10%** | **OK** |
| **4600 / 5913** | 5913 | 4600 | **77.79%** | **OK** |
| 5850 / 5913 | 5913 | 5850 | 98.93% | OK |

关键结论不是“5913 是今天真实全市场总数”——本轮没有做真实网络测量。

关键结论是：

> **只要 numeric denominator 已知，绝对 gate 仍然可以把约 76–78% 的 active coverage 判成 OK。**

它也无法区分：
- 4100 / 4200（接近完整）
- 4100 / 5913（严重缺口）

因为两个输入在当前 health 层都只是 `universe_size=4100`。

这已经足够证明 R-12 不是“阈值再调一下”的问题，而是**分母缺失**。

本轮结果：`universe_denominator_gate_matrix.csv`。

# 5. 新 P1：`IT-P1-UNIVERSE-MEMBERSHIP-QUALITY-001`

当前 Eastmoney 已经正确把：

```text
transport_complete
```

和：

```text
usable_coverage
```

拆开。

这是上一阶段的重要修复：停牌/无效价格行不应该让“服务端 transport 不完整”。

但是 Engine 的 active membership 仍然是：

```text
Eastmoney universe()
→ 返回 parsed usable Quote 列表
→ Engine _record_universe(quotes)
→ _extract_codes(quotes)
→ active _codes
```

也就是说：

```text
raw transport 代码集合
```

和：

```text
当前可解析 Quote 集合
```

虽然在 metadata 里拆开了，但**在 active membership 上又重新合并了**。

代码自身允许这种情况：

```text
expected_total       = 5913
raw_unique_codes     = 5913
transport_complete   = True
usable_quotes        = 4600
```

此时 transport 的确完整，但 Engine 从 4600 个 Quote 对象提取 active codes。

当前绝对 gate：

```text
4600 >= 4500
→ universe = OK
```

而 membership coverage 在该 fixture 中只有：

```text
4600 / 5913 = 77.79%
```

这说明：

> **Universe membership 不应该由当前行情是否可用来定义。**

新浪 `parse_universe()` 自己已经采用了相反且更合理的策略：即使停牌/无成交，也保留 code，注释明确写着“否则复牌当天完全收不到信号”。

因此建议正式拆：

```text
UniverseMember(code, name, board, list_date, ...)
QuoteAvailability
```

或至少让 Eastmoney universe 把 raw transport code list 单独交给 Engine，用它定义 active scan；`usable_quotes` 只做诊断/预热，不再决定市场成员资格。

本轮没有声称“真实市场现在缺了多少停牌股”；这是固定软件机制。

结果：`universe_membership_quality_matrix.csv`。

但这个新分支是“手写的一套简化账”，没有复用正常路径的 dispatch/accounting 语义，因此出现三个残留。

默认配置：

```text

rules.spirit_index.enabled = false
```

所以 `_fetch_indices()` 实际不会 dispatch index request。

但是 zero-return 分支当前仍写：

```python
requested = len(self._codes) + len(self.index_codes)
index_requested = len(self.index_codes)
```

固定：

```text
stock 实际 dispatch = 500
index 实际 dispatch = 0
provider stock 返回 = 0
```

```text
actual requested        = 500
reported requested      = 505
reported index_requested= 5   <- phantom
returned                = 0
unknown_missing         = 0
```

而且该 early return 在 `_poll_count += 1` 之前，因此连续 6 个 empty observation 可以得到：

```text
observation_seq:
101, 102, 103, 104, 105, 106

store_poll_count:
41, 41, 41, 41, 41, 41

observation_poll_count:
41, 41, 41, 41, 41, 41
```

```text

→ requested
→ missing/rejected
→ poll identity
```


# 8. 主改造：`Universe Truth Contract v3`

上一版 UniverseTruth 只强调 expected/active 与 recovery state；本轮把最关键的一层补上：

## 8.1 denominator provenance

```text
denominator_kind:
  provider_declared_total
  pagination_exhausted_non_numeric
  unknown
```

Eastmoney 可以给 numeric total：

```text
expected_total = provider total
```

新浪 clean pagination 可以证明：

```text
source enumeration completed
```

但没有 numeric total：

```text
expected_total = None
```

二者不能硬塞成同一种 coverage。

## 8.2 membership 与 quote usability 分开

```text
transport_codes
    = universe transport 层发现的代码成员

usable_quotes
    = 此刻能构造有效行情 Quote 的成员

active_scan_codes
    = 引擎实际安排 snapshot polling 的成员
```

必须禁止：

```text
active membership = usable quote count
```

这种静默等价。

## 8.3 四种 coverage

当 numeric denominator 存在时：

```text
C_transport = raw_unique_codes / expected_total
C_usable    = usable_quotes / expected_total
C_active    = active_scan_codes / expected_total
C_round     = round_returned / round_requested
```

语义分别是：

```text
服务端 transport 是否给全
当前 universe 行里多少可直接变 Quote
系统到底准备扫描多少市场成员
已经准备扫描的这些成员本轮回来多少
```

**`C_round` 永远不能替代 `C_active`。**

## 8.4 recovery clocks

继续冻结：

```text
last_attempt_at
last_applied_at
last_complete_at
```

smaller partial 被拒时：

```text
last_attempt_at   前进
last_applied_at   不变
last_complete_at  不变
active scan       不变
```

## 8.5 起始健康策略

仅作为候选起点，不是已认证最优：

```text
active_coverage < 90%  -> FAIL
90–95%                 -> WARN
>=95%                  -> OK

expected_total unknown
→ NOT_MEASURED
```

真实阈值必须等本地授权环境重新采集后再标定。

完整 schema：`universe_truth_contract_v3.json`。
