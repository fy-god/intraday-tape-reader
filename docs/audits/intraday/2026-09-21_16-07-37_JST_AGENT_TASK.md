## WP01 — 独立 Delivery Ledger v2【P1，第一优先】

### 现状红点

当前 7 条可发 Alert 的规则中：

```text
volume_burst      signal_id + evaluability ✓
spirit_order      signal_id + evaluability ✓
limit_board       ✗
spirit_index      ✗
spirit_price      ✗
tick_surge        ✗
unusual           ✗
```

最新本地真实 replay：66 committed / 6 tagged / 60 untagged。

### 先写三个红测

1. `test_all_first_party_committed_alerts_have_signal_id`
   - 跑 deterministic replay；
   - 当前必须 RED：untagged > 0；
   - 修后要求 0。

2. `test_signal_id_only_does_not_satisfy_delivery_contract`
   - 对一个没有 SignalEvalStats 的 fake/built-in signal 设置 signal_id；
   - 当前 `_mark_stage` 仍不记 committed；
   - 这个测试用于证明旧方案不足，修后应由独立 delivery ledger 通过，而不是自动造 EvalStats。

3. `test_delivery_does_not_create_ghost_evaluability_rows`
   - 未 instrument evaluability 的 signal 产生并 commit Alert；
   - delivery 必须有值；
   - `signal_evals` 不得凭空出现 considered=0 的幽灵行。

### 实现

建议新增 `SignalDeliveryStats`（可放 `capabilities.py`，更推荐独立小模块后由 RoundObservationSet 聚合）：

```text
rule_selected
global_ignored
bus_accepted
committed
```

Engine 是 delivery 唯一所有者：

```text
rule.evaluate 返回 valid Alert -> rule_selected
ignore -> global_ignored
bus.accept True -> bus_accepted
store.add_alert -> committed
```

不得再用 `sig in observation.signal_evals` 作为 delivery 门禁。

### signal_id 映射

由规则自己填写稳定机器 ID：

```text
limit_board.limit_up_seal / limit_down_seal / limit_up_touch / ...
spirit_index.index_pull / index_press
spirit_price.rocket / rebound / dive / accel_down
unusual.<pattern>
tick_surge.surge / tick_surge.plunge
```

以现有 `metrics.pattern` 为语义依据，但在规则构造 Alert 时显式写入；不要在 Engine 解析 title。

### 迁移交叉检查

`volume_burst / spirit_order` 暂时保留现有 EvalStats.delivery 字段，但必须新增：

```text
EvalStats.rule_selected == DeliveryStats.rule_selected
EvalStats.bus_accepted == DeliveryStats.bus_accepted
EvalStats.committed == DeliveryStats.committed
```

若不一致直接测试失败。稳定后再决定是否移除重复字段。

### 完成标准

真实 replay / selftest 同链：

```text
first_party_committed_total == committed_with_signal_id
Σ DeliveryStats.committed == first_party_committed_total
untagged_first_party == 0
DeliveryStats invariants == 0 violations
EvalStats ghost rows == 0
```

### 回退验牙

只回退 WP01 产品实现，保持新增测试：

- untagged coverage 测试必须重新 RED；
- signal_id-only negative test 必须证明旧 guard 不能覆盖；
- 禁止用 ImportError/字段不存在作为唯一红牙。

回传：`delivery_coverage_reconcile.json`、`eval_delivery_crosscheck.json`、red/green/rollback logs、diff hash。

## WP02 — Universe Coverage Gate【P1，可并行】

最新本地历史真实扫描曾出现 73.0% / 83.1% universe coverage。不要把它当本轮实时值，但必须把这种状态产品化成 `degraded`。

### 实现

让 status/once/soak/research manifest 同时带：

```text
transport_expected_total
transport_received_unique
usable_codes
active_scan_codes
transport_complete
usable_coverage
active_coverage
coverage_status
source/reason
```

### 测试

- expected=5900，active=4300 -> degraded；
- full transport 但停牌使 usable<expected -> transport_complete 仍 true；
- 旧完整池存在，新 partial 更小 -> 保留旧池，同时 status 明确 refresh degraded；
- 初次启动只有 partial -> 可继续扫描，但顶部必须明显 degraded，不能装成全市场。

真实网络可用时再执行一次授权只读扫描；不可用就明确 `not_run_network`。

## WP03 — Stable event_id【依赖 WP01】

在 committed 边界生成 durable event ID。要求：

```text
同一 committed event：Store/JSON/SSE/notifier/future label ID 不变
不同 committed events：ID 不重复
```

不要复用含时间桶的 `key` / `cooldown_key`。

输出 `event_identity.json`。

## WP04 — Typed NotificationResult【依赖 WP03】

把 bool 终态拆成：

```text
sent

skipped_severity

legacy_true_unknown
```
