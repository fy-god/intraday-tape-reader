## 2. 更锐利的机制：是**接线漏了**，不是**没有机制**

### 2.1 逐函数计数（`tools/live_session.py`）

我把每个顶层函数里**新**交付账本词元（`delivery_committed_total` / `delivery_accounting_session` / `accounting_status` / `signal_delivery` / `signed_ratio` / `inconsistent_rounds` / `accounting_errors` / `delivery_committed_signals`）与**旧**可评估性账本词元（`evaluability_*` / `signal_evaluability`）分别计数：

```text
function                             line   NEW  OLD   role
make_round_sample                     204     2    3   PRODUCER
summarize_rounds                      359    19   13   PRODUCER
empty_metrics                         872    12    7   PRODUCER
evaluate_health                       985     0    4   VERDICT      <== 读旧不读新
_fmt_observation_summary             1741     0    6   PRINTER      <== 打印旧不打印新
_print_summary                       2209     0    0   PRINTER
build_report                         1342     0    0   REPORT
```

**新账本只出现在 3 个生产者里。四个权威层（判决 1 + 打印 2 + 报告 1）对新账本的引用全部为 0。**

### 2.2 判决层**本来就会**消费账本 —— 它只是读的是旧那本

`evaluate_health` 里有一段**完整的、带三级严重度的账本消费逻辑**（`:1176-1243`）：

```text
1179|  sig_ev = m.get("signal_evaluability")                     <== 旧账本
1200|  considered_total = _safe_int(m.get("evaluability_considered_total"))
1201|  evaluable_total  = _safe_int(m.get("evaluability_evaluable_total"))
1202|  blocked_total    = _safe_int(m.get("evaluability_blocked_total"))
...
1209|  if all_blocked: cap_level = "fail"        # 唯一站得住的"整类没评估"证据
1211|  elif (ev_warn_cov is not None and worst_sig and worst_sig[0][0] < ev_warn_cov):
1214|      cap_level = "warn"
1219|  if cap_level == "fail" and considered_total < min_samples: cap_level = "warn"
...
1243|  add("capability", cap_level != "fail", detail, level=cap_level)
```

也就是说：**判决层知道怎么读账本、怎么按严重度分层、怎么把它变成一项 fail。** 它甚至已经为旧账本产出了 `checks` 里的 `capability` 项。新账本只是**没有被接到这段逻辑上**。

**⇒ 这把结论从"缺少消费者"精确化为"接线遗漏"**：不是设计上不打算判定，而是加账本的那次提交**只更新了生产者，没有更新任何一个读旧账本的消费者**。同一模式也出现在**人看的打印层**：`_fmt_observation_summary`（`:1741-1782`）打印 6 处旧 `evaluability_*`，0 处新 `delivery_*`。

### 2.3 连"接线模板 + 扩展点"都是现成的

- `add()`（`:1031-1034`）的签名是 `add(name, ok, detail, *, level=None)`，**已经支持 `level=` 三级**（`ok`/`warn`/`fail`），并且注释明说"``ok`` 保持布尔（既有消费方不变）"。
- `capability` 项在 `:1243` / `:1245` / `:1269` 三处以 `add("capability", ...)` 注册；所有 `add(...)` 调用点里**没有任何一处**钉住 `checks` 的数量或名字集合。
- 我实测确认：`git grep -E "len\(.*checks|== \[." -- tests/*.py` 命中 **0** ⇒ 增加第 11 项检查**不会**撞上任何"检查项必须恰好 10 个"的断言。
