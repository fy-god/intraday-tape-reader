## 3. `IT-P1-MARKET-RULE-20260706-001`：当前默认规则已经落后于现行交易制度

### 固定源码证据

`src/arad/models.py` 当前仍定义：

```python
ST_LIMIT_RATE = 0.05

def limit_rate_of(code, name=""):
    ...
    if b in (Board.MAIN, Board.OTHER) and "ST" in name.upper():
        return ST_LIMIT_RATE
```

`limit_board.py` 的模块说明也仍写“ST 主板 5%”，并把 `Quote.limit_up_price / limit_down_price` 作为状态机唯一限价入口。

### 官方当前规则

上交所 2026 修订交易规则已自 **2026-07-06** 生效；上交所官方修订说明明确把主板风险警示股票涨跌幅限制从 5% 调到 **10%**。深交所 2026 风险警示板指南同样自 2026-07-06 起实施；深市 2026-07 的 ST 个股公告已直接写“日涨跌幅限制仍为 10%”。

因此在本轮审计日期，代码里“主板 ST 固定 5%”已不是现行制度。

### 为什么不是只改一个常量

腾讯 parser 会读取 idx47/48 的真实 `limit_up/limit_down`，有显式限价时 `Quote.limit_up_price` 优先使用 provider 值，因此腾讯主通道**可能被真实字段救回来**。

但 Sina parser 明确：

```python
limit_up = 0.0
limit_down = 0.0
```

并注释“由 `Quote.limit_up_price` 推算”。

所以主源故障切到 Sina 后，主板 ST 的限价会直接走这条过期 5% fallback。

固定反例：

```text
prev_close = 10.00
代码 fallback（5%）: limit_up = 10.50
现行规则（10%）:     limit_up = 11.00
```

价格刚到 10.50 时，代码可以把它当“在涨停价”，而现行制度下这只是一笔 +5% 普通价格。由此可能出现提前假“触板/封板”、随后假“炸板”，并污染后续真正 +10% 时的状态机。

本轮 arithmetic probe 已落盘 `st_limit_20260706_probe.json`。这不是实时 ST 股票抓取，但规则日期与代码常量的矛盾是确定事实。

### 正确修法

不能把 `ST_LIMIT_RATE` 从 0.05 粗暴永久改成 0.10，因为历史回放 2026-07-06 之前仍应是 5%。

需要日期感知的市场规则合同：

```text
trade_date < 2026-07-06:
    沪深主板 ST/*ST = ±5%

trade_date >= 2026-07-06:
    沪深主板 ST/*ST = ±10%

STAR/GEM:
    按其板块规则，不因为名称含 ST 就套主板特殊比例

provider 给出明确 limit_up/down:
    优先使用 provider 明确值，同时可审计其与本地规则是否一致
```

决策日期必须来自 `ctx.now.date()` / 回放时钟，而不是 `date.today()`。

### 回归矩阵

至少新增：
- SH 主板 `*ST`：2026-07-03 → 5%，2026-07-06 → 10%；
- SZ 主板 `ST`：同边界；
- 创业板/科创板风险警示不误套主板特例；
- N/C 新股前 5 日仍无限制；
- provider 显式限价优先；
- Sina `limit_up/down=0` 走日期感知 fallback；
- 回放固定 2026-06 与 2026-09，结果不受运行当天影响。

## 4. `IT-P1-EVAL-PUBLISH-001`：`published` 不是系统真的发布

### 当前调用顺序

`volume_burst` 在自己的 `max_per_round` 截断后立即 `mark_published(signal, code)`；`spirit_order` 同样在规则内部截断后写 `mark_published`。

但 Engine 拿到规则返回值后还会继续：

```text
ignore
→ AlertBus.accept（key 去重 + cooldown）
→ fresh
→ store.add_alert
→ notifier dispatch
```

所以当前账本把 `rule_selected` 错命名成 `published`。

### 本轮机制复现

构造同一只票每 5 秒都满足 `volume_burst`，cooldown=600 秒，共 24 轮：

```text
rule-level published = 24
AlertBus 真正接受    = 1
实际可 commit        = 1
```

overcount factor = **24×**。

这只是刻意机制反例，不是线上重复率，但证明字段语义不成立。

### 为什么现在必须修

当前 `NEXT_STEPS` 已把“用 T+5/T+30 事后收益量化告警质量”提为 P0。若以后拿 `signal_evaluability.published` 当标签分母，会把根本没有进入 Store/通知链的 cooldown/dedupe 候选也当作已发布事件。

### 正确分层

```text
hit_candidate
→ rule_selected
→ bus_accepted
→ committed
→ notify_attempted
→ notify_sent
→ client_received/applied
```

当前 `published` 要么兼容期改名为 `rule_selected`，要么只在 Engine `bus.accept + store.add_alert` 后记录真正 committed。Alert 应带稳定 `signal_id`，不要让 Engine 靠 title 文案猜所属 signal。

## 5. `IT-P1-CAPABILITY-002-R1`：逐 source capability 已有，但逐 Quote 实际可用性仍会漏分母

当前 `RuleContext.provides(key)` 仍只看整轮 `SourceCapabilities`。

在 `spirit_order` 中，若当前 source 声明 `depth_l5=True`，`capability_gaps()` 不会把 big-wall pattern 记 blocked；但对某一条具体 Quote，代码又要求 `q.has_depth` 才把它加入 evaluated。

如果该 source 理论支持 L5，但某条响应五档实际缺失：
- 不 blocked；
- 不 evaluated；
- 没有 per-code quality reason；
- 该 code 直接从 considered denominator 消失。

这与未来 mixed-source 同源。实现 targeted fallback 前必须先有：

```text
(route, code)
→ source
→ source_epoch
→ advertised capabilities
→ observed field availability
```

规则应能查询 `ctx.provides(code, "depth_l5")` 或等价 sidecar。

## 6. `IT-P1-SOURCE-EMPTY-001`：soft-partial 仍未修

`SourceManager.call()` 仍然只在异常时 fallback。请求 `[A,B]`、主源 HTTP 正常但只返回 `[A]` 时，不触发 B 的补抓。

本轮不建议直接混源修，因为 per-code provenance/capability 还没落地。正确顺序：

```text
requested-vs-provider_objects
→ per-code provenance/capability
→ unknown_missing
→ 只补 unknown_missing
→ merged current view
```

停牌/explicit unavailable/quality reject 不能无限 fallback。

## 7. 其它真实残留

### 次新股第 6~10 日

配置 `filters.min_list_days=11`，但 Tencent 快照没有 `list_date`；N/C 名称只能覆盖前 5 日。第 6 日起名称前缀消失，因此第 6~10 日缺精确上市日过滤。

## 8. `IT-P2-DAEMON-HEALTH-001`

当前 `_detach_and_return()` 先 Popen 新 daemon，再轮询：

```text
if _healthy(port): success
if child dead: break
```

但单实例/端口占用检查在新 child 的 `run()` 内。

固定场景：8899 已有健康 arad 服务，再运行 `--detach`；新 child 因已有实例退出，但 parent 可先被旧服务的 `/api/status=200` 满足，从而把旧服务误认作新 PID 的启动成功。

修法：parent Popen 前先做 singleton/port preflight；spawn 后健康检查必须绑定新 daemon PID/state identity，而不是只看端口 200。POSIX 未实现 detach 时也不应打印 Windows 等价成功承诺。

## 10. 优先研究实验：`EXP-IT-QUAL-001` — post-alert matched-control 质量代理

当前项目已经能真实全市场跑出告警，但没有真值。继续调模型而没有稳定 label，只会优化未知目标。

### 冻结定义

对每个真实 **committed alert event**：

```text
event = code + signal_id + direction + clustered event time

signed_return_h
= direction × (P[t+h] / P[t] - 1)

h ∈ {5min, 30min}
known_at = t+h
```

主报告用连续 signed return；二值 `continuation_h = 1[signed_return_h > 0]` 只作辅助。随访不足、停牌、跨会话、路径缺失 → unknown，不当负例。

### 匹配负控制

至少匹配同 symbol、同交易日/日内时段、同方向分布，排除 alert 邻域，选择 control 时不能读取未来收益。统计按交易日 + symbol/event cluster bootstrap，不做逐行 IID。

### 本轮软件 smoke

本轮生成 20 synthetic symbols × 5 artificial days、300 个 synthetic alerts，在 60% 人工事件后注入同向 drift，用来验证 labeler 软件链而不是验证市场 alpha。

流水线能正确产出 T+5/T+30、`known_at`、matched controls 与 unknown 结构。**这些 synthetic 数字没有任何实盘意义，不进入策略成绩。**

产物：
- `post_alert_label_spec.json`
- `post_alert_labeler_smoke.json`
- `post_alert_labeler_smoke_rows.csv`

### 真实实验淘汰条件

若真实事件在至少 3 个独立交易日/时间块上，T+5/T+30 signed-return 相对 matched controls 无稳定正增量，或效应只来自单一天/单一股票，或控制市场方向后消失，则该 signal 不应因“告警很多”而开放。

## 11. 主改造：Alert Truth Contract v1

把此前 Observation Truth Contract 延伸到真正的告警交付：

```text
provider response
→ admitted_current
→ MarketRuleContext(trade_date, board, special_status)
→ signal evaluability
→ hit_candidate
→ rule_selected
→ AlertBus accepted
→ Store committed
→ notifier sent
→ client received/applied
→ future label known_at
```

### 目标
- 当前交易制度按日期可重放；
- 规则 hit 与真实可见 alert 分开；
- 未来收益标签只挂真实 committed event；
- capability/quality/soft-partial 仍从同一 provenance 派生。

### 非目标
- 不把 T+5 收益叫交易收益；
- 不自动打开 spirit rules；
- 不在本轮扩 TCN/Transformer；
- 不为了模型训练放宽数据质量 gate。

建议 schema：

```text
AlertEvent:
  event_id
  signal_id
  code
  direction
  decision_ts
  trade_date
  source/source_epoch
  rule_selected_at
  bus_accepted_at?
  committed_at?
  notify_status
  price_at_decision
  market_rule_version
  provenance_hash

ForwardLabel:
  event_id
  horizon
  known_at
  reference_price
  future_price
  signed_return
  market_adjusted_return?
  status = known | unknown
  unknown_reason
```

### WP04 — Per-code provenance/capability
`(route,code) -> source/source_epoch/advertised caps/observed fields`。解决 source-level capability 与单条 Quote 字段缺失不一致。

### WP05 — Soft-partial targeted fallback
依赖 WP04。requested/returned 对账，只补 `unknown_missing`，保留 per-code provenance。

### WP06 — Listing-date cache
解决 Tencent 链路第 6~10 日新股过滤。来源可追溯，未知上市日不伪造。

### WP07 — ObservationInterval
同值新鲜快照延长 `last_observed_at`，断线不延长，source epoch 切段。

### WP08 — SSE durable delivery / bounded state
推进 committed→sent→received→applied；队列满要有 gap/cursor，不静默 drop-oldest。

### WP09 — Daemon attribution + platform contract
detach 前 preflight；健康检查绑定新 PID/state identity；POSIX 未实现真正 detach 时不作 Windows 等价承诺。

### WP10 — 真实数据模型认证
