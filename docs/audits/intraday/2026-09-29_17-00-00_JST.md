### 1.1 `IT-P1-SINA-INDEX-QUOTE-ID-COLLIDES-WITH-STOCK-013`【确认 · 已修】

**文件/函数/行号**：`src/arad/sources/sina.py` · `parse_response()` · 原 `:189`

```python
code = m.group(1)[2:]  # 正则已保证 [a-z]{2}\d{6}，去掉 sh/sz/bj 前缀
```

**触发条件**：指数路由请求 `sh000001`（上证指数），provider 正确返回
`hq_str_sh000001=...`。

**机制（四步链）**：

| 步 | 位置 | 事实 | 状态 |
|---|---|---|---|
| 1 | caller `engine.index_codes` | `["sh000001", ...]` 带前缀 | ✅ |
| 2 | `_wire_symbols()` → HTTP | 发 `list=sh000001` | ✅ 上轮 `9670dd9` 已修 |
| 3 | `parse_response()` `:189` | `Quote.code = "000001"`（**剥掉前缀**） | ❌ **本轮缺陷** |
| 4 | `EngineState.update()` `:269` | `self.quotes["000001"] = q` | ❌ 撞平安银行 |

`sz000001`（平安银行）剥前缀后**同样是** `000001`。于是上证指数与平安银行
共用 `EngineState` 的 `quotes` / `history` / `first_seen` / `last_price` /
`day_open` 五个 map 的**同一个键**。

**本地实测**（`r13_sina_quote_id_diag.py`，真实产品代码）：

```
A. parse_response(bulk_body(["sh000001"]))
     Quote.code = '000001'   board = Board.MAIN   name = '股票000001'
C. 是否撞 key: True          # 上证指数与平安银行同键
D. 默认 5 个 index_codes -> Quote.code 全部被压成裸码
```

**影响（为什么这是 P1 而不只是"少一只"）**：

1. **互相覆盖**：指数样本会顶掉平安银行的价格/开盘点/首见标记，反之亦然。
   两条数据流在 state 里被合并成一条，且**不可观测**（key 相同，无法分辨谁写的）。
2. **指数类信号永不触发**：`rules/spirit_index.is_index_quote(q)` 的判据是
   `q.board is Board.INDEX` 或 `looks_like_index(q.code, q.name)`。指数被压成
   裸码后 `board = board_of("000001", "股票000001") = Board.MAIN`，
   名称为"股票000001"不含"指数" → **判成个股**。即使指数抓得完全正确，
   `spirit_index` 也一条都不会报。
3. **假信号反向可达**：`SpiritIndex` 按 `q.code` 读窗口。预载平安银行
   5 分钟历史后再进第一条指数样本，指数会**继承股票的整段历史**，
   从而算出"从 11 元到 3900 元"的跨证券涨幅 —— 一个**确定性的**假拉升。

当前 `spirit_index.enabled=false`（默认），故线上**未被触发**，
定级 **latent P1 / production-reachable-when-enabled**，与云端定级一致。

**与腾讯的合同冲突**：`tencent.parse_response()` `:328` 早已
`out_code = symbol if is_index else code`。同一证券在两条链路上身份键不同 ——
而新浪是**默认兜底源**（`sources.fallback: ["sina"]`）。后果：**"腾讯挂了"
这一个事实会让指数的账本键从 `sh000001` 变成 `000001`**，样本标签随
"当时谁在供数"漂移且不可观测。这是本仓库 bug 类 (g)
「同一语义在两个时点/两个轴上分别推断」的又一例。

**修复**：`src/arad/sources/sina.py`

- 新增 `_identity_key(symbol, index_codes) -> str`：**唯一**身份函数。
  调用方显式声明 → 保留带前缀；否则符号自带前缀且
  `looks_like_index(sym, "", bare)` 为真 → 保留带前缀；否则裸码。
  **名称不参与身份判定**（请求侧拿不到名称；一旦某一侧能用名称，
  两轴就永远不可能对齐 —— 腾讯 `is_index_role` 返工两次的教训）。
- `parse_response(text, seq=0, index_codes=None)`：`out_code = _identity_key(...)`，
  `board = Board.INDEX if is_index else board_of(code, name)`。
- `_fetch_bulk(codes, seq, index_codes)`：过滤键改用 `_identity_key`。
  原过滤键是裸码，与新的 `Quote.code` **不同域**，不改就会把刚修好的
  前缀又滤掉（`RB-WP03-filter-domain` 牙齿专钉此点）。
- `snapshots()` 的兜底去重同样换成 `_identity_key`（wire / 过滤键 /
  `Quote.code` 三者同域）。
- `SinaSource.index_codes` 类属性（caller-owned role）+ 引擎
  `_publish_index_role()` 在 `_load_index_codes()` 后把角色推给链上每个源。

**验收测试**：`tests/test_sina_index_quote_identity.py`（17 条）
- `test_index_quote_code_keeps_exchange_prefix` — `sh000001`
- `test_index_quote_board_is_index` — `Board.INDEX`
- `test_stock_quote_code_stays_bare` / `test_sh600000_stays_bare_stock`
  **阳性对照**：带前缀的**个股**必须仍是裸码（防"有前缀=指数"误判）
- `test_index_and_stock_do_not_collide` — 两键必须不同
- `test_all_default_index_codes_keep_prefix` — 5/5

## 7. 研究想法（区分三类）

**I1【程序修复·可证伪】** 把 `_identity_key` 升格为**跨源共享**的单一判据
（现为 Sina 私有）。**证伪条件**：新增第三源（如东财）时若各自再写一份
身份函数，则"同一证券跨源身份一致"会在第 N 源上再次失效 ——
这正是本项目第 5 次同型缺陷。**度量**：跨源身份一致性用例通过率（当前 7/7）。

**I2【任务定义调整·可证伪】** 现有验收全部是"单元级确定性证据"
（给定 fixture → 断言身份）。但用户要的是**盘中真实预警**。
**调整**：把"同一指数在 09:30–15:00 连续会话中与平安银行全程分账"
列为验收项，需要真实 tick。**证伪条件**：若真实会话中出现任一轮
`state.quotes` 里 `000001` 被指数写入，则单元级证据不充分。
