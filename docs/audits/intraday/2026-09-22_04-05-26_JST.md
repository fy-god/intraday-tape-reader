# 2. 本轮最高优先新问题：`IT-P1-OBS-EMPTY-ROUND-001`

**级别：P1 · 已确认 · 未修**

### 2.1 固定 SHA 控制流

当前 `Engine.poll_once()` 的主链：

```text
_maybe_refresh_universe()
→ stocks snapshots
→ index snapshots

if not quotes and not idx_quotes:
    return []
```

这个 `return []` 出现在：
- `RoundObservationSet(...)` 创建之前；
- `_poll_count += 1` 之前；
- `store.set_poll_stats(... observation=observation)` 之前。

因此只要 provider：

```text
请求确实发出
HTTP/解析层没有抛异常
但返回 []
```

本轮就不会产生新的 observation ledger。

`AlertStore.set_poll_stats()` 只有真的收到 `observation` 时才推进：

```text
_observation
_observation_seq
_observation_observed_at
_observation_poll_count
```

所以 silent-empty round 的实际语义是：

```text
网络请求发生了
→ 返回 0 行
→ 没有 exception
→ observation_seq 不增长
→ coverage 不产生
→ poll_count 的正常结束路径也没执行
```

这与“休市没有发请求”不是同一件事，却在账本上都表现成“本轮没有 observation”。

### 2.2 为什么这是上一云端“静默断供假绿”的上游根因

最新云端审计已经真实复现：

```text
provider 每轮返回 []
error_rounds=0

但 live_session 的 sample['quotes']
仍等于旧 state.quotes 缓存 5913

6 轮后：
no_data_rounds = 0
quotes.max     = 5913
healthy        = True
exit           = 0
fail           = []
```

本轮进一步沿生产链确认：

> 不只是 `live_session` 写错了 `quotes`，更上游的 Engine 在 zero-return 时**根本不生成本轮 observation**。

所以如果只把：

```python
quotes=len(state.quotes)
```

替换成：

```python
quotes=obs_snapshot["returned"]
```

还不够。

因为 silent-empty round 当前根本没有 `obs_snapshot`。

# 4. 主改造：`Round Truth Contract v1`

目标不是再给 `live_session` 多加一个 if，而是冻结：

> **每一个真正 dispatch 的 poll attempt 必须拥有一个明确、可对账的终态。**

建议最少区分：

```text
not_dispatched_closed_or_idle
provider_exception
zero_return
returned_with_rejections
returned_admitted
```

### 4.1 不变量

```text
1. 只要 stock/index request 真的 dispatch，
   本轮就必须产生 observation 或 typed error outcome。

2. zero_return 且无 exception：
   requested > 0
   returned = 0
   coverage = 0
   observation_seq 必须推进。

3. live_session 的本轮 quotes
   必须来自本轮 returned/admitted，
   不能来自 state.quotes。

4. state.quotes 只能叫 latest cache，
   禁止用于 no-data / current-round health。

5. 休市/idle 未 dispatch
   不能被当成 zero_return。

6. poll attempt identity 在 zero_return 时也必须可追踪，
   不能出现“请求发生了但轮次身份没有推进”。
```

### 4.2 最小兼容修法

第一阶段不需要立刻重写整个 Engine。

可以先：

```text
stocks/index dispatch
→ 得到 raw lists
→ 在 zero-return early return 之前
   创建 RoundObservationSet
→ requested > 0
→ returned = 0
→ set_poll_stats(observation=...)
→ 再 return []
```

然后 `live_session._soak_loop()`：

```text
有本轮 observation：
    quotes = observation.returned
    latest_quote_cache_size = len(state.quotes)

无 observation 且本轮没有 dispatch：
    明确记 not_dispatched
```

不要通过“把 `state.quotes` 放进 prune”来解决，因为 latest cache 本身仍有展示/历史用途；问题是**消费方把 cache 当成 current truth**。

# 8. `IT-P2-ACK-RECENCY-001` 值得排进近端工程包

当前：

```python
self._acked.add(key)
if len(self._acked) > 5000:
    self._acked = set(list(self._acked)[-2000:])
```

`set` 没有插入顺序语义。

所以 `[-2000:]` 不是“最新 2000”，只是当前哈希遍历顺序中的任意 2000。

最新云端审计已经真实做了：
- 5001 个 ack；
- 5 个 `PYTHONHASHSEED`；
- 旧实现均不能保证保留最新 2000；
- 某些 seed 连最新 ack 都被丢；
- 用户可见效果是刚 ack 的行重新显示未 ack。

这项不影响信号算法，但直接影响告警运营可信度。

正确做法应换成有序 bounded structure，而不是继续在 `set` 上裁剪。

## 本轮最终判断

当前项目已经把很多“字段有没有”修到了“字段能改变判决”的层面，这是明显进步。

但最新的 silent-outage 说明还差一个更基础的不变量：

> **一轮请求只要真的发生，就必须留下本轮事实；不能因为返回 0 行，就让这一轮从 observation ledger 里消失。**

现在的错误链是：

```text
provider 返回 []
但不抛异常
→ Engine 在 observation 之前 return
→ observation_seq 不增长
→ live_session 看不到本轮账
→ 又用 state.quotes latest cache 充当本轮 quotes
→ fetch/data/coverage 全部可能绿
```

这不是单纯一个 `quotes` 字段写错，而是：

```text
Poll Attempt
→ Round Observation
```

之间存在一个洞。

因此下一阶段最优顺序是：

**Round Truth → Universe health/UniverseTruth → retry/recovery → per-code provenance → SSE/delivery → 真实标签 → 模型。**

在这个链条闭合以前，扩大模型搜索仍然只会优化一个“某些坏轮次甚至根本没被记录”的数据集。
