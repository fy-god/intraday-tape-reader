## §1 已确认错误（本轮新发现，均用**真实归档绿报告**做基线）

### 1.1 `IT-P1-UNIVERSE-T0-MEASURED-ZERO-READ-AS-MISSING-001`（**P1**）〔**已确认错误 · 未修**〕

- **文件/函数/行号**：
  - `tools/live_session.py:1755` `_u_size = _safe_int(_setup.get("universe_size"))`
  - `tools/live_session.py:1764-1767` `elif _u_size <= 0:` → `add("universe", True, "无股票池规模记录（旧报告/未采集），无法判定（跳过不算失败）", level="ok")`
  - 相关：`:1871-1880` t0 分母未知时 `universe_coverage` 落 `ok`（"无法计算"）
- **触发条件**：t0 的 `setup.universe_size == 0`（**明确测到 0 只**）**且** t0 分母未知
  （`expected_total=None` / `denominator_kind="unknown"`）。
- **机制**：`:1764` 把**测出来的 0** 与**没有记录**合并成同一支，
  文案直接写"**无股票池规模记录（旧报告/未采集）**" —— 这是**反向踩了本仓库自己的三态纪律
  「未知 != 0」**（同文件 `:478` 注释原文）。测到 0 是**最坏的事实**，却被渲染成"没数据、跳过"。
  当分母也未知时 `universe_coverage` 同样无法计算而落 ok，于是**没有任何判决项消费这个 0**。
- **影响（实测 · 真实归档绿报告 + 只替换 t0 快照）**：

  | 注入到真实绿报告的 t0 | `healthy` / `exit_code` / `fails` | `universe` 文案 |
  |---|---|---|
  | **基线（不改）** | True / 0 / `[]` | 「无股票池规模记录…无法判定」 |
  | `universe_size=0` + `active_scan_codes=0` + **分母已知**(6000) | **False / 1 / `['universe_coverage']`** | 「无股票池规模记录…无法判定」 |
  | `universe_size=0` + `active_scan_codes=0` + **分母未知** | **True / 0 / `[]`（全绿）** | 「无股票池规模记录…无法判定」 |

  ⇒ **一次明确什么都没扫的会话，只要分母拿不到，就能拿到 `healthy=True / exit_code=0`。**
  消费方只看 `healthy`/`exit_code` 时，它与"真扫了全市场"**不可区分**。
- **修复建议**：把 `universe_size` 的**缺失**与**实测 0** 分开（`_optional_int` 已存在，用它：
  `None` -> "无记录"、`0` -> 单独一条 `fail`"本轮测到扫描池 0 只"）。
  这与仓库既有纪律一致，不是新口径。
- **验收测试**（三条）：
  1. `universe_size=0` 且分母未知 -> **必须**判 fail（或至少不得全绿），文案不得说"无记录"；
  2. `universe_size=None`（真无记录）-> **仍必须**保持现在的"无法判定 / 跳过"（防假红）；
  3. 对照：`universe_size=5563` + 全 30 轮 full_market -> 必须保持绿。

### 1.2 `IT-P2-UNIVERSE-FULL-MARKET-IS-MAGNITUDE-BLIND-001`（**P2**）〔**已确认错误 · 未修**〕

- **文件/函数/行号**：`tools/live_session.py:541-545`
  `active = ut.get("active_scan_codes")` → `if has_active: return SCOPE_EMPTY_SCAN if float(active) <= 0 else SCOPE_FULL_MARKET`
- **机制**：`full_market` 的**全部判据**是"`active_scan_codes > 0`"，
  **从不与 `expected_total` 比较**。于是"只数远小于全市场"也会被贴成 `full_market`，
  再由 `:1737` 输出肯定句。**这是同一类的另一面**：P1 是"分母只数有证据的轮次"，
  这条是"分子只问是否非零" —— 两者都**只看存在性、不看覆盖度**。
- **影响（实测）**：

  | 轮样本（30 轮一致） | `universe_scope` | 其他判决 | 判定 |
  |---|---|---|---|
  | `active=400`（自选 100 只，非降级） | **ok**「全程全市场扫描，30/30 轮有明确扫描范围证据」 | `universe` **fail**（400 < 下限 3000）、`universe_coverage` **fail** 6.67% | 判决被别的项兜住，但**这句话是错的** |
  | `active=3000` + **分母未知** | **ok**「全程全市场扫描，30/30…」 | `universe` **warn**（3000 = 下限，偏小）、`coverage` ok（算不出） | **全绿方向上无拦截** |
  | `active=3001` + 分母未知 | **ok**「全程全市场扫描，30/30…」 | `universe` **warn** | 同上 |

  ⇒ 一个**只有全市场约一半**（3000/6000）的池子，会被写成"**全程全市场扫描**"，
  而绝对门禁只给 `warn`、`coverage` 因分母未知**算不出**。
  注意 30/30 轮**确实**都有扫描范围证据，所以这**不是** P1 的分母问题，是**判据本身不比较规模**。
- **修复建议**：`full_market` 应要求"有分母且 active/expected 达阈值"；
  分母未知时**不得**用 `full_market`，应落 `unknown` 或新增"范围存疑"态。
- **验收测试**：`active=3000 / expected=6000` 时 `universe_scope` **不得**出现"全程全市场扫描"；
  对照 `active=5900 / expected=6000` 必须仍为 `full_market`。
