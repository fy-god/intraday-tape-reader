## §0 本轮一句话

**我 17:00 轮修好的那层，在"证据合并边界"上又造出了两个新的假绿。**

一次 tri-state 修复确实解决了"把不知道当有罪"（假红），
但我**把判决改成了"会话优先"** —— 于是**后来的好消息开始抹掉先前的坏消息**：

```text
t0 transport_complete = False        <- provider 明确声明：本次股票池被截断
session 30 轮全测、0 轮不完整         <- 会话里确实没再看到截断
=> universe_transport = ok            <- 硬事实被盖掉
```

而且我**自己的负控制测试是"以错误的理由通过"的** ——
我把输入设成 `rounds_transport_measured=0`，
恰好**把被测分支绕过去了**：

```text
t0=False + rounds_transport_measured=0   -> fail   <-- 我的测试走的路径
t0=False + rounds_transport_measured=1   -> ok     <-- 一个单位就翻绿！
t0=False + rounds_transport_measured=30  -> ok
```

**这是"负控制的输入把被测分支绕过去了"的教科书案例。**
ADDENDUM2 §2 指认、我复算确认：**我加的负控制从未真正测过它要测的分支。**

**第二个新假绿：零证据被当成肯定证据。**

```text
_universe_session([]) -> measured=False, ratio=None, ever=False
=> universe_scope = ok  detail「会话期间未降级为仅自选股（全程全市场扫描）」
```

`finalize_metrics([])`（**一轮都没跑**）也输出同一句肯定句 —— 而同一份报告
的别处正 `fail=['rounds','data','api','sse','memory']`。

**第三个：会话内活跃覆盖下降无消费者。**

```text
t0: 5900/6000 = 98.33%  -> ok
会话: 4500/6000 = 75%   -> 被完全掩盖
```

`summarize_rounds` 算出的 `metrics['universe'].min=4500` **确实存在**，
但它**没有分母**，算不出覆盖率，也没有判决项读它 —— 又一个"算了没人读"。

**根因不是阈值，是"证据合并"没有合同。** 所以我这轮做的**不是补三个洞**，
而是立一份 **Session Universe Evidence Contract v1**：把 t0 与逐轮事实
变成一条 **evidence timeline**，并明确规定**谁在什么条件下能推翻谁**。

## §6 1–3 条有证据、可证伪的研究想法

### 想法 1〔**任务定义调整**〕：证据合并必须有**优先级合同**，而不只是"谁优先"
* **证据**：本轮 §1.2 与 §1.4 是**同一个结构性错误的两面** ——
  我 17:00 轮立的规矩是"**session measured facts > t0 snapshot**"
  （17:00 报告原文），这条规矩**方向是对的但不够**：

  | 情形 | "session 优先"会怎么判 | 正确判法 |
  |---|---|---|
  | session 正面 + t0 负面 | **ok（错）** | **fail**（窗口内出现过明确坏） |
  | session 负面 + t0 正面 | fail（对） | fail |
  | session 未测 + t0 负面 | fail（对） | fail |
  | session 未测 + t0 未测 | ok（对） | not measured |

  单调性要求：**在合并函数上，加入"明确坏"证据永远不能改善结论**
  （20:04 §7 的 288 个 monotonicity property checks 就是这个意思，
  0 violations —— 但那是**候选合同**的性质，**不是我已发布代码的性质**）。
* **做法**：把合并规则从"会话优先"改成**格（lattice）上的 join**：
  `fail ⊔ anything = fail`；`ok` 只在**所有有证据的来源都 ok** 时成立；
  `unknown` 是单位元。**explicit hard negative 是吸收元。**
* **可证伪预测**：若穷举 t0 × session 所有组合后发现"会话优先"
  与 join 语义**结论一致**，这条规矩无用。
  —— **反证不成立**：本轮实测 **7 个组合格判得更轻**
  （`t0=False + session all-true` 的全部分支）。
* **类别**：**任务定义调整**（改判决的合并语义，不改任何阈值）。

### 想法 2〔**程序修复**〕：零证据不得进入**任何**肯定句（生产者到消费者的全链）
* **证据**：§1.1 的形态是"生产者给了三态、消费者用两态"。更精确地说：
  生产者已经在**同一段代码里**写了正确的 `measured=False / ratio=None`，
  消费者**看见了这些字段却仍走肯定分支**。
  **"默认分支"成了"未测量落进去的肯定句"** —— 这是本轮第 3 次
  遇到"默认分支 = 假绿出口"。
* **做法**：凡是**肯定句**（"全程…"/"均为…"/"新鲜"/"完整"）都必须有一个
  **显式的 `_measured` 前置条件**，且默认分支输出**否定式**文案。
  可做成门禁：扫描所有 `add(..., True, ...)` 的 detail 文案，
  含肯定词但没有对应 `measured` 门控的 -> 报错。
* **可证伪预测**：若穷举所有肯定句后从未发现缺门控，这条规矩无用。
  —— **反证不成立**：本轮**当场抓到 2 条**
  （`universe_scope` 的 else、`universe_transport` 的 session positive）。
* **类别**：**程序修复**（可落地为门禁）。

### 想法 3〔**模型真正增量提升：无**〕
* 诚实声明：`程序修复` = §1.1–§1.5；
  `任务定义调整` = 想法 1（**已在代码里落地合并语义**）、想法 2；
