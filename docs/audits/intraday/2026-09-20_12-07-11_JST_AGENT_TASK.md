## 需要先关闭的三个问题

### A. `IT-P0-002-R2` — accepted watermark 不能等于 `history[-1][0]`

当前 `history` 只在价格/累计量变化时追加。新增显式 watermark，每次成功时间准入都推进；不要为了推进水位线把所有 flat tick 都塞入 history。

水位键至少预留：

```text
(code, source_epoch, time_role)
```

首先加当前源码必红测试：

```text
R1: t0   10.0 / 100
R2: t+60 10.0 / 100   # admitted，但 history 不增加
R3: t+30  9.8 / 110   # 必须 reject
```

修后断言：R3 不在 admitted；latest 仍 10.0；last_price 仍 10.0；ooo +1。

再加：same timestamp revision、slight future clamp、far future、source switch、index。

必须做回退验牙：局部恢复 history-tail guard 后 flat-R2 测试重新变红。

### B. `IT-P1-TIME-ROLE-001` — source time contract

仓库 fixtures 已证明三家 `Quote.ts` 都是 per-symbol 时间而非整批接收时间；Exact role 仍不确定。

新增/产出 `source_time_contract.json`：

```json
{
  "tencent": {"raw_field":"30", "role":"unknown", "timezone":"Asia/Shanghai"},
  "sina": {"raw_fields":[30,31], "role":"unknown", "timezone":"Asia/Shanghai"},
  "eastmoney": {"raw_field":"f124", "role":"unknown", "timezone":"Asia/Shanghai"}
}
```

若找到一手文档或可靠 live correlation 才把 `unknown` 升级。单独记录 `received_at` 和 monotonic process time。切 source 生成新 `source_epoch`，不跨 epoch 比 provider timestamp。

### C. `IT-P1-INDEX-CURRENT-001` — index 也必须 current-only

当前 `spirit_index.evaluate()` 扫整个 `ctx.state.quotes`。新增真实集成测试：

1. 第一轮指数有返回并积累足够历史；
2. 第二轮 index source 返回 `[]` 或抛错，股票主链正常；
3. 第二轮 `idx_admitted` 为空；
4. 第二轮不得用旧 index current quote 新生成 alert；
5. 历史允许保留，不能通过清历史糊住问题。

实现方案优先：把 current index view 放进内部 observation/current view，`spirit_index` 消费 current view，而不是累计 state cache。

## Observation Ledger v2

在 `src/arad/capabilities.py` / `engine.py` / `store.py` / `tools/live_session.py` 形成以下口径：

```text
round_id
observed_at
status = ok | partial | fetch_error
requested
provider_objects
returned_positive
admitted_time
rule_eligible
unknown_missing
explicit_unavailable
future_rejected
out_of_order_rejected
rejected_quality
filter_rejected
```

强制机械恒等式：

```text
requested = provider_objects + unknown_missing
provider_objects = admitted_time + future + ooo + explicit_unavailable + rejected_quality
admitted_time_stock = rule_eligible + filter_rejected
```

注意：实际实现可因重复代码/指数分组而使用 set 口径，但必须在 schema 中说清楚，不能混行数与 unique code。

失败轮也写新的 observation identity；禁止 `live_session` 把上一成功轮的 Store observation 复制成本轮。

## per-code provenance / capability 是 targeted fallback 前置

先建立：

```text
code -> source
code -> source_epoch
code -> capabilities
```

规则 API 必须能判断某只 code 的能力，如 `provides(code,key)` 或等价结构。

**只有完成这个前置后**才能做 soft-partial targeted fallback：主源返回 A、不返回 B 时，只补 B；停牌/explicit unavailable/quality reject 不无限 fallback。
