## 1. 新确认错误 `IT-P2-CALL-DETAILED-TYPE-ERROR-ABORTS-FAILOVER-004`（W11）

**文件 / 函数 / 行**
- `src/arad/engine.py:646-650` —— 原子绑定段
  ```python
  646             # ⚠ 原子绑定：source 以**实际返回数据的源**为准。
  649             if getattr(out, "source", "") != name:
  650                 out = out._replace(source=name)
  ```
- `src/arad/engine.py:628-645` —— **每个源各自的 `try/except` 只包住取数**，
  `:645 continue` 之后才是 `:649-650` 的 `_replace`

**触发条件 / 反例（实测，含两条对照）**
某源定义了 `snapshots_detailed` 但**返回了错类型**（例如裸 `list`，而非
`SnapshotFetchResult`）时：`getattr(out, "source", "")` 取不到 → `"" != name` 成立 →
走 `out._replace(...)` → `list` 没有 `_replace` → **`AttributeError` 直接冒泡出整个
`call_detailed`**，而**不是**被 `:642` 的 `except Exception` 捕获后 `continue` 到下一个源。

```text
ARM1  错类型 detailed        -> raised AttributeError('list' object has no attribute '_replace')
                               健康备源被调用次数 good_served = 0        ← 整条链被掐断
ARM2  对照: snapshots 抛异常  -> returned n=1 ; bad_scalls=1 good_scalls=1  ← failover 正常
ARM3  对照: detailed 抛异常   -> returned SnapshotFetchResult ; good_dcalls=1 ← failover 正常
      => 两条对照共同证明 failover 本身是好的，且异常路径没问题
         （两条对照都真正到达了 failover 分支，故本判据有判别力）
```

**机制**：`try` 的边界画在了"取数"上，而**类型契约的违反**发生在取数**之后**的绑定段。
`except Exception` 抓不到，因为它不在 `try` 里。

**影响**
- **当前暴露面 = 0**：我实测三个内置源（`tencent.py`/`sina.py`/`eastmoney.py`）
  的 `snapshots_detailed` 都返回 `SnapshotFetchResult`，故随包链路不触发。
- **风险面**：任何**第三方源**或**半迁移源**（有 `snapshots_detailed` 但尚未改成 v4
  返回类型）会让**整条链**（含健康备源）一起失败 —— 而 `call()` 的语义是
  "逐个后备源尝试"（`:547-571`），`call_detailed` 在此处**偏离了它自己声称的
  'failover 顺序与 call 完全一致'**。
- 与 `IT-P2-LEGACY-FALLBACK-PHANTOM-MISSING-003` 同属"WP03 接线前必须收口"的一类：
  接线后这是**可用性**问题（不是账本问题），且只在坏源上暴露。

**修复建议**：把类型校验**并入** `try`，或在 `:649` 前显式判型：
```python
if not hasattr(out, "_replace"):
    last_exc = TypeError(f"{name}.snapshots_detailed 返回类型非法: {type(out).__name__}")
    log.warning("数据源 %s.snapshots_detailed 返回类型非法，尝试下一个源", name)
    continue
```
（即：**类型错误也应当走 failover**，与异常同待遇。）

**验收测试**：构造一个返回裸 `list` 的 `snapshots_detailed` 主源 + 一个健康备源，
断言 `call_detailed` **不抛异常**且 `result.source == 备源名`；
**对照**：主源 `snapshots_detailed` 抛异常时同样应切到备源（现行为已正确，防回归）。
