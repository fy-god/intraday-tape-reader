## 4. P0：`IT-P0-002-R1` —— 时间准入修在 State 内，但规则仍消费原始 provider 输出

### 4.1 固定源码证据

`EngineState.update()` 已经改成先执行：

```python
ok, q_ep, why = self._admit_time(q, now, ep)
if not ok:
    ...
    continue
```

远未来点因此不会写入 `state.quotes/history`。`window()` 也已经改为：

```python
cutoff <= p[0] <= now_epoch
```

这是正确进展。

但是 `Engine.poll_once()` 的当前顺序是：

```python
self.state.update(quotes, now)

returned = {q.code: q for q in quotes if q.price > 0}
eligible = {
    c: q for c, q in returned.items()
    if self.filters.accept(q, now.date()) and c not in self.ignore
}
...
snap = Snapshot(...)
snap.quotes.update(eligible)
```

也就是说 `returned` 并不是“通过时间准入的返回”，而只是原始 `quotes` 中 `price > 0` 的项。State 拒掉的数据仍存在于局部变量 `quotes`，随后又被规则 Snapshot 接走。

### 4.2 本轮机制复现 A：far-future quote

使用当前 `EngineState.update` 与 `poll_once` 的关键控制流同构摘录：

```text
quote.ts = now + 9999s
price = 99
```

结果：

```json
{
  "state_has_code": false,
  "t_reject_future": 1,
  "rule_snapshot_has_code": true,
  "observation_admitted": 1
}
```

因此“写前拒绝”只保护了 State，却没有保护规则。同一只远未来报价仍可能让 `tick_surge / volume_burst / unusual / limit_board` 等规则读取未来价格。

### 4.3 本轮机制复现 B：out-of-order quote

现有代码在判断 `q_ep < h[-1][0]` 之前已经：

```python
self.quotes[q.code] = q
```

然后在 out-of-order 分支只是不 append history，最后仍执行：

```python
self.last_price[q.code] = q.price
```

固定序列：

```text
10:00:00 price 10.0
10:01:00 price 10.5
10:00:10 迟到到达 price 8.0
```

本轮机制结果：

```text
history:       [10.0, 10.5]
latest_cache:  8.0
last_price:    8.0
rule Snapshot: 8.0
t_reject:out_of_order = 1
```

这是一个“指标说已拒绝、业务状态仍被污染”的残留。

### 4.4 为什么现有新测试没有钉住它

`tests/test_engine_time_admission.py` 当前确实测试了 far-future 不进入 `EngineState.quotes/history/last_price`、out-of-order 不追加 history、window 不读取 future point；但它没有断言：

- `Engine.poll_once` 的 CaptureRule 看不到 far-future quote；
- out-of-order 后 `state.quotes[code]` 仍是最新值；
- out-of-order 后 `last_price[code]` 仍是最新值；
- `RoundObservationSet.admitted` 只统计质量准入后的标的；
- index 路由也遵守同一 admitted-current 合同。

所以这是**单元层修复没有闭合到 Engine 集成层**。

### 4.5 修复合同

下一版必须只有一个事实源：

```text
raw returned
  ↓
quality/time/source admission
  ↓
admitted_current
  ├── state mutation
  ├── rule Snapshot
  ├── RoundObservationSet.admitted
  ├── index rule current state
  └── research feature input
```

最低要求：out-of-order 若政策是拒绝，就必须在修改 `latest_cache / last_price` **之前**拒绝，不能只拒绝 history append。

## 7. 继续开放的核心工程问题

### 7.1 `IT-P0-001`：14:57–15:00 仍错误归为 continuous

当前 `session.py` 仍把 AFTERNOON 定义到 15:00，并加入 `CONTINUOUS`。上交所当前官方交易时段将股票 13:00–14:57 定义为连续竞价、14:57–15:00 定义为收盘集合竞价；深交所公开时段同样如此。下一版需要显式 close-auction 语义，并让规则声明是否支持。

### 7.2 `IT-P1-SOURCE-EMPTY-001`：soft-partial 仍被当成功

`SourceManager.call()` 仍以“是否抛异常”判调用成功。某源请求 4800 只、正常返回 4700 只，不会自动得到 `unknown_missing=100` 并定向补备用源。目标不是“一少行就整轮失败”，而是区分 `explicit_unavailable` 与 `unknown_missing`，只对 unknown 做有界补洞，并保存 provenance/source epoch。

### 7.3 `IT-P1-WINDOW-001`：change-only history 仍丢新鲜横盘覆盖

当前 `EngineState.update()` 仍只在价格或累计量变化时 append history。这能去重复包，但也会删除“价格没变、却持续收到新鲜有效观测”的覆盖证据。候选仍是 `ObservationInterval(first_observed_at, last_observed_at, value...)`。

### 7.4 `IT-P1-LIMIT-001`：封单跨资格门槛仍可永久漏一次

当前 `limit_board` 在 `at_limit` 后先写 `self._state[tag] = "sealed"`，再调用 `_make_seal()`；而 `_make_seal()` 才检查 `min_seal_wan`。第一次贴板但封单不足会写 sealed，下一轮封单达到资格时 `prev == "sealed"` 直接 return。应拆为 `at_limit_unqualified → sealed_qualified`。

### 7.5 `IT-P1-006-R1`：Eastmoney `max_pages` 截断仍可标完整

当前：`pages = min(max_pages, ceil(total/page_size))`，最终 `complete = bool(total > 0) and not failed`。若 total=300、page_size=100、max_pages=2 且两页都成功，仍会 complete=True，实际仅 200/300。应额外比较 `required_pages > max_pages`。

### 7.6 SSE / Store

`IT-P1-008/009/003/004` 本轮产品提交未触及：SSE 断线补账、慢客户端 drop-oldest 无 gap、series 主体容量、Tencent TLS fallback 继续开放。本轮没有启动服务或浏览器，所以不编端到端漏事件率。

## 10. 主改造：Admitted Current + Capability Coverage 共同数据合同

目标是把“provider 返回什么”“质量门控接纳什么”“哪些字段可评估”“规则/模型实际消费什么”统一为一个可对账合同，消除 State 与 Snapshot 双轨语义。

非目标：这一阶段不改规则阈值，不把 Sina 缺 turnover 自动当通过门槛，不让模型修补被拒绝的脏行情，不直接把 shadow score 接真实通知，也不同时重写全部 Store/SSE。

建议 schema：`RawBatchResult(source/source_epoch/requested/returned/explicit_unavailable/unknown_missing)`、`AdmissionDecision(code/admitted/reason/effective_event_ts)`、`RoundObservationSet(raw/admitted_current/decisions/capabilities/rule_coverage)`。

关键不变量：`Snapshot_t.keys ⊆ admitted_current_t.keys`；latest cache / history 只能由 admitted_current 更新；`RoundObservationSet.admitted == len(admitted_current)`；研究特征只能由 admitted_current + capability mask 计算。

迁移时先 sidecar/shadow 对账，再切规则消费；旧字段保留兼容，但不得回退到“被拒绝 quote 仍进入规则”。
