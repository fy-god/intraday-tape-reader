# 2. P1：Tencent 修好了显式股票，却把“名称唯一定身份”的指数修坏了

稳定 ID：

## `IT-P2-TENCENT-NAME-BLIND-REQUEST-KEY-REGRESSION-002`
**当前严重度：P1 · 已确认 · 未修。**

固定代码里同一个“它到底是不是指数”的身份语义被实现了三次：

```text
parse_response         -> Quote.code        输入有 provider 真名
detailed _key          -> raw ledger key    输入有 provider 真名
detailed _req_key      -> requested R       输入强制 name=""
```

`models.looks_like_index()` 明确把名称中的“指数/成指”视为合法证据。因此当某符号只有名称能证明指数身份时，请求轴与 raw/Quote 轴会分叉。

真实独立审计已经对 15 个符号做 PRE/POST 控制，确认回归集恰好等于：

```text
{ sym : looks_like_index(sym, 真名, code)
      != looks_like_index(sym, "", code) }
```

已确认 7 个：

```text
sh000922 中证红利指数
sh000015 红利指数
sh000903 中证100指数
sh000904 中证200指数
sh000906 中证800指数
sh000009 上证380指数
sh000133 上证150指数
```

例如 `sh000009`：

```text
raw / Quote axis：sh000009
request axis：    000009

=> P=Q=∅
=> missing=['000009']
=> unexpected=['sh000009']
```

这是“假精确账”，因为 `raw_presence_known=True`。

出厂配置的 5 个指数目前都能在名称空缺时由白名单/399 段识别，所以当前默认配置暴露为 0/5；但 `_load_index_codes` 允许用户扩展，任意上述名称敏感指数被加入就触发。

本轮沙箱把最新审计的 15 个符号放进三个策略：

# 4. P1：`call_detailed` 的类型契约错误发生在 try 外，会直接掐断健康备源

稳定 ID：

## `IT-P2-CALL-DETAILED-TYPE-ERROR-ABORTS-FAILOVER-004`
**当前严重度 P1 · 已确认 · 未修。**

固定源码：

```python
try:
    out = detailed(...)
except Exception:
    continue

# try 已结束
if getattr(out, "source", "") != name:
    out = out._replace(source=name)
```

如果某第三方/半迁移源定义了 `snapshots_detailed()`，却返回裸 `list`，`out._replace(...)` 的 AttributeError 在 per-source `try` 外，导致健康备用源完全不被尝试。

真实独立审计已有两个对照：普通 snapshots 抛异常和 detailed 自己抛异常都能正常 failover，所以缺陷被精确定位到**返回值契约校验的位置**。

# 5. 本轮新增 P2：`call_detailed` 原子纠正了 source，却没有纠正/验证 route

**P2 · 本轮新静态发现。**


## 最终判断

当前项目已经不缺“能表达 raw truth 的数据结构”。WP01 和 WP02 已经把 source truth 与 failover 原子来源推到可用状态。

真正阻塞 WP03 的，是**身份合同与测试有效性**：

```text
同一个 identity 决策写了三次
其中一次输入与另外两次不同
而现有测试甚至无法杀死“把三处一起改错”的实现
```

如果此时直接接 Engine，系统会把“精确 raw truth”变成“精确但错误的 raw truth”，这比 legacy 的明确 unknown 更危险。

所以下一轮最高价值不是继续扩功能，而是：

**先让 identity 测试能杀错解 → 再统一 identity role → 再把 type/source/route contract 纳入 failover → 最后才接 WP03。**

模型继续保持 0 是正确选择；等在线 Round Attribution 真正 source-invariant 后，再进入 Membership / Failover / 研究训练。
