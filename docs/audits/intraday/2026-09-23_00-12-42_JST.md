# 2. 22:45 最新追加 P1：测到 0 只仍被当成“没记录”

### `IT-P1-UNIVERSE-T0-MEASURED-ZERO-READ-AS-MISSING-001`
**P1 · 已确认 · 未修**

当前绝对股票池判决：

```python
_u_size = _safe_int(_setup.get("universe_size"))
```

正确修法必须使用 tri-state：

# 3. 本轮新 P1：会话中绝对扫描池从 5000 掉到 2000，分母未知时仍只看 t0

但是最终绝对股票池 health 的 `universe` 项只读：


也就是 soak 启动前的 t0 值。

因此可以出现：

```text

=> absolute gate OK

=> universe_coverage 无法计算
```


```text
None != 0
```

所以：
- t0=None/session=None -> NOT_MEASURED；
- 任一明确测到 0 -> FAIL；
- session min < absolute fail threshold -> FAIL；
- session min in warn band -> WARN。

# 7. 本轮主改造：Universe Evidence Completeness Contract v2

最近三轮共同暴露的根因不只是“证据合并”，而是：

> **肯定结论的量词和实际证据覆盖范围不一致。**

因此合同需要同时约束 **时间分母** 与 **市场分母**。

## 7.1 时间证据完整性

会话至少保留：

```text
rounds_total
scope_measured_rounds
freshness_measured_rounds
coverage_active_measured_rounds
```

全称肯定句：
```text
“全程全市场”
“会话期间新鲜”
“全程覆盖健康”
```
只有 `measured_rounds == rounds_total > 0` 才允许。

证据只覆盖 k/N：
```text
必须明确写 k/N
不能升级成整个会话肯定
```

## 7.2 市场范围完整性

scope 不是：
```text
active > 0
```

而应结合：
```text
active_scan_codes
expected_total
coverage_active
denominator_kind
```

分母未知时：
```text
只能说明“有较广扫描集合”
不能证明“full market”
```

## 7.3 明确零值

```text
None = 没有测量
0    = 明确测到 0
```

不能再用 `_safe_int` 把它们合并。

## 7.4 Session 事实不能依赖 t0 事实存在

t0 与 session 分别解析：

```text
t0 absolute size
session min absolute size

t0 numeric coverage
session numeric coverage
```

然后按同轴最坏显式证据 merge。

## 最终判断

`bf0b83b` 已经把“证据合并”从没有合同推进到有了基本 join 规则，这是真进展。

但最新审计线证明还有一个更一般的系统问题：

> **存在一些证据 ≠ 证据足够支撑全称肯定句。**

目前剩下的错误形态可以统一写成：

```text
明确测到 0
→ 被当成没测

只测到 1/30
→ 被写成整个会话新鲜

active > 0
→ 被写成 full market

t0 正常、session 绝对池严重缩小
→ 仍只看 t0

t0 没 truth、session 已有 75% coverage
→ session 证据被丢掉
```

所以主线现在应从：

```text
“有 consumer”
```

继续升级为：

```text
Evidence Completeness
+ Evidence Magnitude
+ Correct Quantifier
```

下一轮把这一层闭合后，才值得继续做 membership、source recovery、timezone、ObservationInterval；在这些事实链完成之前，继续跑模型只会让研究结果比代码事实走得更快。
