## 1. `IT-P0-002-R2` — 平价新鲜观测不推进水位线（P0，已修 + 验牙）

> 来源：该缺陷**最早由 05:30 JST 报告发现**，08:10 复现，09:32 第三次独立复现
> 并补上关键新事实。**本轮是第四次**，且**首次修复**。上游三次确认，功劳不在本轮。

### 1.1 文件 / 函数 / 行号

- `src/arad/engine.py` `EngineState.update()`，修复前 `:157-161`（乱序守卫）
  与 `:173-174`（history 追加门）
- `src/arad/engine.py:82-85` `window()`（按 `p[0]` 过滤并排序，受影响的下游）

### 1.2 触发条件

同一标的连续两个**同价同量**的新鲜观测，随后跟一个**迟到**观测。

### 1.3 机制

水位线是**隐式**的 `history[-1][0]`，而 `history` 只在**价格或累计量变化**时
追加（`:173`，这是服务窗口采样的正确语义）。于是：

- 平价新鲜观测**已通过**时间准入，也推进了 `quotes` / `last_price`；
- 但它**不追加 history** → **水位线不动**；
- 下一个真正迟到的点因 `q_ep >= h[-1][0]` 被**放行** → 覆盖 latest 缓存、
  时间序列尾部倒挂、`out_of_order` 计数为 0。

根因是把「窗口采样点」与「准入水位线」两件不同的事绑在了同一个数据结构上。

### 1.4 复现证据（修复前，本机真实执行）

```text
  latest = 9.8   last_price = 9.8

  结果: [XX] 迟到点被误准入 + latest 倒退 + ooo=0

R2 变动价格 —— 守卫工作正常（对照）
  R2 后水位线 = t+60s
  R3(迟到 t+30) admitted = []
  latest = 10.5   out_of_order 计数 = 1
  结果: [OK] 被正确拒绝
```

**与上游上游报告完全一致**，包括"变动路径正常、平价路径漏水"的分叉。

### 1.5 修法

引入**独立显式**水位线 `EngineState.accepted_watermark: dict[str, float]`：

1. 乱序判定改用 `accepted_watermark`，不再借用 `history[-1][0]`；
2. 水位线在**准入成功时无条件推进**：`max(旧值, q_ep)`；
3. `history` 的"仅变化追加"语义**保留不动**（它服务窗口采样）；
4. `prune()` 同步回收水位线 —— 否则 prune 后残留的旧水位线会让重新关注的
   标的被误判为"迟到"。

## 2. `IT-P2-OBS-005` — provider 返回但 `price<=0` 被记成「没返回」（已修 + 验牙）

### 2.1 文件 / 函数 / 行号

- `src/arad/engine.py:876`（修复前 `returned = dict(admitted)`）
- `src/arad/engine.py` `unknown_missing` 补集构造
- 丢弃点：`src/arad/engine.py:145-146`（`if q.price <= 0: continue`）
- 质量桶文档：`src/arad/capabilities.py`（`rejected_quality` **有文档零实现**）

### 2.2 机制

`returned` 被定义成**准入后**集合，而 `unknown_missing` 用 `returned` 做补集。
于是任何**已返回但被内部丢弃**的票都落进 `unknown_missing`：

- `price<=0`（质量不可用，`:145`）；
- 被**时间准入**拒绝的（`:150-152`、`:158-161`）。

第二个还构成**双重计数**：同一票既计入 `stale_rejected`/`out_of_order_rejected`
（差分），又计入 `unknown_missing`。结果 `unknown_missing` 一个字段同时表达
三种互斥语义，覆盖率与"缺数据"诊断不可解释。

### 2.3 修法

三个互斥桶 + 分账：

| 桶 | 含义 |
|---|---|
| `unknown_missing` | 请求了、provider **完全没返回** |
| `rejected_quality` | 返回了、**质量不可用**（`price<=0`） |
| `stale_rejected` + `out_of_order_rejected` | 返回了、**时间不合格** |

`returned` 改为 provider **原始返回**条数（含 `price<=0`）。

同时**恢复了 `rejected_quality` 的发射点** —— 该桶在 `capabilities.py` 早有
文档定义，代码里零实现，本轮补上。

## 3. `IT-P2-OBS-003` — `admitted` 混算两类语义（已修 + 验牙）

修复前 `admitted = len(eligible) + len(idx_admitted)`：`eligible` 经**个股业务
粗筛**，`idx_admitted` 是**指数纯时间准入**。相加后 `returned - admitted`
无法解释为"被时间拒绝"。

修法：`admitted` 改为**纯时间准入**口径（`len(admitted) + len(idx_admitted)`，
两者同口径），并新增 `index_admitted` 分账。

**本轮由此发现一个新问题（上游未提）**：机械恒等式

```
requested == admitted + missing + quality + future + ooo
```

**对不上，差额恰好 5** —— 等于 `poll.index_codes` 的长度。原因是 `requested`
含指数，而 `unknown_missing`/`rejected_quality` 只覆盖个股。故新增
`index_requested` 与 `stock_requested` 属性，恒等式改为个股口径后**对平**：

```
requested_stock == admitted_stock + missing + quality + future + ooo
```

这正是上游"下一轮必须核查"第 4 条（per-code provenance）的前置。
测试 `test_ledger_identity_holds` / `test_stock_and_index_are_separately_accounted`。

## 4. `IT-P2-OBS-004` — 失败轮沿用上一成功轮的 observation（已修 + 验牙）

### 4.1 机制

`tools/live_session.py` 在 `poll_once` 抛异常时仍从 Store 取「**最近一轮**」的
observation 并写进本轮 sample。Store 里那份属于**上一成功轮**；而 sample 只有
`index`（无 `round_id`/`observed_at`），事后无法识别该数字属于哪一轮。

### 4.2 修法

`AlertStore` 新增 `observation_seq`（每写入一次 +1，仅在真收到 observation 时）。
消费方在 poll **之前**记下序号，poll 之后：

- 序号未增加 → 本轮没产生新账本 → **不并入**；
- `error` 轮 → **一律不并入**。

正常轮路径未被堵死（`test_fresh_observation_is_attributed` 守着）。

## 7. 三条可证伪的研究想法

### RF-01【程序修复】"水位线"与"窗口采样"必须由类型系统分开

- **假设**：本轮 R2 的根因是**两个概念共用一个结构**（`history` 既当窗口采样
  又当准入水位线）。可加一条静态守卫：任何以 `history[...][-1][0]` 形式读取
  时间用于**准入判定**的写法都应报错。
- **证伪条件**：若 `tools/check_admission_bypass.py` 报出的候选点全部是
  合法窗口读取（误报），或漏掉 R2 形态，则规则无效。
- **可执行动作**：与 `check_bom.py` 同级的独立守卫（不依赖 pytest）。

### RF-02【任务定义调整】`unknown_missing` 之外应有"能力缺口"聚合告警

- **假设**：Sina 服务期间 `turnover` 不可用应产出一条**系统级**告警
  （"放量规则当前不可评估：缺 turnover，影响 N 只"），用户对漏报的感知显著
  优于"只写进 status 的 observation 字段"。
- **证伪条件**：若 soak 中出现频率 > 1 次/小时，或该告警挤掉真实异动告警，
  则说明它降低信噪比、应退回 status-only。
- **性质**：这是**任务定义**问题 —— 系统当前承诺"报异动"，未承诺"报自身能力
  缺陷"。本轮已让事实可观测，但**尚未决定是否进通知流**。

### RF-03【模型真正增量提升】把账本一致性作为数据质量因子

- **假设**：`coverage`、`rejected_quality` 占比、`out_of_order` 率作为 H 类
  质量因子输入，能提升真实数据上的 PR AUC。
- **证伪条件**：真实语料上相对 base 提升 < 0.005，或该因子在 family
  permutation 中重要性排名后 50%。
- **前提**：依赖真实多日语料，当前 `blocked`。本轮已让这些量在
  `live_session` 报告中可用且**归属明确**（OBS-004），为取证打好基础。
