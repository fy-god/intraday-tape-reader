# 4. 本轮关键新裁决：不能用“空轮全部塞进 unknown_missing”快速修 D6

`list[Quote] == []` 至少可能对应三类上游事实。

### A. 真 raw empty
provider 原始响应一个 requested code 都没出现，正确是 `unknown_missing = requested`。

### B. raw rows 全出现，但 parser 因质量丢弃
Sina/Eastmoney 可以在 parser 内因 price/prev_close 不可用而丢 row。Engine 同样看到空 Quote list，但正确是 `rejected_quality=requested`，不是 missing。

### C. legacy / raw presence 不可知
某 source 只有 `snapshots()->list[Quote]`，没有 exact raw-presence sidecar。此时不能知道 provider 真没回还是 parser 丢了，最诚实的是 `unattributed/raw_presence_not_measured`。

所以 D6 必须与 Snapshot Outcome 一起收口。若现在简单做 `empty => all missing`，会制造一份机械上对账、语义上说谎的 ledger。

# 9. Raw Set Algebra 继续作为硬边界

设 `R=requested unique identities`，`P=raw returned identities ∩ R`，`Q=usable identities ∩ R`：

```text
returned = |P|
quality = P - Q
missing = R - P
```

另记 `unexpected_raw = raw_seen - R` 与 `duplicate_raw`。不能用 raw row count 或未过滤 raw unique count 做 returned，否则 duplicate/unexpected 会让 returned>requested 或掩盖 requested missing。

## 最终判断

15:52 的独立实测把研发顺序进一步校正：Snapshot Outcome 与 Membership 之间必须加入 **Raw Presence Truth → Round Attribution**。空的 Quote list 不是一个业务事实，它可能代表 provider 真没回、parser 全丢、或者 raw presence 根本没测。若把三者都叫 missing，系统会得到一份“机械上对账、语义上说谎”的账本。

因此正确前置链是：Requested Identity Set → Exact/Unknown Raw Presence → Quote Usability → Disjoint Round Attribution → Membership → Failover → Research。

同时 default pytest 的 wall-clock 不确定性必须尽快拆掉，否则所有后续 RED/GREEN/rollback 的证据质量都会被 200ms 墙钟阈值污染。

下一次真实产品进展应该是：**三源 detailed outcome + Round Attribution invariant + Eastmoney pagination 小修 + deterministic correctness gate。**
