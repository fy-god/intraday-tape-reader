## 1. 本轮新 P1：raw-presence 把“证据质量”和“route 是否实际测量”混成一个 bool

固定 SHA `src/arad/engine.py@55dc`: 

- `1223-1231`：指数未启用时 `_fetch_indices_detailed()` 返回 `([], None)`；指数抓取异常同样捕获后返回 `([], None)`。
- `2121-2128`：正常路径用 `_raw_keys_of(outcome) is not None` 得到 `exact_stock/exact_index`；`None` 会变成 `False`。
- `2226-2229`：随后**无条件**导出两条 route：`{stocks: exact_stock, index: exact_index}`。
- `1922-1994`：如果两条 route 最终都没有 Quote，空轮分支甚至直接硬编码 `{stocks: True, index: True}`，不看 `stk_outcome/idx_outcome`。

一个 bool 因而同时承担了四种本应分开的状态：

```text
True  = 有 outcome 且 raw evidence exact
False = 有 outcome 但 legacy/projected
?     = route 根本没请求
?     = route 请求了但 fetch 失败 / 没有 outcome
```

当前实现把后两种压成 False；空轮又把它们压成 True。两个方向都不诚实。

## 2. 三个确定反例

### 2.1 默认 soak：未请求 index，却被系统自己报成 projected

`tools/live_session.py` 直接 `load_settings()`，也就是默认 `config/settings.yaml`。当前默认：

```text
rules.spirit_index.enabled = false
poll.index_codes = 5 个指数
```

Engine `_request_arithmetic()` 正确给：

```text
index_requested = 0
```

但是正常 observation 仍导出：

```text
raw_presence_known_by_route = {stocks: True, index: False}
```

`live_session` 会把 `index=False` 解释成“投影反推”，于是一个**根本没有 dispatch 的 route** 反过来给 soak 制造黄色证据等级。

这是 false downgrade，不是 provider 数据降级。

### 2.2 live index 请求失败：`None` 被误说成 projected

`config/settings.live.yaml` 当前明确开启：

```text
spirit_index.enabled = true
```

指数请求异常时 `_fetch_indices_detailed()` 捕获异常并返回：

```text
([], None)
```

只要股票 route 仍有数据，正常 observation 会写：

```text
index: False
```

而 False 的既定语义是“有 legacy/projected evidence”。但这里真实语义是：

```text
requested, but no outcome / no evidence
```

必须是 `not_measured`，不能冒充 projected。

### 2.3 最危险的镜像错误：空轮可把失败的 index 写成 exact

若：

```text
stocks detailed -> exact empty outcome
index detailed  -> raises -> Engine catches -> None
```

因为最终 `quotes=[] / idx_quotes=[]`，Engine 进入空轮分支。当前代码硬编码：

```python
raw_presence_known_by_route={
    ROUTE_STOCKS: True, ROUTE_INDEX: True
}
```

于是一个刚刚**抓取失败、完全没有 outcome 的 index route** 会被 observation/soak 标成 exact。

这就是 044 定为 P1 的理由：它不直接制造交易信号，但它能给研究/soak 的证据链制造 false exact。

## 3. live_session 还有一个放大器：把“零值 shape key”当成 route 活动

当前 Engine `_route_ledger()` 为 schema 稳定，每轮都保留：

```text
returned_by_route: stocks + index
admitted_by_route: stocks + index
reject_by_route: stocks + index
```

即使 index 根本没请求，index 键也存在，只是值为 0。

但 `tools/live_session.py@55dc:1115-1158` 构造 `_seen_here` 时只是 union map **keys**。因此：

```text
index:0
```

仍会被当成“这条 route 本轮出过数/出现过”。

这个做法原本是为了抓“产了数据但没登记 evidence”的 partial 事故，方向正确；错误在于没有区分**键存在**和**值 > 0**。

修复不能删除稳定的 route-ledger 零键，而应该在 live_session 消费端只把正 returned/admitted/reject 计作 produced activity。

## 5. 主改造：Raw Presence Route Applicability Contract v1

### 5.1 Engine 端：只给“实际请求且有 evidence-bearing outcome”的 route 写 bool

冻结合同：

```text
outcome present + raw_presence_known=True
    -> route=True (exact)

outcome present + raw_presence_known=False
    -> route=False (projected/legacy)

route unrequested
    -> omit key

route requested but outcome=None (fetch failed/no evidence)
    -> omit key; downstream marks requested route not_measured
```

Normal 与 empty branch 必须共用同一个 helper，禁止再手写两套。

### 5.2 live_session：把 actual dispatch denominator 带进轮样本

`RoundObservationSet` 已经导出 `index_requested`，但 `make_round_sample()` 当前没有保留。应把 `index_requested` 加进 marker/value whitelists 和轮样本。

对新样本：

```text
stock_requested = requested - index_requested
expected routes = 实际 request > 0 的 routes
```

对旧样本没有 `index_requested` 时，才退回：

```text
evidence map keys ∪ positive route activity
```

绝不靠零值 route-ledger key 猜“这条 route 被测过”。

### 5.3 三种 route 集合必须分开

```text
expected   = 本轮真实 dispatch 的 route
produced   = returned/admitted/reject 任一正数的 route
measured   = raw_presence grade map 有键的 route
```

从而：

```text
unmeasured = expected - measured
partial    = produced - measured
```

- requested 但 fetch failed：`not_measured` / warn；
- produced 了数据但没 grade：partial / fail；
- 根本没请求：不进入分母；
- legacy outcome 明确存在且 `raw_presence_known=False`：projected / warn。

这四类不能再压成一个 bool。

### 5.4 043

health 文案分母直接使用：

```text
metrics.rounds_with_observation
```

`rounds_seen_by_route` 继续只作为 route->round_count 的诊断 map。
