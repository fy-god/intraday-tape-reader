### 2.1 【已确认 · 已修复 · P1】`IT-P2-LIMIT-FIRST-BOARD-MULTI`
`max_per_round` 截断把告警**永久**吃掉

- **文件/函数/行**：`src/arad/rules/limit_board.py`
  - `evaluate()` L108-118：`_check_side(...)` **顺带写状态**（L187
    `self._state[tag] = "sealed"`），而 `out = out[: self.max_per_round]`
    发生在**之后**
- **触发条件**：同轮 ≥ `max_per_round+1` 只票**同时首次跨过封单门槛**。
  我实测：3 只票同轮达标、`max_per_round=2`。
- **机制**：被截掉的那只，状态**已经**写成 `sealed`；下一轮它仍是达标状态，
  命中 L179 `if prev == "sealed" and qualified: return None` ——
  代码认为"已报过了"，但那条告警**从没发出去**。
- **影响**（实测原始输出）：
  ```text
  第2轮 三只均达标(300万): 告警 2 条 -> ['600001', '600002']
  第3轮 仍达标:            告警 0 条 -> []
  >>> 永久丢失: ['600003']
  ```
  涨停封板对做短线的人是**最高优先级信号之一**。它在"多股同时涨停"这种
  **最该看到的行情**里恰好最容易丢 —— 因为那正是会触发截断的场景。
  `max_per_round` 默认 20，意味着同时 ≥21 只涨停时开始丢，且丢的那些
  **不会再补**。
- **修复**：`evaluate()` 用与 `out` **平行的 `meta: list[(tag, prev_state)]`**
  记录每条告警写入前的状态；排序时 `out` 与 `meta` **一起重排**（否则回滚会
  张冠李戴）；截断后对**被截掉的那些**把状态回滚到调用前的值。
  只能回滚"本轮真没发出去"的告警 —— 发出去了就必须保留状态，否则下一轮会
  重复报同一条（幂等被破坏）。
- **验收测试**：`tests/test_rule_limit_board.py`
  - `test_truncated_alerts_are_reported_next_round_not_lost`（**真验牙**）
  - `test_truncated_alert_state_rollback_is_exact`（**真验牙**）
  - `test_no_truncation_reports_all_and_stays_idempotent`（回归保护）
- **验牙实测**（`git stash push -- src/arad/rules/limit_board.py`，保留新测试）：
  ```text
  2 failed, 81 passed
  AssertionError: 被 max_per_round 截断的票必须下一轮补报，不能永久丢失；
                  第2轮=['600001','600002'] 第3轮=[] 永久丢失=['600003']
  AssertionError: 被截断的 600002 状态应回滚到 at_limit_unqualified，实际 'sealed'
  ```
  两条都是 **`AssertionError`（语义级真验牙）**，不是缺符号的结构性红。
- **修复后**：第 3 轮 `告警 1 条 -> ['600003']`，第 4 轮静默（幂等恢复）。
- **诚实标注**：这条是**既有遗留形态**，不是 `IT-P1-LIMIT-001` 引入的
  （`max_per_round=0` 时单只路径本来就对）。他方审计也明说"post 2/3 比
  pre 0/3 更好"，属改善而非引入 —— 我确认这一点后再修的。

### 2.2 【已确认 · 已修复 · P1】`IT-P2-OBS-008` 没发出的指数请求被算成"请求了"

- **文件/函数/行**：`src/arad/engine.py::poll_once`
  - L814 `_fetch_indices()`：`if not self.index_codes or not self._wants_indices: return []`
    —— **故意不发**请求（`spirit_index` 默认关闭，省流量）
  - L1216（旧）`requested=req_stocks + len(self.index_codes)`、
    `index_requested=len(self.index_codes)` —— **无条件**加
- **触发条件**：任何一轮，只要配置里有 `index_codes` 但没有启用的指数规则。
- **机制**：`wants_indices=False`（不发请求）与 `True`（发了、返回空）

  一个**完全正常的配置**（不用指数规则）在健康检查里看起来像持续丢数据。
  这直接毒化 `IT-P1-OBS-011` 修好的那套覆盖率聚合。
- **修复**：`_idx_dispatched = bool(self.index_codes) and self._wants_indices`，
  只有真发出去才算 `requested` / `index_requested`。
- **验收测试**：`tests/test_observation_ledger_buckets.py::
  test_index_not_requested_is_not_counted_as_requested`（**真验牙**）

### 2.3 【已确认 · 已修复 · P1】`IT-P2-OBS-009` 指数丢失完全不可观测

- **文件/函数/行**：`src/arad/engine.py::poll_once`
  - `unknown_missing=tuple(c for c in self._codes ...)` —— 只遍历**个股**
- **触发条件**：指数请求已发、provider 返回空（或只返回部分指数）。
- **机制**：`index_admitted=0`，而 `unknown_missing=()`。指数码在**整个账本里

  两者都不可观测。

  指数），并排除指数侧的时间拒绝集合 `idx_time_rejected`。
