- **文件/函数/行**：`src/arad/sources/eastmoney.py`
  - `:344` `total = self._total_of(first)` → `:346 expected_total = total`（**transport 口径**）

- **触发条件/反例（我亲自复现，两条独立路径）**：
  1. **纯 parser 层**：一页 100 行中混入 N 行 `f2="-"`（停牌/不可用），`parse_clist` 返回 `100-N` 条。`N=0 → KEPT 100`；**`N=1 → 99 条，`len(out) < total` 成立`**。

  3. **真实量级门槛量化**（我自建，`total=5913`、60 页 × 100 行）：
     - 有 87 行上界重叠缓冲时：停牌 ≤ **87** 仍 `complete=True`；**第 88 行起翻 `False`**
     - 无重叠（59 页 × 100 + 末页 13）时：**停牌 1 行即翻 `False`**

- **机制**：`expected_total` 来自服务端 `data.total`（含停牌/PT/退市的原始行），`len(out)` 是 parser 按 `docs/DATA_CONTRACT.md:189` 契约剔除无效行后的可用数。两者**本就是不同口径**，相减得到的 `shortfall` 把"市场里有停牌股"误判成"服务端少给了数据"。
- **影响**（`src/arad/engine.py`）：
  - `:789` `if not meta.get("complete", True):` → 走 partial 分支，记 warning 并 `continue`
  - `:818` `if prev and n < prev:` → **拒绝覆盖，`return 0`**，保留旧池

  1. **不是"永久/永不入池"**：实测是**棘轮**，跨过缺口（本例 361）即自愈。

### 2.2 【已确认错误 · P1 · 本提交新引入】`IT-P1-TIME-ROLE-003-R1` — 跨源切换后已见码的两道时间闸同时让开

- **文件/行**：`src/arad/engine.py`
  - `:274-292` `begin_source_epoch()` → `:291 self.accepted_watermark.clear()`，**不清 `first_seen`**
  - `:203` `_admit_time(..., first_seen=q.code not in self.first_seen)` → 跨 epoch 后仍为 `False`

- **触发条件/反例（我亲自复现，`probe_f1.py`）**：
  ```text
  now = 2026-09-18 14:00:00   STALE_TOLERANCE = 14400s (4h)
  同 epoch 内，已见码收到 3 天前 ts：准入 []（被拒）  ooo=1  缓存价 10.0
  ```

- **修复建议**：`begin_source_epoch` 应同时清 `first_seen`（或改为 per-epoch 的 `first_seen`），使新 epoch 的每个码重新走首见陈旧闸；`_admit_time` 的 `first_seen` 判据应与 epoch 绑定而非全局。
- **验收测试**：在**同一用例**里同时出现 `begin_source_epoch` 与 `timedelta(days=3)` 的陈旧包，断言**拒绝**。现状：这两个 API 在两个新测试文件里**从未出现在同一用例中**（我 grep 确认）。

## 10. 三条有依据的研究/改进想法

依据均来自本轮证据：

1. **把"可用性下降"统一建模为路由级可观测量，而不是散落在各处的布尔。** 本轮 12 条 OPEN 里有 4 条（COMPLETE-001、TIME-ROLE-004、SOURCE-EMPTY-001、OBS-011）本质是同一个病：**"少了数据"不被识别，也不被计量**。建议引入一个统一的路由健康三元组（`requested` / `transport_returned` / `usable`），所有门控与告警只读它。依据：§2.1 实测"停牌 1 行即翻 False"、§2.9 实测"返回 1/2 码不触发 fallback"、§2.6 实测 11 个字段全被丢弃。
2. **时间准入合同必须与路由同构，否则 epoch 机制会互相污染。** §2.3 实测"股票切源清空指数水位线"，§2.2 实测"切源后陈旧价覆盖缓存"。两者都源于"两个路由共用一个全局状态"。建议把 `(route, serving_source)` 作为 epoch 主键。依据：`probe_f1.py`（10.0→12.0）与 `probe_f2.py`（3900→2900）。
3. **给"合同声明的语义"加一条可执行的守门测试，否则合同会与代码静默分叉。** §2.4 的 stale 策略冲突与 §6 的 SHA 末位错误是同一类问题：**书面合同没有任何机制强制代码遵守**。建议对 `source_time_contract.json` 增加两项断言：(a) 引用的 SHA 必须存在且可解析；(b) `freshness_allowed=false` 的来源不得被用作新鲜度判据（或必须显式豁免）。依据：`git cat-file` exit 128 实测 + `engine.py:56/268` 与合同 `:consequences.freshness_judgement` 的直接冲突。

外部论文不构成本项目实股收益证据。
