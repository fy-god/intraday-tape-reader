### 1.2 触发条件

任何在 **14:57:00-14:59:59** 之间运行的实时轮询。

### 1.3 机制

`phase()` 把 13:00-15:00 **整体**返回 `AFTERNOON`，而 `AFTERNOON ∈ CONTINUOUS`。
于是收盘集合竞价在**三个层面**都被当成连续竞价：

1. **规则层**：7 个 `only_continuous=True` 的规则照常评估。这段没有连续成交，
   价格由 15:00 一次性撮合决定 —— 触发出来的"急拉/放量/盘口增量"是撮合假象。
2. **量能时钟层**：`elapsed_trading_seconds()` 把这段计入分母。于是
   `volume_burst` 的 `avg_per_min = volume_lots / elapsed * 60` 出现
   **"分子不动、分母继续涨"** → 放量速率被人为稀释。
3. **展示层**：看板把该时段显示成"午盘交易中"。

**这是代码与自身文档矛盾**：`session.py:4` 从第一天起就声明了该时段。

- `src/arad/sources/eastmoney.py:352`（修复前）
  `complete = bool(total > 0) and not failed` —— 截断仍为 True

### 2.2 触发条件

`total / page_size > max_pages`（`max_pages` 默认 80）。

### 2.3 机制 / 影响

`min()` 使实际请求页数少于所需页数，而 `complete` 只看"有总数且无失败页"。
于是**低于 `expected_total` 的返回被当成完整 universe** —— 全市场扫描静默
漏掉尾部股票，且系统自报"完整"。

### 2.4 修法

```python
required_pages = -(-total // self.page_size)
truncated = required_pages > self.max_pages
pages = min(self.max_pages, required_pages)
...
complete = bool(total > 0) and not failed and not truncated
```

新增 `universe_info()` 诊断字段 `truncated` / `required_pages` / `max_pages`。
`max_pages` 默认值仍为 80；截断**不抛异常**，仍返回部分数据。

## 5. 三条可证伪的研究想法

### RF-01【程序修复】时段契约应由"集合"成员关系驱动，而非散落的比较

- **假设**：本轮 `IT-P0-001` 能在三个层面同时出错，根因是**没有一个地方
  集中声明"哪些时段属于连续竞价/可观测/可告警"**，而是各处写
  `phase not in CONTINUOUS and phase is not PRE_OPEN` 这类**特例比较**。
  改成 `OBSERVABLE`/`CONTINUOUS` 这类具名集合后，新增时段只需改一处。
- **证伪条件**：若全仓仍能搜到 `phase is not` / `phase ==` 形式的时段特例
  比较（而非集合成员判定），说明约束未真正建立。
- **可执行动作**：`tools/check_phase_sets.py` 独立守卫 —— 扫描 `src/` 里对
  `SessionPhase` 成员的点名比较，白名单放行集合定义处。

### RF-02【任务定义调整】量能分母应使用"已成交时长"而非"已开市时长"

- **假设**：本轮把分母收口在 14:57 修掉了集合竞价稀释，但**同源问题在开盘
  集合竞价与停牌期间依然存在** —— `volume_lots` 含 09:25 撮合成交量，而
  分母从 09:30 起算。更本质的口径是"该标的**实际有连续成交**的时长"。
- **证伪条件**：若按标的级实际成交时长替换后，`volume_burst` 的
  false-positive 率在真实数据上无改善（或无真实数据可测），则该重构不值得做。
- **性质**：这是**任务定义**问题 —— 当前系统承诺的 `avg_per_min` 到底
  是"市场节奏"还是"个股节奏"，本轮**未决定**，只修了已确认的集合竞价部分。

### RF-03【模型真正增量提升】时段语义应作为质量因子而非硬门控

- **假设**：把 `IT-P0-001` 这类时段判定从**硬门控**（在收盘集合竞价一律
  静音）改为**特征**（`session_phase` 作 one-hot 输入模型），模型可学到
  "集合竞价的放量含义不同于连续竞价"，从而在真实数据上提升 PR AUC。
- **证伪条件**：真实语料上相对 base 提升 < 0.005，或 `session_phase` 在
  family permutation 中重要性排名后 50%。
- **前提**：依赖真实多日语料，当前 `blocked`。本轮已让时段语义**可区分且
  可观测**（`close_auction` 独立枚举 + 中文标签），为取证打好基础。
