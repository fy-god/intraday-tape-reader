2. **出口完整性（含异常出口）** —— 我数了 `refresh_universe` 的**4 个 `return`**，

**根因一句话：三态被压成两态。**

```python
# 我的代码（engine.py:975，修前）
"transport_complete": bool(transport_complete)
#   None（我没测）  ->  False（provider 说被截断了）
```

`bool(None)` 得 `False`，于是判决层输出：

**provider 什么都没声明。** 这是把"我没测"渲染成"我测出你坏了"，
并且**把排障指向数据源**。

## §6 1–3 条有证据、可证伪的研究想法

### 想法 1〔**程序修复**〕：把"机制存在"升级为"**消费效果**"验收
* **证据**：本轮的**全部 9 条缺陷**都是同一形态 ——
  **数据算了 / 字段进了报告 / 测试只断言字段名存在 / 最终判决没有消费者**：
  `rounds_transport_incomplete`（第 6 次）、`ev_fail_cov`（说谎的旋钮）、
  `freshness.warn_s`/`fail_s`（我修 B5 时**新发现**的）、
  `watchlist_only_rounds`、`active_age_s` vs `full_market_age_s`。
* **做法**：任何被宣称为 health fact 的字段，必须配一条
  **consumer-effect test**：
  ```
  先造 fully-green baseline
  → 只修改那一个事实
  → 断言**完整 verdict signature** 按设计变化
  ```
  本轮已落地 `test_every_session_fact_has_a_consumer`
  （参数化 4 个事实）+ `test_green_baseline_is_actually_green`。
* **可证伪预测**：若穷举所有 health fact 后从未发现新的零读者，
  这条规矩无用。**反证不成立** —— 本轮**当场就抓到 2 个**
  （`ev_fail_cov`、`freshness.warn_s`）。
* **类别**：**程序修复**（可落地为门禁：health fact 必须有 consumer-effect test）。

### 想法 2〔**任务定义调整**〕：修复声明必须验**三条**，不止"机制存在"
* **证据**：我 13:00 轮的失败**不是**因为机制写错了 —— 三条机制都对。
  失败在于我的验收只覆盖了三条中的**第一条的一半**：
  * ①**边界可达性**（那条"跳过"分支在真实引擎上不可达）；
  * ②**出口完整性**（数 `return` 枚举不了出口，**异常出口不是 return**）；
  * ③**新引入的镜像错误**（修假绿 → 造出假红并归罪数据源）。
* **做法**：每个修复声明附三问：这条分支**真实可达吗**？
  **所有**出口（含异常）都处理了吗？我**新造出**什么反向错误？
* **可证伪预测**：若按这三问复核后从未发现遗漏，规矩无用。
  **反证不成立** —— 本轮三问各抓到至少一条（1.1 / 1.8 / 1.1 的诬告）。
* **类别**：**任务定义调整**（改"什么叫已修复"的验收定义，不改阈值）。

### 想法 3〔**模型真正增量提升：无**〕
* 诚实声明：`程序修复` = §1.1–1.9；
  `任务定义调整` = 想法 1、2（随代码部分落地，**未**形成独立门禁）；
  **`模型真正增量提升` = 0** —— 本轮没有任何模型被训练或改动。
* **真实 Precision / Recall / 漏事件率 / 交易收益：`unavailable`。**
  不编造任何命中率或收益率。
* **本轮没有任何新的真实世界观测数字**：所有证据均来自
  **离线 stub + 真实引擎代码路径**（`evidence_type = 软件样本`），
