### 2.1 WP01 `SnapshotFetchResult` v4（`9ed75ef`）

- **文件 / 行**：`sina.py:197-198`、`eastmoney.py:196-200`、`tencent.py:316-322`

### 2.6 云端 18:17 §0 — **P0 假红回归（我上一轮引入的）**（`ff8fd8f`）

- **文件 / 行**：`tools/live_session.py` `universe_size = int(engine.refresh_universe() or 0)`
- **机制**：生产者 `engine.refresh_universe()`（`engine.py:1177`）AST 实测 **4 个 `return`、无 `return None`**，其中
  - `:1302`（`rejected_smaller`：部分池更小 → **拒绝覆盖、保留现有池**）`return 0`
  - `:1326`（`all_failed` / `empty`：**保留原股票池**）`return 0`
  
  两条**都不重写** `self._codes_raw` —— 池子确实还在（我实测 **5563 只 × 30 轮**）。`or 0` 把「刷新失败但池子保留」压成 `0`，判决层按"明确测到 0"处理 → 「扫描池为 **0 只**…本场**一只票都没扫**」。
- **影响**：**假红与假绿同样致命**。假绿让运维漏掉真问题；**假红让退出码失去可信度** —— 一次全源抖动就让整场判红，运维学会忽略红，此后真假红不再可区分。
- **这是本会话第 2 个"我修了消费者没修生产者"的实例**。我上一轮把 `0` 从"异常路径共用"里拆了出来，但**漏掉了第三种情况**（正常返回 0 但池子被保留）—— 我自己的注释当时还写着"正常返回 0 → 真的 0"，那句话本身就是错的。
- **修复**：新增**纯函数** `_t0_universe_size(ret, *, retained_pool, attempt, say)`，按「返回值 + 池子是否保留」联合判定（成功 N → N；真 0 只且池空 → 0；失败但保留 → `None`）。
- **为什么提取成纯函数**：云端 §0.5 实测该行位于 `def run` 内，全 `tests/` 对该入口点命中 **0 次** —— 缺陷能在 `1830 passed` 下存活。提取后可直接测。
- **验收（三态对照）**：失败保留池 → 不得判红；真 0 只（池子也空）→ **必须**判红；成功 N → 原样透传。

1. **把"肯定句的分母"做成一条可失败的不变量，而不是逐条修**（依据 §0-4：同一条缺陷类本轮 4 次，且**只有修过的那两条**有牙）。云端 18:07 §7 也提了同一方向。可操作：仿照仓库已有的 `test_every_session_fact_has_a_consumer`，新增一条 AST 测试抓「会话期间…」的全称 `add(...)`，断言其门里出现 `_rounds_total` 且**不包括**"已测量子集"变量。**这是我认为下一轮最高价值的一步** —— 它能把"下一次再冒出第五条邻轴"从"靠审计发现"变成"CI 直接红"。
2. **把"生产者/消费者成对修"变成显式检查项**（依据 §2.6：我的 P0 假红正是只修消费者造成的；§3.2 的镜像错误也是只改一边造成的）。可操作：对每个三态字段，在测试里同时断言**生产者出口**与**消费者判决**，任一侧单独改动都变红。
