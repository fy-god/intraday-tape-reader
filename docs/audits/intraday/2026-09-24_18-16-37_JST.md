## 2. 【已确认错误 · 本轮独立复现】Sina 指数前缀丢失 → 静默换成**另一只证券**

**文件 / 函数 / 行**：`src/arad/sources/sina.py`
- `_norm_code`：**L627-636**
- `_norm_codes`：**L639-647**
- `guess_prefix`：同文件（被上述两者后续使用）

**代码（原文，L627-636）**：
```python
def _norm_code(value: Any) -> str | None:
    """``600000`` / ``"sh600000"`` -> ``"600000"``。"""
    if value is None or isinstance(value, bool):
        return None
    s = str(value).strip().upper()
    if s[:2] in ("SH", "SZ", "BJ"):
        s = s[2:]                      # <-- 显式交易所前缀在这里被丢掉
    if not s.isdigit() or len(s) > 6:
        return None
    return s.zfill(6)
```

**触发条件 / 反例（我执行真实函数所得，非引用）**：

```
_norm_code('sh000001') = '000001'    <- 上证指数
_norm_code('sz000001') = '000001'    <- 平安银行（股票）
COLLIDE? True

sh000001 -> norm '000001' -> guess_prefix -> 'sz'
sz000001 -> norm '000001' -> guess_prefix -> 'sz'

_norm_codes(['sh000001','sz000001']) = ['000001']      # 2 个输入 -> 1 个输出
COLLAPSED = True
```

**正/负对照对（`ttt2`：一个「坏」结论必须配一个「好」的行为才成立）**：
- **正对照（必须正常）**：`_norm_code('sh600519')='600519'`、`_norm_code('sz000002')='000002'`
  ⇒ 普通股票的去前缀**语义正确**（用户按裸码要 600519 没问题）。
- **负对照（缺陷）**：指数 `sh000001` 与股票 `sz000001` **塌成同一身份**，且后续 `guess_prefix`
  把它**一律判成 `sz`** ⇒ 请求上证指数会拿到**平安银行**的行情。

**机制**：`_norm_code` 的职责是「归一成裸码」，但它**无条件丢弃**交易所前缀，
而指数与股票**共享同一段 6 位数字空间**（`000001` 既是上证指数也是平安银行）。
丢前缀之后没有任何信息能区分二者；`guess_prefix` 只能按股票规则猜，于是**机器自洽地猜错**。
`_norm_codes` 再用集合去重，把**两个不同证券合并成一个**，请求数直接少一个。

**影响**：①**错误证券的响应会被当成成功行情收下**（不是 missing、不抛异常、不计入失败）；
②detailed 路径共用同一 normalization ⇒ `R/P/Q` 在**错误的证券**上仍可机械自洽，
产出「exact but wrong」的假精确；③指数相关的准入/健康度统计**被股票数据污染**。
这是**身份层**缺陷，不是显示层。

**修**：显式 index prefix **必须保留到 HTTP wire**，指数 `Quote.code` 保留交易所前缀，
index route 的 detailed `R/P/Q` 使用同一 prefixed identity；**同时保持普通股票裸码 API 兼容**。

**验收测试**：
1. `_norm_code('sh000001') != _norm_code('sz000001')`（当前 **失败** ⇒ 应红）；
2. `_norm_codes(['sh000001','sz000001'])` 长度 **2**（当前 **1** ⇒ 应红）；
3. 走 wire 断言 `list=` 请求里指数带 `sh` 前缀（当前 **失败**）。

> 我**只复现**，**未修**：相A 只写文档，且本仓库不是我的改动对象。
