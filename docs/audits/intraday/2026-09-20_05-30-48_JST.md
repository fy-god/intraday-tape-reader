### 2.1 `IT-P0-002-R2`：乱序水位线取自 history 追加点，可滞后 → 旧价仍可倒退并进规则

**性质：已确认错误（修复后回归 / 同一缺陷类残留）**

| 项 | 内容 |
|---|---|
| 文件/函数/行 | `src/arad/engine.py` `EngineState.update()` **L157-158**（水位线 `h[-1][0]`）、**L173-174**（仅价格/量变化才 append）、**L163/L175/L176**（每次准入都推进 `quotes`/`last_price`/`admitted`） |
| 触发条件 | 出现**重复的同价同量观测**使 `history` 不追加，随后 provider 送来一个**旧于已接受最新事件时间、但新于 `history[-1]`** 的报价 |
| 反例（实测） | 实验组：R1 `t+0@10.0/vol200000` → R2 `t+60@10.0/vol200000`（同价同量，history 不追加，仍为 `[(0,10.0)]`）→ R3 `t+30@9.8`。结果 `last_price = 9.8`、`state.quotes.price = 9.8`、规则 Snapshot `['600000']`、`t_reject:out_of_order = 0`。对照组仅把 R2 改为 `10.5`（history 推进到 `[(0,10.0),(60,10.5)]`）：同样 R3 被拒，`last_price = 10.5`、规则 Snapshot `[]`、`ooo = 1`。两组**唯一差异**是 history 是否推进 |
| 机制 | 守卫条件是 `if h and q_ep < h[-1][0]: reject`。`h[-1][0]` 是**最后一次被 append 的点**，而 append 只在 `prev != q.price or h[-1][2] != q.volume_lots` 时发生（L173）。因此"被准入但未追加"的观测会推进 `quotes`/`last_price`（L163/L175）却**不推进水位线**，水位线可**任意滞后**于已接受的最新事件时间 |
| 影响 | ① `last_price` 与 `quotes` 缓存被旧价**倒退**；② 该旧价**进入规则 Snapshot**，可能产出"无中生有"的告警（正是原缺陷的后果）；③ `out_of_order_rejected` **漏计**，使 §2.2 的账本更不可信。重复同价同量在盘中（分钟级轮询、量价常持平的冷门股）**很常见**，因此可达性不低 |
| 修复建议 | 为每只票维护独立水位线 `last_accepted_ep[code]`，在**每次准入**时更新（与 `quotes`/`last_price` 同点），乱序判定改为 `q_ep < last_accepted_ep[code]`；**不要**复用 `history[-1][0]` |
| 验收测试 | ① 上述实验组必须 `last_price` 保持 10.0、Snapshot 为空、`ooo == 1`；② 对照组保持现状通过；③ 追加"连续 3 次同价同量后送旧价"用例；④ 断言 `last_accepted_ep` 在未 append 的轮次也推进 |

## 5. 研究/改进想法（1–3 条，依据均来自本轮证据）

1. **把"水位线"作为可观测对象纳入账本。** 依据：§2.1 证明水位线滞后是旧价倒退的**唯一**触发条件（实验/对照只差 history 是否推进）。可做实验：为每票记录 `last_accepted_ep` 与 `history[-1][0]` 之差，作为 `watermark_lag_seconds` 计入 `RoundObservationSet`；若该值盘中长期 > 一个轮询周期，即预警乱序守卫处于失效状态。
2. **用"分桶恒等式"当账本自检。** 依据：§2.2 的 `1 + 1 + 1 = 3 ≠ 7`。可做实验：把 `missing + admitted + time_rejected + filter_rejected == requested` 做成一个**常驻断言**（在 soak 里每轮检查），一旦不成立即说明有票被重复归桶——这能在不引入新数据的前提下捕获同类口径回归。
3. **对"修复提交"要求独立的反例复现，而不是引用自证测试。** 依据：本次修复提交**把自己的审计报告与源码放在同一个提交**（`a88094e` 同时含 `src/arad/engine.py` 与 `docs/audits/intraday/2026-09-20_05-16-58_JST.md`），而该报告正是宣布"已修 + 验牙通过"的文件；同时 §2.1 的残留恰恰是它声称闭合的行为。可做实验：在 CI 增加"修复类提交必须附带一个**在修复前运行会失败的独立反例**（红测），且该反例由非提交者路径提供"的检查项。
