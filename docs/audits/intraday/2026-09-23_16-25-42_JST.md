### 1.1 根因（云端 `2026-09-23_00-12-42_JST.md` §7）

> **肯定结论的量词和实际证据覆盖范围不一致。**

* **门控的语义是存在量词**（存在至少一轮被测到），
  而它守护的文案是**全称量词**（会话期间全程/新鲜）。
  **加了 `_measured` 也还是假绿。**

  而这一类是"**有门控但量词不匹配**"，于是被**系统性漏掉**。

正确的门不是"有没有 `_measured`"，而是
**肯定句里那个计数的分母是不是会话总轮数**。

### 2.3 `IT-P1-UNIVERSE-T0-MEASURED-ZERO-READ-AS-MISSING-001`【P1】

**位置**：bf0b83b `:1755`

```python
_u_size = _safe_int(_setup.get("universe_size"))
...
elif _u_size <= 0:
    add("universe", True, "无股票池规模记录（旧报告/未采集），无法判定…")
```

`_safe_int(None) == _safe_int(0) == 0` —— **三态被压成两态**。
"没有测到股票池大小"与"**明确测到 active scan = 0**"被合并。

**实测（真实代码）**：

```
universe_size=None（没测到）   -> universe=ok  healthy=True / fails=[]
universe_size=0（明确测到 0）  -> universe=ok  healthy=True / fails=[]   ← 同一句文案
```

分母未知时 coverage 也算不出，于是**整场全绿**：
一次明确什么都没扫的会话拿到 `healthy=True / exit_code=0`，
与其他"真扫了全市场"的报告**不可区分**。

**修法**：改用既有的三态 helper `_optional_int`；
`None` → 未测量（跳过），`0` → **FAIL**（一只票都没扫）。

**并且修了生产者源头**：`universe_size = 0` 曾是**异常路径**的初始值，
与"真的刷新出 0 只"**共用同一个 0**。
判据层再想分开，信息已经丢了 —— 改为 `None`。
