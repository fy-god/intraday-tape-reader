## 3. 【已确认错误 · 新增 · P1】空扫描集被**肯定地**说成「全程全市场扫描」

**文件/函数/行**：`tools/live_session.py:1591-1592`（消费者）
→ 根因在生产者的代理标志 `tools/live_session.py:2644`。

**触发条件（真实引擎，非构造 metrics）**：
```text
真实 Engine.refresh_universe() 取到 5000 只 -> engine._codes 有 5000
随后 _codes 变空（全市场刷新失败/池被清空），而 state.quotes 仍保留 5000 条
=> 代理 watchlist_only = bool(0) and (0<=0) = False   # ← 「空」被判成「非降级」
```
实测（`D:\it_h16_c6`，真实 `Engine` + `_round_quote_count` + `_universe_session` + `evaluate_health`）：

```text
codes(universe)=0   watch=0   _round_quote_count({}, state)=5000
sample universe/quotes/watchlist_only = 0 / 5000 / False
agg ever_watchlist_only=False rounds=0 ratio=0.0
healthy = True   fail = []
  universe_scope     ok   会话期间未降级为仅自选股（全程全市场扫描）
  universe           ok   无股票池规模记录（旧报告/未采集），无法判定（跳过不算失败）
  universe_transport ok   会话期间 30 轮 transport 均为完整（无截断）
  data               ok   单轮最多拿到 5000 只行情
```

**机制**：`_round_quote_count` 在**本轮观测缺失**时回退到**累计** `state.quotes`
（`tools/live_session.py:2605-2627` 的注释明确说明它**从不缩小**），
于是 `quotes` 指标看起来健康；而**扫描集本身已经空了**这件事，
既没有被 `data` 也没有被 `universe` 捕获，
新增的 `universe_scope` 反而给出**肯定的绿灯**。

**为什么这是本轮主题的同一类错误**：本轮修的是「三态被压成两态」（不知道 → 有罪）。
这里出现的是它的**第三形态**：**「空」被压成「全市场」** ——
`bool(codes)` 把「0 只」折叠成「非降级」，消费者把「非降级」渲染成
「**全程全市场扫描**」。**零证据被写成了肯定句。**

**影响面**：这条错误落在**判决层**，且**方向是放行**（`healthy=True`、`exit=0`）。
即「扫描集整个空了」与「正常全市场扫描」在报告里**文本可区分但判决不可区分**。
未计数：我**没有**统计真实历史运行中出现该形态的轮次（无归档可用，见 §6）。

**修复建议**（三处，缺一不可）：
1. `_universe_session` 增加独立事实 `scan_rounds` / `empty_scan_rounds`（本轮 `universe` 为 0 的轮数），不要让调用方从 `ever_watchlist_only` 反推；
2. 生产者把「空扫描集」与「降级为自选股」**分开表达**（三态或枚举，而不是 `bool(codes) and ...`）；
3. 消费者在 `universe_scope` 里为「扫描集为空」单列分支，**不得**落进 `全程全市场扫描` 的肯定句。

**验收测试**（应可直接加入仓库）：
```python

    # 真实 Engine：先刷 5000，再清空 _codes，state.quotes 保留
    rows = [_soak_placeholder(universe=0, quotes=5000, watchlist_only=False)] * 30
    m = _green_metrics(); m["universe_session"] = ls._universe_session(rows)

    assert "未测量" in det or _lvl(v, "universe_scope") == "fail"
```

## 4. 【已确认错误 · 新增 · P2】「无法判定」分支**结构上不可达**，正确的「未测量」信号被丢弃

**文件/行**：`tools/live_session.py:552-554`（生产者）与 `:1568`、`:1576`（消费者）

```python
# 生产者 tools/live_session.py:550-555
watch_facts = {
    "watchlist_only_rounds": watch_only,
    "watchlist_only_ratio": (round(watch_only / watch_seen, 4)
                             if watch_seen else None),   # ← 这里正确地表达「未测到」
    "ever_watchlist_only": bool(watch_only),             # ← 这里把「未测到」压成 False
}
# 消费者 tools/live_session.py:1576
elif _w_ever is None:      # ← 只有当整个 universe_session 键缺席才成立
    add("universe_scope", True, "无会话级扫描范围记录（旧报告/未采集），无法判定…")
```

**触发条件**：任何由 `_universe_session` 产出的 dict。
**机制**：`bool(watch_only)` 恒为 `bool`，**永不返回 `None`**；
因此 `_w_ever is None` **只能**在整个 `universe_session` 键缺失时成立。
结果是：生产者**已经算对了**的「未测量」（`watchlist_only_ratio is None`）
在消费者处**被读取却不被使用**，同一个 dict 里的 `ever_watchlist_only=False` 反而走了
`else` 分支输出**肯定句**。实测：

```text
输入 [{"quotes":1},{"quotes":2}] -> 
  {'measured': False, 'watchlist_only_rounds': 0,
   'watchlist_only_ratio': None, 'ever_watchlist_only': False}
```

**这与本仓库反复出现的「判决层零读者」是同一形态的新一例**：
`watchlist_only_ratio` 有出口、**零消费者**。

**影响**：把「本轮压根没采集到扫描范围信息」与「本轮确实全程全市场」在判决上**合并**，
方向同样是**放行**。未计数（同 §6）。

**修复建议**：消费者改为判 `_w_ratio is None and not _w_ever`（即用**表达力更强**的 ratio），
或让生产者把 `ever_watchlist_only` 也做成三态（`None` 表示未测到）。
**注**：修这个问题**必须**同时改 `:517` 的 `watch_seen` 语义，
否则只是把「不可达分支」换成「恒真分支」。

**验收测试**：
```python
def test_unmeasured_scope_is_not_asserted_as_full_market():
    agg = ls._universe_session([{"quotes": 1}, {"quotes": 2}])
    assert agg["watchlist_only_ratio"] is None      # 生产者已正确表达「未测量」
    m = _green_metrics(); m["universe_session"] = agg
    v = ls.evaluate_health(m)
    assert "全程全市场扫描" not in _detail(v, "universe_scope")
```

## 5. 【待验证风险 · 降级】小规模**合法**全市场池被说成「降级为仅自选股」

**文件/行**：`tools/live_session.py:2644`（代理）→ `:1586-1589`（消费者文案）

```python
watchlist_only = bool(codes) and len(codes) <= len(watch)
```

**反例（实测）**：`codes=8`、`watch=20` → 代理判 `True` → 消费者输出
「会话期间有 30 轮**降级为仅自选股**（占比 100.0%）」。
但这是**合法的小全市场池**（例如早期 A 股，或自选股列表很长），**根本没有发生降级**。

**为什么降级为「待验证风险」而不是「已确认错误」**：同一输入下，
**修前就存在**的 `universe` 项已经判红（「扫描池仅 8 只（下限 3000）」），
`healthy` 在**两个版本里都是 `False`**。所以这不是**新的放行**，
而是**新增了一条措辞错误**的失败原因 —— 判决方向未被改变。

**严重度纪律**：按生产可达性只算 **P3 文案正确性**。
**未复现**：我没有找到真实生产中出现「合法全市场池 ≤ 自选股条数」的**实盘证据**，
因此**不主张**它必然发生；标记为 `未复现` 并降级。

**修复建议**：`--watch-only` 已经有**显式**标记（`parse_args` 的 `--watch-only`），
应改用「`_codes` 是否等于 `watchlist` 集合」或显式 run mode 判定，
而不是用**数量比较**猜意图 —— 这正是作者自己在 `:1570` 写下的纪律
（「绝不能靠"股票数很少"猜意图」），**却在 `:2644` 用了数量比较**。
