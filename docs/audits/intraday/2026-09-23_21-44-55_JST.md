## 5. 新发现（P2）`IT-P2-COVERAGE-ALIAS-REINTRODUCES-COLLISION-ACROSS-WP03-BOUNDARY-002`

> **定级说明（三轴分开）**：
> `execution_status` = 我已用**确定性探针**实测该碰撞（含正/负对照）；
> `evidence_status` = **机制已确认、后果尚未发生** ——
> `git grep` 实测**仓库内当前没有任何消费者读取该别名**（`SnapshotFetchResult.as_dict()` 与
> `.coverage` 的生产读取点 = 0），所以它**不是**当下就已发作的错误；
> `research_verdict` = **待验证风险**（潜伏，P2）。
> 我不把它写成"已确认错误"，因为它今天不改变任何线上数字 ——
> 与两个提交"不改变线上账本"的诚实边界是同一性质。

**文件/函数/行**
- `src/arad/sources/outcome.py:122-131`（废弃别名 `coverage` → `usable_coverage`）
- `src/arad/sources/outcome.py:194`（`as_dict()["coverage"] = self.coverage`）
- `src/arad/capabilities.py:867-869` + `:892`（账本 `coverage` = `returned/requested`）
- `src/arad/engine.py:1693`（注释：`returned` = "provider **原始返回**的条数"）
- `src/arad/engine.py:1753`（`returned=len(raw_stock)+len(raw_idx)`）
- `tools/live_session.py:257/323`（消费者把 `coverage` 当"我看到多少行情"）

**触发条件 / 反例**（我实测，含对照）
```text
R=3, P=3, Q=1：
  SnapshotFetchResult.as_dict()['coverage'] = 0.3333333333333333   （可用轴）
  RoundObservationSet.as_dict()['coverage'] = 1.0                  （传输轴 = 3/3）
  合并 {**ledger, **snapshot} -> merged['coverage'] = 0.3333333333333333
  => 按线上语义读"传输覆盖率"的消费者拿到 0.3333，真值 1.0，误差 0.666667
POSITIVE CONTROL：两轴在该 fixture 下数值不同 -> 反例有判别力
NEGATIVE CONTROL：raw == usable 时合并无害 -> 不误报
```

**机制**：RED 1 的诊断是"中性名字 `coverage` 被两种语义争用"。
WP01 的正解是**拆名**（已做），但为兼容旧调用方又保留 `coverage` **指向可用轴**。
于是 `SnapshotFetchResult` 这个**普通 dict** 仍带着一个名为 `coverage` 的可用轴值；
线上账本**同样**是普通 dict 且 `coverage` 是传输轴。
WP03（Engine Round Attribution）既定动作就是把两者合并 —— **合并即覆盖**。

**⚠ 别名方向与它自己引用的先例相反（这是我本轮最锋利的一条证据）**：
WP01 提交把 `eastmoney.py:415-433` 的"双轴"纪律当作先例引用。我读了那段先例：
那里的兼容做法是

```text
eastmoney.py:432  meta["complete"] = meta["transport_complete"]
                                     ^^^^^^^^^^^^^^^^^^^^^^^ 旧名 -> 传输轴（安全）
outcome.py:131    return self.usable_coverage
                                     ^^^^^^^^^^^^^^^ 旧名 -> 可用轴（危险）
```

即：**先例把旧名钉在传输轴上，WP01 把旧名钉在可用轴上**。
同一条纪律、两个方向 —— 而线上账本要的恰恰是传输轴（`engine.py:1693/1753`）。
所以本条的修复建议不是"删名字"这么随意的口味问题，而是
**别名应指向 `raw_return_coverage`（或干脆删掉导出）**，与先例对齐。

**影响**：**当前影响 = 零**（无消费者，我实测）。
风险在 **WP03 接线时**兑现：若照本实施，**静默**产生 0.67 量级偏差（本例），
方向系统性偏向"覆盖率被低估"（可用 ≤ 传输，`|Q| ≤ |P|`）。
与本仓库反复出现的"同名两义"bug 类同源，且**现有测试无法发现**（两个 dict 各自自洽）。

**修复建议**
1. `as_dict()` **删掉** `coverage` 别名键（保留属性、不再导出），只导出两轴；或
2. 必须保留则改名导出 `coverage_usable_alias`，并在 `_schema_note` 标注轴向；
3. WP03 合并 helper 必须**显式白名单**取键，禁止 `{**a, **b}` 式合并；
4. 给 `RoundObservationSet.as_dict()` 的 `coverage` 也加 `_schema_note` 注明**是传输轴**。

**验收测试**：断言
`set(SnapshotFetchResult.as_dict()) ∩ set(RoundObservationSet.as_dict())`
中**不含**任何同名两义的键；并加 fixture：`R=3,P=3,Q=1` 时合并结果的传输覆盖率
必须仍为 `1.0`（现有代码得 `0.3333`，故该测试当前**必然红**）。
