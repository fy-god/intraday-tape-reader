## 为什么这轮要改方向

当前 `unavailable_capability` 只是所有规则写入的 code 集合并集。`live_session` 却用“本轮是否有任意 unavailable code”计算 round ratio，并在 ratio=1 时解释成“整类规则整场都没被评估”。这在语义上不成立。

更关键的是：`VolumeBurstRule` 的 `volume_ratio` 缺失会被记 unavailable，但当前语义允许跳过该门槛并继续命中；而 `spirit_order` 基本没有 capability ledger，Sina/Eastmoney 能力不足时可以静默 0 alert。

所以 targeted fallback / capability-mask ML 之前，必须先建立可信的 signal-level evaluability 真值。

## WP01 — Signal Evaluability Contract【P1，第一优先，ready】

### 目标

把“缺能力”拆成至少三种状态：

```text
blocking_missing      缺失导致该 signal 不能评估
advisory_skipped      当前规则语义允许跳过该条件，signal 仍可评估
not_required          本 signal 根本不需要该 capability
```

### 建议结构

可在 `src/arad/capabilities.py` 新增等价结构：

```python
@dataclass(slots=True)
class SignalEvalStats:
    signal: str
    considered: int = 0
    evaluable: int = 0
    blocked_capability: int = 0
    advisory_missing: int = 0
    evaluated_no_hit: int = 0
    hit_candidates: int = 0
    published: int = 0
    blocked_reasons: dict[str, int] = field(default_factory=dict)
    blocked_sample: list[dict] = field(default_factory=list)
```

实际字段名可调整，但必须满足机械不变量：

```text
evaluable + blocked_capability == considered

evaluated_no_hit + hit_candidates == evaluable

published <= hit_candidates
```

`max_per_round` / AlertBus cooldown 后被截掉的命中必须与 `evaluated_no_hit` 区分。

### API

给 `RoundObservationSet` 增加有界方法，例如：

```python
mark_considered(signal, code)
mark_blocked(signal, code, reason, capability)
mark_advisory_missing(signal, code, reason, capability)
mark_evaluated(signal, code, hit: bool)
mark_published(signal, code)
```

逐 code 临时状态可以用 set/dict，`as_dict()` 只导出计数 + 最多 N 条样本，防止全市场载荷无界。

### 必须先写红测

1. 5000 code 里 1 code blocking、4999 evaluable，连续 20 轮：不能得到“整类规则 0% 可评估”；
2. 某条 signal 5000/5000 全 blocking：才允许 signal evaluable coverage=0；
3. `volume_ratio` 缺失但允许跳过：必须记 advisory，不得记 blocking；
4. `turnover` 缺失且 `min_turnover>0`：必须记 blocking；
5. hit candidate 被 `max_per_round` 截断：不得变成 evaluated_no_hit；
6. 兼容旧 `unavailable_capability` 字段，但明确 deprecated/diagnostic，不再作为 whole-class health 真值。

- 修前红测真实 `AssertionError`；

## WP02 — SpiritOrder capability closure【P1，ready，依赖 WP01 schema】

### 当前真实问题

Sina parser 提供：

```text
bid1 / ask1
bid_vol / ask_vol
```

但不提供五档 tuple。Capability table 因此声明 `depth_l1=True`。

`spirit_order._best_order()` 却只遍历：

```python
q.bid_vols / q.ask_vols
```

只给价格做 `fallback_px`，不给数量做 L1 fallback。因此 `institution_buy / institution_sell` 在 Sina 下即使有真实 L1 量也永远无法命中。

同时：

- `big_buy / big_sell / institution_eat / institution_vomit` 需要 `outer_inner`；
- `big_bid_wall / big_ask_wall` 需要 L5；
- 当前规则没有 `ctx.provides()` / evaluability 记账。

### 必须实现

逐 pattern requirements：

```text
big_buy             outer_inner (blocking)
big_sell            outer_inner (blocking)
institution_eat     outer_inner (blocking)
institution_vomit   outer_inner (blocking)
institution_buy     depth_l1 (blocking)
institution_sell    depth_l1 (blocking)
big_bid_wall        depth_l5 (blocking)
big_ask_wall        depth_l5 (blocking)
```

对 L1 institution order：若 `bid_vols/ask_vols` 为空，但 capability `depth_l1=True` 且 `bid_vol/ask_vol>0`，把 L1 当一个单档 level 参与 `_best_order()`。不要伪造 L2/L5；只构造一档。

对 outer_inner/L5 真缺失的 pattern：直接 `mark_blocked`，不能默默返回 no-hit。

### 必须锁住的 provider matrix

在 capability + parser 实际数据形状维度：

```text
Tencent:    8/8 patterns hard-evaluable
Sina:       修前实现 0/8；修后 capability 允许 2/8（institution buy/sell）
Eastmoney:  0/8（当前快照无 L1/L5/outer_inner）
```

这里的 2/8 只表示“字段能力足以评估”，不是应该命中。

### 红测

- Sina L1 500k+ 股单档：修前 institution_buy/sell 0 条，修后可按阈值评估；
- Sina trade patterns 必须 blocked_capability，而不是 evaluated_no_hit；
- Sina wall patterns 必须 blocked depth_l5；
- Eastmoney 8 pattern 全部有明确 blocked ledger；
- Tencent 既有行为不得回退；
- capability 缺失不能影响其它 source / 其它 pattern 的边沿状态。

回传 `spirit_order_provider_matrix.json`。

## WP03 — 修 live-session capability health【P1，依赖 WP01】

### 禁止继续使用的主指标

```text

= 有任意 unavailable code 的轮数 / observation rounds
```

### 新输出

```text
considered_total
evaluable_total
blocked_total
evaluable_coverage
blocked_by_reason
hit_candidates
published
```

健康判定：

- whole-class FAIL：某条**启用 signal** 有足够 considered 分母，但 evaluable_coverage 低于明确 fail 阈值；
- WARN：部分 code blocked；
- 仅有 advisory_missing 不应等同 hard unavailable；
- 无 considered 分母时标 `not_measured`，不填 0。

阈值不要先凭感觉写死。先在 fixed fixture + 当前真实 soak 可取得数据里输出分布；若没有足够真实样本，默认只 WARN，不贸然 FAIL。
